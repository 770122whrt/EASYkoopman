# 当前模型为什么有好有坏：模型含义、参数与实验结果

**2026-09-29当前路线：** 下一步仅做加扰动、物理与Koopman结合。物理基线冻结，不学习新增扰动数据、不重新校准。以下数值和既有协议保留为历史证据；与此冲突的旧下一步建议已被替代。当前执行入口见[STATE](../.planning/STATE.md)。

结果日期：2026-09-27；可读性修订：2026-09-28。本次修订解释名称、参数与比较边界，没有新增训练、服务器实验或改变原始数值。

**先读结论：** 在这批仿真轨迹的短期预测中，数据校准的物理模型整体最好；限制学习修正的自由度后，预测误差接近物理模型。尝试“非线性特征＋矩阵传播”的两种模型，目前换激励、换构型都没有达到要求。这说明当前具体实现需要改进，还不能判定整个Koopman方法无效。

这些首先是**预测实验**：给定当前状态和一段输入，看模型能否正确预测后续运动。误差小不自动等于机器人实际控制更好，后者还需要MPC求解和仿真闭环验证。

## 1. 先认清五种模型

以下中文名称是阅读入口。旧缩写仅用于对照代码与原始记录，不要求读者记住；它们不是五篇论文的标准算法名。

| 本文名称 | 它实际在做什么 | 旧代码简称 |
|---|---|---|
| 数据校准的物理模型 | 按质量、惯量、浮力、阻力等规律预测；用训练数据校准阻力系数 | P，physical |
| 物理＋自由残差 | 先保留物理预测，再用53项特征学习速度预测的额外修正 | R53，53项特征残差 |
| 物理＋受约束残差 | 同样保留物理预测，但只允许15种规定的系数修正方向 | Rc，compact residual |
| 非线性特征＋固定矩阵传播 | 先计算状态的平方、乘积等38项特征，再用固定矩阵向前预测整组特征 | LK，本项目的提升传播简称 |
| 非线性特征＋交互矩阵传播 | 在上一种模型上加入“当前状态特征×输入”的作用 | BLK，本项目的双线性提升简称 |

**53不是53个传感器，也不是53个机器人状态。** 它是从已有状态和机械参数算出来的特征数量。受约束残差仍使用兼容的特征存储，但仅允许15个独立系数方向变化，不能把它说成“15维状态模型”。

物理模型的一维示意是：

\[
v_{k+1}=v_k+\frac{\Delta t}{m}\,[\tau_k-c_1v_k-c_2|v_k|v_k].
\]

这里v是速度，τ是推力，m是质量，c₁/c₂表示阻力系数。完整实现还包括转动、姿态、浮力、恢复力矩与推进器动态；这只是帮助理解的单轴例子。所谓“递推”，就是算出下一步后，再用下一步继续往后算。

两种残差模型的共同思想是：

\[
\text{下一步速度预测}=\text{物理速度预测}+\text{数据学到的修正}.
\]

**因此我们已经在利用物理模型。** 学习目标是物理预测剩下的误差，不是一定要把已知物理全部重新学一遍。自由残差允许更广泛的修正；受约束残差限制修正的轴向和类型，以减少训练中看似有用、换场景后却错误的关联。

后两种提升模型承担更大的学习任务：保留共同的推进器输入链和已知机械参数，但主体状态及其特征的演化主要由学习矩阵负责。它们并没有像残差模型那样，把完整的物理主体递推直接加在预测结果里。表中差异因此不只是“一个线性、一个非线性”。

## 2. 表里的0.001和0.1是什么

它们是**训练正则强度λ**，用于约束模型系数，不是误差、控制周期、学习率或物理模型所占百分比。训练目标可以概括为：

\[
\min_W\;\text{训练数据上的预测误差}+\lambda\,\text{学习系数的大小惩罚}.
\]

λ较小通常更允许系数追随训练数据；λ较大通常更抑制大系数。两者都可能出现欠拟合或错误外推，不能只看λ大小决定好坏。实际代码还有特征尺度处理；残差模型惩罚额外修正，提升模型惩罚相对恒等传播的拟合增量。**不同模型的同一个λ，不代表完全相同的约束强度。**

因此，“物理＋自由残差（λ=0.001）”和“物理＋自由残差（λ=0.1）”是同一模型的两套训练参数，而非两种新算法。后两种提升模型另在训练来源内部比较了5档λ，选择完再评价外部留出构型；来源选择全部未达误差要求，所谓“校准后”不等于已经合格。

## 3. 怎么读结果表

“跨构型预测”采用留一构型的方法：八种构型每次拿一种不参与训练，再预测它的轨迹；共做八次。数据已经用于研发诊断，因此不是全新盲测泛化成绩。

每构型三条轨迹、每条取三个起点，共九段预测；八构型合计72段。每段预测80个物理步，约0.667秒。

- 深度误差用毫米（mm），姿态误差用毫弧度（mrad）；1mrad约0.0573°。均为RMSE，可理解为一段预测中的典型偏差，越小越好。
- “完整72/72”只表示72段都预测到末尾，仍可能误差过大。精度要求是每段深度RMSE≤2mm、姿态RMSE≤4mrad，且不违反状态与局部姿态坐标的适用范围。
- 若只有40/72完整，误差只计算这40段，另外32段失败不能当作零误差，也不能用幸存段给整个模型排名。
- 这是理想化仿真中的预测误差，不能解释为真实水下传感器或真实控制精度。

## 4. 为什么保留物理会更好，如何看学习的增量作用

当前物理模型知道质量、惯量、浮力等机械信息，采用与当前仿真力源相匹配的规律，并用同一训练数据拟合阻力参数。它不是随手选的粗糙模型，也不是无数据基线。在这些条件下，它剩下的预测误差已经很小；数据模型要进一步改善并不容易。

这个结果提示当前场景可供学习修正的空间较小，但还不能外推为物理模型在现实环境永远更好。存在未知水动力、参数变化或扰动时是否能产生学习收益，需要新的公平实验，而不能先假定必然获胜。

如果“提取物理作用”指保留已知规律，只学不足，残差模型正在这样做。如果指单独衡量学习贡献，应使用同一个MPC、同一个任务和输入条件，比较“只用物理预测”和“物理＋学习修正”。两者的实际闭环成绩之差才是该设置下的学习增量；用MPC相比反馈控制的收益不能直接都归给Koopman。

## 5. 提升模型为什么叫线性，和论文有什么区别

先把状态x转换为非线性特征：例如把速度v和v²都放进z=ψ(x)。本轮38项特征还包含姿态局部坐标、速度乘积等。固定矩阵模型为：

\[
z_{k+1}=A(p)z_k+B(p)\phi(a_k),\qquad \phi(a)=[a;a\odot a].
\]

p是质量、惯量等机械条件；在一个构型的一次预测中固定。a是共同推进器模型算出的输入加速度。A/B由训练数据学习。给定输入时，对提升状态z是线性传播；但特征ψ、输入平方和姿态解码都可以非线性，完整MPC因此并不自动变成线性优化。

交互矩阵模型进一步写成：

\[
z_{k+1}=\left(A(p)+\sum_i a_{k,i}N_i\right)z_k+B(p)\phi(a_k).
\]

新增Nᵢ表示状态特征与输入相乘的作用。给定输入序列后仍对z线性；同时考虑未知状态和待优化输入时，aᵢNᵢz是双线性项，所以称双线性模型。

用户提供的[Koopman论文](../../Research/agentic-auv/Sources/Papers/Koopman-based.pdf)第3页式(6)/(8)确实使用“非线性特征＋矩阵传播”。但其10维特征围绕平面航向控制设计，包含角速度平方、控制力矩平方和航向参考误差；本文38维特征、三维姿态与跨构型条件化是本项目扩展。论文该字典没有本轮后来加入的状态×输入交互项。不能把新增双线性模型称作原论文的严格复现。

论文还有在线参数更新，本轮模型则保持冻结；但论文也报告离线预测结果，不能简单用“尚未在线更新”解释本轮全部失败。论文在预测比较中给Koopman额外参考信号，本项目主模型对照先统一可用信息。论文未充分展开MPC中未来控制、参考误差与平方项的逐步处理，不能用猜测补成代码。

Koopman理论中的线性算子不保证任意有限特征都能精确预测。例如x⁺=x+αx²，看起来用[x,x²]就够，但下一步平方会出现x³和x⁴。有限字典遗漏这些影响时，只能依赖数据近似，误差还可能在连续预测中累积。经典[线性Koopman-MPC论文](https://mgroup.me.ucsb.edu/sites/default/files/publications/koopmanmpc.pdf)同样把它视为有限时域的近似预测，不保证任意非线性系统在所有未来时刻都被有限矩阵准确表示。

下面保留具体归因和求解结果，方便需要时核对。

## 6. 自由残差为什么会把预测修坏

同一真实起点与输入下，物理误差eP=y真−y物理、残差修正r=ΔKᵀψ，则 eR=eP−r，误差增量为 ‖r‖²−2ePᵀr。修正未对准真实误差，或者修正太大，就会越修越差。

已复算18个冻结模型；全部8个LOCO构型的角速度单步预测均比对应物理基线差，虽然源训练误差下降。heavy_moderate主要被“平移阻力特征→角速度输出”的自由交叉系数拖累；asymmetric主要是恢复力矩特征修正。删除相应组能显著减小退步，支持这些具体归因。某个特征虽有很大的标准分数，但其残差系数为零，不能把它当作原因。

绝对误差同样重要：heavy和asymmetric的物理单步角速度误差约6.97e−6和3.77e−5 rad/s，比值很大不等于控制必然剧烈失稳。受约束残差模型改变了结构约束及正则，不是旧自由残差模型的等价改写。详细分解见 [残差归因](evidence/phase9/residual-attribution-v84-20260927/README.md)。

## 7. 固定矩阵与交互矩阵的实际对照

固定A/B经过来源数据上的5档正则校准，pooled姿态RMSE从6.710降到1.577mrad，但最差窗口仍为3.871mm/6.501mrad，未过门。不能只看平均值。

加入交互项有明确代数动机：v⁺=v+Δt·a时，(v⁺)²=v²+2Δt·va+Δt²a²。固定A/B缺少中间项。新交互矩阵提升模型已加入该项，数值与CasADi计算一致，但这并不保证有限字典整体闭合，也不保证新增系数能从现有数据中可靠辨识。

严格相同来源折、相同λ的45个开发对照中，交互矩阵提升模型按原选模规则24个更差、4个更好、17个失败并列（这些是重叠折和参数，不是45个独立样本）；两类模型全部9个选中开发候选都未过预测门。交互矩阵提升模型在80步留出窗口失败32/72，在128步失败55/72；固定固定矩阵提升模型分别32/72、36/72。该结果不支持“补交互项即可解决”。

本轮专项测试与独立复算未发现矩阵装配转置错误、未来真值回灌及意外重提升；训练数组和分折哈希一致。现有证据支持“源域拟合改善未转化为多步迁移改善”。有限提升闭合误差、稀疏构型条件化和训练激励不足仍是需要拆分验证的假设，尚不能指定其中一个为唯一根因。

仅诊断的“每步解码再重提升”在pooled固定固定矩阵提升模型上降到0.813mrad并通过该局部门，但它改变了传播方式，不能称为线性提升成功，也没有据此换主线。来源校准详见 [固定固定矩阵提升模型](evidence/phase9/lifted-calibration-v84-20260927/README.md)、[交互矩阵提升模型原始结果](evidence/phase9/bilinear-calibration-v85-20260927/report.json)、[同λ独立审核](evidence/phase9/bilinear-calibration-v85-20260927/readonly-review.md)。

## 8. MPC求解与执行状态

六次离线求解首轮发现工具的父子进程路径绑定错误：父进程用相对路径、子进程用绝对路径，模型哈希未变却被拒绝。这发生在NLP启动前，六个子进程均未求解。原始失败保留；父进程保留了经独立复算的已有可行计划，但不构成新求解成功。修复后另建r2记录。

修复后的第二轮实际执行6次非线性优化（NLP）：**1次到达可接受精度收敛、5次CPU超时；没有一个新输出优于已提供且独立核验的最佳旧计划。** 六组都保留了可行旧计划，原单位约束违反量为0；这些是保留计划的复核，不是六次新优化成功。主监督器422.90秒、进程组已清理，原生退出1明确保留。

定位到另一个现有实现缺口：CPU超时时在读取最后x/g和独立验收前就返回，最后候选与约束残差没有保存。必须保留超时标签并补上候选复核，不能把“超时没返回计划”解释成“找不到可行解”。当前没有证据把慢唯一归因于CPU性能或目标尺度。见[求解诊断](evidence/phase9/server-parity-v84-20260927/solver-review.md)、[r2完整记录](evidence/phase9/server-parity-v84-20260927/solver-regression-v84-r2-results/report.json)。共同求解质量门仍未通过，暂不启动新闭环。

没有把离线预测/已有计划复算冒充新的2秒Isaac闭环。模型失败记录、旧实际执行失败和冻结材料均保留。

## 9. 固定同一机器人，换一种输入测试

基础构型代码名为base。PRBS是伪随机切换输入，multisine是多种频率叠加的正弦输入，chirp是频率逐渐变化的扫频输入。“激励”就是为了观察机器人反应而施加的输入；“留出”表示该轨迹没有参与这次训练。

随后按用户选择固定base：PRBS＋multisine训练、chirp留出，各5档固定/双线性模型，10次拟合。**8/10通过训练门，0/10通过留出门。** 因而不是只有“换构型”才出现问题；同构型换激励也会退步。chirp约55.47%的x速度样本、44.22%的y速度样本越出训练取值范围，双线性265个有效设计列中数值秩224，提示覆盖不足和弱辨识；尚不是唯一因果结论。未用chirp选择部署模型。

[单构型完整表与范围诊断](evidence/phase9/single-configuration-v85-20260927/README.md)、[独立审核](evidence/phase9/single-configuration-v85-20260927/readonly-review.md)。这一步同时减少了训练数据与构型变化，不能把差值全部解释为参数条件化的独立效应。

## 10. 当前证据与后续建议

- 控制支线：完成P/Rc共同求解质量复核；只有通过后才按同初值、同目标、同预演规则进入base/uuv4两秒配对。新求解规则下必须连物理对照一起重跑。
- Koopman主线：当前两类完整提升均未过门，应先拆分“单构型动态表示”和“跨构型参数条件化”，避免继续盲加字典。单构型诊断已按用户选择完成，仍未通过留出激励。下一步先定义控制目标范围内的训练覆盖与独立验证设计，检查确定冗余及已知积分关系的结构约束，再决定补采数据；不继续盲目追加自由特征。
- 2秒实际控制收益、未见构型泛化、长期稳定和实时控制均未由本轮证明；不削弱物理基线，不改成普通线性控制目标。

本地相关回归115项通过、6项因无CasADi跳过；服务器补齐对应数值检查（不能把重叠测试数量相加当独立覆盖）。本轮训练/验证使用CPU；GPU加速不是这里模型误差的解法。因果输入回放24条均通过；服务器原数值测试35项、新双线性/求解工具首轮15项、修订后19项通过，但这些不等于仿真闭环验收。
