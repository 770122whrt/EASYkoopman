# Phase 9：恢复候选与真实模型进程已接通

2026-09-20。八构型各一次固定 fit 起点请求，通过真正加载冻结模型的独立进程返回完整可行计划，**8/8 在父进程 100ms 门内通过，23.15–29.39ms**。116 项相关测试通过。当前结果仍是本地预测请求资格；计划未在船体上执行，完整低层周期、执行前仲裁和 Isaac 闭环仍未通过。

## 修复了什么

[先前源反例](evidence/phase9/deadzone-v49-probe-20260920/result.json)表明，base 零命令起点的“原命令加减0.002”九组候选都产生零推进器输入，不能靠这些候选区分运动响应。这不表示已经在目标位置的中性浮力船体也应该主动产生推力。

[v50 恢复基准](../koopman/recovery_solver_v50.py)保留父进程明确给出的前8个控制区间，再用当前观测生成一次完整静态需求，逐步按0.01变化率和原 fit 命令范围接近它。后12步是预先确定的候选命令，不假设未来反馈已知，也不登记为真实执行历史。需要恢复时，测试证明该序列能跨过原源映射的死区；若支持域限制了继续接近，仍记录受限误差及无进展，不能称为目标已达到。

模型工厂在 READY 前检查冻结 handoff、源 bundle、模型哈希和 fit 支持域，并完成编译。序列构造、搜索和末端命令复核共用100ms，父进程的100ms还包括传输和解码。模型、权重和物理递推没有重新拟合或改写。

首次真实 worker 测量为[6/8，NO_GO](evidence/phase9/recovery-v50-worker-20260920/result.json)。两例失败均为 base/long_body 的正 heave 候选：第8区间 PWM 距离 float32 死区面仅2.4214e-8，小于原2e-6要求，而 PWM 余量约0.98；不是计算超时或饱和。[只读诊断](evidence/phase9/recovery-v50-diagnosis-20260920/result.json)重构了已选候选，没有再运行模型。

[v51 搜索](../koopman/bounded_mpc_v51.py)把这项已有命令约束提前到候选预测与代价比较之前；[worker 接口](../koopman/recovery_solver_v51.py)继续保留最终独立检查。原候选、目标、扰动幅度、变化率、支持域和期限均保持。两例分别改选合法候选3、4；其余六构型的已选命令、预测与代价按原 rtol=atol=1e-12 对照一致。旧 v45/v50 源码和失败证据保留。

## 剩下的关键工作

1. 请求与真实已发历史绑定：相同执行/复位身份、worker代次、reference版本、模型/支持域，及命令前缀核对。
2. 固定激活位置：早到结果暂存，到请求起点后的第8区间才可能激活；晚到或漏过该位置不等待。回退替换过前缀后，旧计划失效，不能从旧计划第0步重新执行。
3. 当前状态与相应预测对齐：偏差超门、支持域外或接触等条件触发回退/停止；持续受限、无进展也需要有界停止规则。8/60秒的承诺区间是实际开环保持，不能宣称每一步都有新反馈。
4. 接上真实 Isaac reset/子步确认，再测低层完整周期和匹配闭环。当前每构型仅一次请求，不支持延迟尾部保证、冷启动稳定、跨构型控制收益或 Koopman/Agent 独立增益结论。
