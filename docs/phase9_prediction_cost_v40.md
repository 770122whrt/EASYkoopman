# Phase 9 首项预测计算优化 v40

2026-09-20。本报告跟踪09-02的工程性能验证，不提供闭环或新模型资格。前置为[路线审核](phase9_roadmap_review.md)。

## 改了什么

新增独立的prepared_projected_v40适配器，保留相同53/41维字典、冻结速度读出矩阵、已知位姿积分及输入/状态验证；每步旧姿态旋转复用，固定context的几何和拖曳系数在准备时计算。旋转计算从每物理子步6次减为2次。没有改变命令、TAM、PWM/执行器时钟、物理dt或模型参数。

准备对象独占不可写数组副本，逐次核对实际context，不缓存预测输出或跨分支状态。构型、物理参数变化必须重新准入和准备，不能静默沿用旧缓存。模型的训练/冻结provenance仍由已有加载器负责，适配器本身不做科学晋级。

## 判断和后续

本次小型检查证明这项等价优化有效，但85.82–104.02ms的20步单候选仍超过16.67ms。还未达到60Hz在线MPC，也没有实际求解器或闭环收益。

full已通过；下一项有界假设是将多个候选状态的模型递推批量计算，减少逐候选Python/小数组开销；不要求现在就添加GPU或新依赖。批量计算必须保持每个分支完整执行器记忆、两子步hold、mask/TAM和错误隔离，复用原始逐候选路径作为参考。若batch造成浮点差异超出原合同，应保留失败、定位运算路径，不能临时放宽容差。

选择优化器/调度之前，仍需测完整批量候选与整个求解轮次；低频优化必须配合60Hz非阻塞仲裁、已执行前缀核对、计划有效期与晚结果拒绝。任何一项欠缺都不能称Phase9完成。当前不需要服务器。

控制目标的另一个具体检查：uuv4*仅将命令yaw置零还不够，目标成本与结果评分也必须对不可控yaw不敏感；后续合同需以只改变yaw的反例验证。不能直接沿用旧8D PWM控制器的全姿态成本，也不能让被屏蔽yaw间接改变优化排名。
