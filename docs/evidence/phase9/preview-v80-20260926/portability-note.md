# uuv4跨平台复核差异

原Linux完整验收通过。Windows原验证器在第4物理步的记录成本比较失败：记录0.002026655382688722，重算0.00202665567407511，差2.91e-10超过原1e-10门。该失败保留在 `uuv4-off-original-local-failure.json`，不改写服务器验收。

59个决策完整诊断：成本最大差3.56e-10，80步预测的各分量最大绝对差不超过2.10e-7。对全部实际指令及选中计划共1240条输入做相同探针：B矩阵、虚拟控制逐元素相同；Linux Torch2.7.0与Windows Torch2.8.0经float32伪逆/矩阵乘法分配得到的PWM最大差5.22e-8，4777个元素不同，死区分类差0。不是模型文件或任务更换，也不是求解器重新求解。版本、输入SHA和全部输出保存在 `uuv4-off-platform-{local,server,comparison}.json`。

新增 `workflows/validate_portable_v82.py` 作为**补充**本地复核：验证旧验证器源码SHA，私有加载，只有记录预测/独立预测重算使用绝对容差1e-6，记录成本/计划成本使用1e-8。命令因果性、选择支配1e-10、实际PWM2e-6、CPU计划余量3e-6、状态支持、安全、身份和退出检查均不变。原Linux严格验收仍为必要条件。

容差针对保存值跨平台复算，不用来放宽可行域；它大于已观测平台差异，远小于任务尺度（2cm、40mrad）。这是当前轨迹的经验性可移植核验，不是全域误差定理。成本/预测/命令/源码四种实质篡改仍被拒绝。完整uuv4反馈和预演关闭臂已通过补充验收，见 `uuv4-partial-return-verified.json` 和 `*-local-portable-acceptance.json`。

诊断期间暂停的只是v82依赖等待进程；运行中的物理队列及全部冻结控制源码未修改。最终状态以当前交接入口为准。
