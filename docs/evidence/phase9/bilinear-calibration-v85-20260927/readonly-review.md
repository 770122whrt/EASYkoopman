# 双线性v85为何没有改善：独立只读审核

2026-09-27。本次仅检查既有记录、代码和准备后模型类型，没有新拟合、预测回放、求解、仿真或选参。原负结果保留。

## 实现与公平性

- `PreparedBilinear`继承`PreparedLifted`，实际类型检查为True，动态方法为`PreparedBilinear.step`。共同forecast只在起点提升，随后传递上一步latent；只有明确命名的`relift_diagnostic`分支重提升。没有发现因继承使双线性项未执行或误重提升的问题。
- 九个外层折的来源配置、内层训练配置、开发构型、外部目标、内层轨迹与开发轨迹哈希全部与固定LK一致。
- 45个同λ开发模型，加9个外层重拟合模型，共54组训练数组哈希与固定LK一致。比较使用同一真实起点、记录加速度、状态边界、时域和门；未改变字典或输入平方特征。
- 从保存的开发rows独立重算九次选择，均与selection记录一致。代码顺序明确是开发选λ→写selection→外层重拟合→外层评价；pooled两实验文件写入时间顺序亦一致。选模函数不接收外部评价数据。
- **双线性九个选中开发候选均未过门（0/9）。** 两个开发折全候选失败时，仅按预定同分规则选较大的λ；外部离线计算不能理解成控制准入。

## 不能只比较不同的“最佳λ”

## 有哪些直接证据，哪些仍是机制假设

**已有直接证据：** pooled来源开发λ=1e−6，训练三轴角速度读出RMSE范数由1.1878e−5降到7.9413e−6（约下降33.1%），来源留出开发却由0/9失败变为9/9失败。改善源训练拟合没有带来来源构型外推改善。增添216列后，设计由490变706；更多自由度在有限数据上并非自动有益。严格而言，尚未做足够消融来确定哪一组系数是唯一致因。

**双线性确实补齐了指定的表达缺口：** 对`v_next=v+dt*a`，平方更新中的`2*dt*v*a`现在可以由N表达；已有精确积分器平方测试、非零训练系数到A/B/N运行式及训练RMSE重现测试支持实现正确。但训练过程没有强制N取解析积分器系数，它仍是从有限数据估计的自由参数。

**仍非完整闭合：** 比如字典中的`w_x*w_y`即使在简单积分器下也产生`dt²*a_x*a_y`，当前输入仅含逐分量平方`a_i²`，没有不同轴的输入乘积。带符号阻力平方和局部姿态坐标还有非多项式/高阶变化。指出这些限制不代表本轮应继续加特征，更不证明它们已是观测退步的唯一原因。

**还存在数据与正则混杂：** N为了有界辨识在构型间共享，不随机械描述变化；来源构型有限，交互列相关性可能导致拟合系数不可靠。加入列后，即使同λ，ridge的有效假设空间也发生变化。来源校准已经排除了“完全没试小λ”的简单解释，但不能保证找到了所有模型的最佳正则，更不能据外部失败继续挑λ。

## 结论与证据身份

当前实现没有发现latent记忆或A/B/N调用错误；与固定LK同来源同λ对比，双线性多数开发格子更差，少数改善但仍未达到门。pool选中模型有9/72个80步窗口失败（固定LK为0），LOCO两者均32/72失败。保存全部失败后，现有证据只支持：**本数据、字典与拟合规则下的双线性候选未取得可用优势。** 不支持否定所有双线性Koopman方法。
