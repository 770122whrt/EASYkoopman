# Phase 9：求解与控制修复结果（v77）

2026-09-24。v77有界求解与控制实验已交付。r4首组四构型×两模型8例均完整验收；原repair设置仅base改善0.67%，其他三个构型仍负收益。uuv4提高深度权重并延长时域后，相对反馈改善12.15%，是短任务局部收益，不是统一跨构型或独特Koopman收益证明。模型冻结、零训练，Phase9保持开放。

## 先看结论

- **求解可靠性改善了。** 修复反馈失败提前否决MPC、子进程线程继承和PWM死区零梯度初值；原先中止的uuv4两模型都完成2秒任务。
- **找到一项局部控制收益。** uuv4提高深度权重并延长时域后，综合误差比反馈低12.15%。原repair统一设置仍只有base微小改善；新设置尚未覆盖其余三个构型，不能混成同一策略的跨构型成绩。
- **还不能证明独特Koopman表示收益。** 当前投影分支的控制读出与同D/Q参数的物理模型等价；名义物理对照使用D=0、Q=1。它们的差异最多支持参数及其与求解过程的交互影响。

## 公平比较的范围

首组base、uuv4、long_body、uuv6；同v76的seed19760、零速度/零转速初态、深度5.5m、俯仰目标0.04rad、2秒任务。每例60个30Hz命令、240个120Hz物理子步；求解时仿真暂停，**不是实时性验证**。模型、机械参数、TAM、输入/状态支持域及安全规则冻结；没有训练。

反馈是**PD加物理补偿**，不是传统PID或persistence。新base反馈与v76冻结base反馈的240个状态、命令、转速最大差均0；其余三个反馈明确复用同一新服务器环境的v76验收轨迹。r4八个MPC全部重跑，未从r2/r3挑选最好成绩。

综合分数=mean[(深度误差/0.02m)²+(姿态误差/0.04rad)²]，越低越好。百分比=100×(1−MPC分数/反馈分数)，负数代表变差，不是失败率。

## uuv4目标与时域消融

事前设定repair=深度权重1、时域10区间(0.333秒)；depth4仅深度权重1→4；depth4_h20在depth4基础上仅时域10→20(0.667秒)。其余目标权重、约束、模型、迭代与CPU上限不变。

| 模型 / 设置 | 深度RMSE (m) | 姿态RMSE (rad) | 综合分数 | 相对反馈 |
|---|---:|---:|---:|---:|
| 投影模型 / repair | 0.016869 | 0.017734 | 0.907941 | -324.41% |
| 投影模型 / depth4 | 0.005198 | 0.016715 | 0.242167 | -13.20% |
| 投影模型 / depth4_h20 | 0.000411 | 0.017322 | 0.187943 | +12.15% |
| 名义物理 / depth4_h20 | 0.000674 | 0.017440 | 0.191225 | +10.61% |

只提高深度权重时，投影分数由0.907941降至0.242167，改善约73.3%，但反馈为0.213930，仍差约13.2%。说明目标权重是实质因素，不能据此说已追平。

再将时域延长到20区间后，投影分数降至0.187943，相对反馈改善12.15%；深度RMSE从反馈0.001693m降至0.000411m，姿态RMSE从0.018189rad降至0.017322rad。两项实际误差都降低，不是只改了评分公式。该例原生采集769.19秒，明显高于depth4的181.94秒；这说明控制能力与计算成本需要分开评价。

depth4与depth4_h20的单次求解墙钟中位数分别1.09/13.81秒。H20共59次决策，43次optimized、6次recovered、9次warm_retained、1次baseline_retained；底层26次达到160迭代上限。所有最终执行序列都经过精确可行性和代价比较，达到迭代上限不等于执行非法序列，也不能称收敛最优。收益并非全部来自回退，但没有全局最优或实时性证明。

同一depth4_h20设置的名义物理MPC分数为0.191225，相对反馈改善10.61%；投影分支相对该物理MPC的误差下降为+1.72%（负数即投影更差）。这一配对区分模型参数与共同控制设置的影响，但仍不足以证明独特Koopman表示贡献。

事后从实际命令核算，投影分支的命令平方积分/PWM平方积分分别为反馈的0.966/0.992倍；名义物理分支为1.018/1.049倍。它们只是控制强度代理，不是实测能耗；原始值随本地指标重算保存。本次投影分支的跟踪改善未伴随这两个代理增加，仍不宣称能源效率收益。

调试消耗了启动名额，因此在任何profile闭环启动前，已将原拟uuv4/uuv6消融收窄为上表最后三例uuv4。总上限不增加：22次物理启动、原生采集+验收120分钟、两端各256MiB新增研究文件；每次启动预留1100秒，采集900秒软限/1000秒进程组外限、验收90秒。原准备队列不等于实际执行。目标消融仅作开发归因，不混用不同构型各自最好profile，不称独立验证。

## 为什么仍控制不好：证据与待证假设

1. **局部短预测失准不是当前最强解释。** uuv4 r4投影分支236个实际子步，在相同已发首命令的下一控制区间内，最大深度误差6.30e−7m、姿态误差1.99e−5rad；差表现uuv6 r3分支也很小。它不保证完整未来时域或未知构型预测。
2. **负收益并非只有评分口径问题。** 按原优化权重重算实际2秒轨迹，uuv4 r4投影/名义物理代价仍比反馈高130.62%/197.64%。这是完整实际轨迹代价，不是重叠预测代价相加。
3. **内部反馈参照偏弱、局部最优和短时域仍需归因。** 当前内部参照保持一个反馈命令，实际反馈每步重算。优化器超过该参照并不保证超过真正反馈控制器。权重/时域消融只检验其中部分因素。
4. **因果反馈预演有离线改善迹象。** 在uuv4 physics4/80/160，基于模型预测的未来状态逐步计算反馈，再作为同一个NLP初值，所得预测代价比r4当时所选计划低17.39%/35.23%/8.94%；三次均精确可行。未读取真实未来控制，历史未改写。该方案尚未接入真实闭环，不能算控制收益。
