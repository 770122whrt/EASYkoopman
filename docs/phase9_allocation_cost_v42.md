# Phase 9：固定推力分配预计算 v42

直接分配器及其批量预测集成已通过本地数值和成本检查。八构型K8/H20整批p50为79.29–159.34ms，相对同轮v41提速1.675–3.636倍，中位2.864倍；最大已测字段差2.22e-16。这仍不足以宣称60Hz控制或完整MPC可行。

## 改动与验证

新增[prepared分配器](../koopman/prepared_allocation_v42.py)与[v42批量路径](../koopman/command_batch_v42.py)。每个预测批次只构建一次固定TAM逆；保留原float32标量einsum归约、WLS权重、roll/pitch/yaw/depth符号、控制掩码和PWM限幅。旧8推混合保持原运算顺序。只移除预测用不到的PID诊断副本，不改变实际plant、真实发令路径、浮点执行器时钟或已发命令历史。

45项针对性测试先RED（缺新模块）后GREEN，27.666秒含启动。覆盖八构型、随机/饱和/死区邻域命令、固定逆调用次数、并行和输出隔离，以及合成模型上的H20/H128整批递推、历史起点、失败候选和deadline。另155项相关模型/命令/执行器回归通过，50.618秒含启动；未运行全仓测试。[原始测试记录](evidence/phase9/allocation-v42-checks-20260920/focused.txt)。

## 实际fit轨迹计时

[协议](evidence/phase9/allocation-v42-pilot-20260920/protocol.json)预先固定八构型fit PRBS、pooled冻结模型、origin128、8候选×20控制区间。候选使用既有fit命令加固定0.0005正弦扰动，首候选不变；一次预热、三次交错计时。每个候选同时对照旧v41批量路径及v39+原v30标量模型。rtol=atol=1e-12保持。[结果](evidence/phase9/allocation-v42-pilot-20260920/result.json)在47.688秒完成/native0，无重拟合、正式test访问或服务器运行。

## 剩余热点与路线

[两构型剖析](evidence/phase9/allocation-v42-profile-20260920/result.json)在9.625秒完成/native0。base模型递推约53.7%、分配约12.1%；uuv6_angled分别约44.5%和28.6%。固定逆预计算消除了上一轮的主热点，但小数组运算和Python调度仍需处理。此比例只用于定位，插桩耗时不作为实时分位。

下一项先有界评估固定预测数值核的编译执行，保留模型矩阵、物理更新和既定容差；仅编译一个环节后重新看整批成本，不同时改模型形式或优化算法。即使编译提速，完整求解器、非阻塞仲裁、实际发令前缀匹配、状态支持域和超时回退仍需另行验证。优化频率必须由完整求解测量决定，不能把仿真停表时间当实时成功。

[源/结果复核](evidence/phase9/allocation-v42-pilot-20260920/review.json)通过，v38关闭结果、正确handoff v2及预算三项hash未变。当前1800秒工程阶段已测1620.127秒，另保留30秒启动余量，保守1650.127秒，剩余149.873秒。后续编译试验按09-02的新阶段单独记账，不重置历史。未安装新依赖。
