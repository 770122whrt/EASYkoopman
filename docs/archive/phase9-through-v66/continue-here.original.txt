## 需要优先批判的当前结论

1. `_apply_action()` 是否确定在目标 Isaac Lab 版本的每个 physics substep 都调用？如果本机无法核实，必须把它标为待 runtime trace 验证，而不是确认事实。
2. 即使两个 substep 的 `virtual_control` 不同，最正确的离散输入应是什么：最后值、均值、时间序列、generalized impulse、raw action，还是 controller state augmented input？
3. “每个 control step 只计算一次控制并 hold”是否改变 S-surface/PID 的设计带宽和闭环稳定性？它是否反而让采集 plant 与现有 baseline 不再相同？
4. 如果 Phase 9 MPC 直接输出 `virtual_control_4` 并绕开 S-surface/PID，Phase 8.2 在 inner controller 下采集到的映射是否仍与 Phase 9 的执行 plant 一致？
5. 当前 pooled Koopman 与 simple linear 数值相同，主要是候选/observable 等价导致，还是控制合同导致？不能在没有消融时把二者混为同一个根因。
6. platform PCA2 缺失 exact $B$/authority 是否真的伤害预测，还是 conditioning 结构、样本覆盖或数值 gate 才是主要瓶颈？
7. `actuator_memory_4` 的不足能否用可部署 estimator 修复？8D padded memory 会不会因为不同构型推进器索引不具有共同物理语义而制造新问题？
8. 现有数据能用于哪些 exploratory diagnostics？哪些结论必须 fresh recollection？不得把探索性重分析伪装成新 protocol 的正式结果。
9. Phase 8.3/8.4 是否是最小、最清楚的阶段划分？也可以提出单一 forensic phase、独立新 milestone 或线性-only 路线。
