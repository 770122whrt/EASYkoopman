## 下一步与方法判断

1. **先测清首周期组成。** 在独立诊断入口分开记录边界读回、决策、`env.step`、子步快照/接触检查/确认，以及渲染和第一次调用准备开销。计时应覆盖异步工作的实际等待，避免把 GPU 提交时间当完成时间。正式 16.67ms 失败保留；不能删除首周期、放宽门或把较长诊断预算写成实时通过。
2. **独立定位退出后的崩溃。** 用最小初始化/reset/关闭生命周期复现，保留 Python faulthandler/可用原生栈与退出码，检查 native 资源引用和释放顺序。不能通过强制 `os._exit(0)` 或忽略负退出码绕过故障。
3. **有证据再修复、再做新版本短预检。** 仅调整测得的实现瓶颈；物理积分、控制输入、模型和安全检查保持。若实测表明仿真墙钟达不到 60Hz，需要明确区分离线仿真控制效果与目标硬件实时能力，重新讨论实验口径，不能自动把两者混为一谈。
4. **预检通过后才做匹配闭环比较。** 当前仍保留 Koopman-UUV 主线；尚无证据要求重训或否定模型，也没有依据声称控制收益、未见构型泛化或 Agent 收益。不要因本地测试数量增加而跳过真实控制证据。

本轮原失败已保存，停止的是这一版冻结预检；下一次服务器工作应针对以上明确问题，避免原样重复八构型运行。
