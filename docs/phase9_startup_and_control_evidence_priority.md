# 启动与稳态分开，优先验证闭环效果

2026-09-21，依据用户本轮明确意见修正下一步：首周期允许作为启动阶段单独评估，尽快回答当前Koopman路线是否带来控制收益。本文更新研究顺序及待实现的验收语义，不是新实验已经通过或已经运行的记录；旧v58–v64结果保持原协议下NO_GO。

## 当前证据与瓶颈

v64在八构型96次离线直接求解中验证数值等价和40%–44% CPU提速；实际base首周期27.767ms，决策2.603ms，1区间/2物理子步后停止，MPC请求及激活均0。计时包含回读、发令、物理推进、子步校验和确认，不能归为纯控制器或纯PhysX耗时。稳态尚未测量，不能认定慢只发生在首次。

v38已有八构型24 validation＋24 test的限定预测证据：pooled及heldout主门通过；test中heldout自行递推的汇总速度分数约为persistence的0.54%–2.01%。这是特定指标、工况及已知机械上下文下的预测表现，不是控制误差，也不是完全未知平台泛化。当前投影预测器与相同D/Q系数的参数物理模型等价；不能将其预测成功表述为独特Koopman表示优势。实际闭环收益、适应及Agent收益均未证明。

## 启动规则的具体修改方向

采用新版本入口，冻结旧包不改。模型加载、编译和静态准备仍在READY前完成。仅首次实际控制区间标记startup，建议初始有限墙钟上限100ms；保留完整初态、发令、执行器、接触、状态范围和物理回执检查。此100ms为待实现的启动上限，不替代求解100ms门，也不是已测安全保证。

启动区间成功收到两物理子步回执后，只重新锚定一次后续墙钟调度起点；物理dt=1/120、每控制区间两子步、状态与执行器历史继续递推，不reset、不丢弃启动轨迹、不补发赶周期。不能只删除首次deadline判断而继续用旧due，让启动超时债务污染后续；也不能每周期重新锚定掩盖持续超时。

启动耗时单列，后续全部区间报告最大值、分位数、超时数与比例、计划年龄和实际MPC激活/回退比例。短预检仍以稳态16.667ms为实时资格门；若失败，记录其实际位置，不用“尽可能”替代可衡量结果。先base连续短运行确认MPC确实提交、接收并使用，然后才扩展构型。

## 尽快得到控制效果证据

将控制有效性和硬件实时性分成两个结论，避免全仿真器墙钟持续阻塞效果检验。先用编译、不默认共享的固定模型和优化设置，进行小型、匹配的实际Isaac闭环pilot；优先base、asymmetric和一个欠驱动构型，任务含安全支持域内非零深度阶跃及可控姿态变化。精确参考幅度、运行长度、种子和接受差异在运行前冻结，不读取旧正式test来选参。

首个因果对照是相同反馈回退：一组启用MPC、一组禁用MPC，仅这一开关不同，初态、参考、扰动、物理与约束相同。必须确认MPC存在实际接管及发令差异；全程回退不算MPC有效。指标包括可控姿态/深度跟踪误差、恢复时间、命令变化与推力代价（非实测电能）、越界/接触/饱和、回退比例及计算时间。欠驱动构型不以不可控yaw处罚。匹配Legacy/S-Surface作为后续原控制器对照，避免其参考语义不一致造成不公平比较。

若实时短预检依然受仿真器墙钟限制，可另行固定“仿真时间控制效果”协议，保持物理dt、信息权限及统一承诺/延迟规则，让各方法使用同一固定模拟执行时序。必须显式实现该调度并检查接管因果性，不能仅屏蔽旧deadline或让异步线程靠主机快慢随意改变控制序列。其结论仅限仿真闭环效果，不报告60Hz部署资格；原实时失败保留。新运行前仍需要具体有界协议、资源范围和服务器就绪检查，不复用已结束v64启动次数。

先回答“当前路线是否优于纯回退/原控制器”。再在相同优化器和约束下比较名义参数物理预测器与当前学习预测器，判断学习参数的收益；相同辨识D/Q参数模型是等价性对照，若相同应报告等价，不能强求Koopman独特优势。pilot无改善或频繁失败则先检查候选搜索、承诺延迟、模型误差及回退原因；公平对照仍无效便修改路线，不扩大Agent/自适应工作。
