# v36：可分支调用的4D因果命令预测接口

2026-09-13，下一项有界实现合同。承接[v35结论](phase8_4_kinematic_dictionary_v35_results.md)，属于07/NID-05的实际受控模型合同核查，不是Phase9正式交接。用户既有代码及服务器授权持续；本项仅使用本地source和原fit，无服务器运行或新正式D-23。

## 决策

停止自由位姿字典的自动扩展，保留冻结v30的结构化速度读出与已知运动学。现有独立证据支持其限定预测可用性；参数模型等价性和学习优势未证实的结论一并保留。不会给同一模型换名后声称新Koopman算法，也不把它改说成常数A/B线性系统。

实际待补接口为 `F_c(x, rotor_history, planned_u4)`：输入当前观测状态、从明确冷启动起点连续记录到当前控制边界的已发命令历史、接下来计划执行的有界4D命令。通过同一配置的mask/TAM/PWM、float32时钟的N维转速估计，逐个物理子步重建作用加速度，推进已冻结预测器。一个4D命令保持两个物理子步，两个作用输入一般不同。

旧v32 policy_forecast每段未来命令由FeedbackPolicy根据自身预测状态产生。新接口接收优化器可选择的计划命令，具有独立分支语义；同一历史/初态/命令重复调用或改变另一个分支，都不能污染结果。每个分支的执行器状态必须从相同历史恢复。初始接口不追求加速历史重放；需要缓存时另做数值等价验证。

接口必须拒绝不完整控制边界历史、错误配置/context、超界或非有限命令、无效状态和伪造原点索引。未来真实状态、实测转速和未来实测wrench不作为输入。返回每个子步的预测状态、执行命令、PWM/估计转速/作用输入及失败位置，失败不得留下成功标记。欠驱动mask的效果明确记录。原静态初始化/参数合同仍适用，动态换构型不在范围内。

## 固定本地验证

1. 先RED：不同分支互不污染；两个子步转速不同；同一步作用；历史和控制边界检查；欠驱动mask；配置/实际context不一致拒绝；非法未来真值参数不被API接受。
2. 使用原fit中八构型第一条PRBS，固定起点128。先让旧policy_forecast生成4个控制区间，再把其命令序列输入新接口。从同一个初态和历史逐子步比较：state、估计作用输入与旧循环直接重算差≤1e-12（float64模型）；float32命令/PWM保持精确相同。旧数据只用于source/接口等价，不能称新独立精度验证。
3. 同一初态作不超过两组预设有界命令分支，检查没有后见真值、状态/时间/转速串扰或越mask执行。不给这种局部有限差分冠以全局线性B，也不据此选MPC参数。
4. source及真实fit接口核查最多300秒，零新模型拟合、零新仿真、零validation/test访问。冻结调用脚本与所用父模型/fit身份；另承接v35及此前资源账本。结果不足时修具体接口，不重开旧采集。

通过后再准备新独立命令/策略预测的具体协议，以及真实非线性命令映射下优化器的方案与计算预算。比较器保持同信息：persistence、线性、已知物理、同系数参数模型。下一步控制若使用线性化/SQP等方法，应按实际优化器报告，不继承常数A/B Koopman-MPC的线性QP或速度优势。Agentic策略的收益另做消融；这些工作均未因本设计获得完成状态。
