# 修复控制链后，为什么仍然落后于 persistence

本轮在修复后的真实Isaac轨迹上完成了12个预声明的线性增量诊断拟合。结论是：**控制子步顺序值得保留，但只补顺序或增加转速维度，尚不能解决预测误差。单构型换seed也会失败，因此不能把问题全部归因于跨构型。**

新增8个进程、256控制区间，拉回49文件全部通过SHA256、源码、实际加载、原生退出及子步检查。连同已有修复轨迹，共12条独立轨迹；每构型1条32步PRBS用于fit，另1条不同seed的PRBS及zero/step用于评价。warm/off重复轨迹不增加独立样本量。新的拟合不读取Phase8.2轨迹，也不改其NO_SELECTION。

所有12条轨迹的命令驱动转速估计误差不超过1.184e-4，且没有读入实测转速修正状态。估计可重建与模型可预测是两件需要分别验证的事。输入包含同一实际轨迹上两子步的因果重建值；未来输入可知仅适用于这次预设动作控制器。

## 可以与不可以下的结论

- **CONFIRMED：** 原控制边界遗漏首子步、执行器状态与4Dproxy不同、冷启动参数时序和reset历史曾有缺陷。它们已具备直接取证或修复对照。
- **PARTIALLY_SUPPORTED：** 子步顺序遗漏对本次拟合的姿态/角速度预测有影响，收益随构型和通道变化。不是所有误差的唯一根因。
- **UNCERTAIN：** 真实N维状态相较4Dproxy是否改善泛化；当前比较没有一致支持。增加维度同时增加有限样本回归负担。
- **REFUTED（针对本次样本）：** “同构型已经表现好，只是跨构型才坏”。这里每个模型只拟合一个构型，换seed仍有严重角速度误差。

每次fit只有32条相邻数据、5–7种PRBS动作，非偏置特征19–29维。部分转速特征成对相关，base的转速设计秩低于列数；其他矩阵虽然数值满秩，最弱方向也极小。秩和正则化通过不能证明覆盖充分。zero/step结果同样没有建立全面收益，且zero的姿态分母接近零，应查看绝对误差而不是夸大倍率。

下一步采用一个与未来4D MPC一致的直接pre-TAM接口，明确其区间保持波形，保留完整因果执行器状态及几何。先做原输入序列的执行等价检查，再用全新的多激励、整段隔离pilot辨识。它是需要验证的研究路线；本轮没有可晋级Koopman模型。
