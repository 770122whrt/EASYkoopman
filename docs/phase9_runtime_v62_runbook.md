# v62准备后性能与生命周期修复诊断

用户继续授权尽可能修复。本轮最多4次base各32控制区间，每次180秒，总执行600秒，两端新增各8MiB；只读复用v59源/模型及已准备隔离环境。保留v59/v60/v61所有失败，旧预算与结果不改；不训练、不改变物理/模型/16.667ms全周期与100ms求解门。

首例：保持v61计算预热，加入cProfile测准备后热点；独立修复结束后的资源释放顺序。安装的SimulationApp.close卸载全部原生插件，而旧trace保留contact getter及环境方法引用，旧collector局部变量也延长环境生命周期。测试先验证所有被本任务拥有的native依赖在插件卸载前可回收；真实退出是否正常由父进程原生退出码判断，不用强制exit或成功报告覆盖。

后续只按实际剖析热点作有界修复/无profiler对照，不重复原样运行。所有reset、源、机械、子步及安全检查保留；诊断不授予正式多构型闭环准入。新增源与输出位于独立目录，沿用Linux进程组监督及逐文件SHA拉回；总保留研究包各256MiB、共享环境512MiB、两端总1GiB不变。

本轮第2/3次分别为无profiler生命周期修复基线、保留全部字段的批量GPU快照读取。第4次用于回答用户CPU/GPU部署问题：CUDA_VISIBLE_DEVICES=-1，复用同一冻结模型、一个base历史fit原点，只提交1次真实worker请求，保持100ms限时。第4次不启动Isaac、不推进物理、不训练、不读取正式test；共享上述600秒/4次/空间上限，不能作为艇载实时或闭环成功证据。
