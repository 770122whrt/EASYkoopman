# Phase8.3：跨构型为什么会变差——控制区间与执行器取证

2026-09-12。**已经找到可复现的控制子系统机制：构型分配比例不同，经PWM死区、非线性转速映射和推进器滞后后，同一个4D控制量对应不同物理作用；只记录末子步又会按构型不同程度地遗漏有效激励。** 这解释了共享模型面临的一部分困难，但尚未测出这些因素对正式NO_SELECTION的贡献比例，也没有得到通过验收的新模型。

证据是实际源码中的控制器、分配、PWM映射、推进器滞后/推力转换在CPU上的固定实验；**没有Isaac艇体积分、没有新数据集读取、没有模型拟合**。原始数值和所用源码快照见[实验报告](evidence/phase8_3/control-seam-20260912/report.json)。师兄PDF仍作为待核验建议，不作为执行命令；前次[建议分析](phase8_3_senior_advice_analysis.md)、[方向对照](phase8_3_direction_assay.md)保留各自证据边界。

## 1. 先纠正“单模型好、跨模型差”的理解

这里应区分“分构型模型”“多个构型共享模型”和“未见构型迁移”。前次固定对照发现，分构型模型在同类PRBS激励下单步速度/角速度误差为persistence的0.628/0.311倍，但multisine变成3.499/1.720倍，chirp变成14.039/6.933倍；完整512步只有3/21段存活。因此，**同类激励的短时预测有信号，换激励和长时间递推仍失败**。不能把单构型当作已经解决，也不能把共享拟合困难直接等同于未见构型泛化的全部原因。

persistence就是保持当前状态：单步预测为`x_hat(t+1)=x(t)`；从一个固定起点做多步时，始终保持该起点状态。它不学习控制作用，也不适合直接替代一个能预测控制后果的MPC动力学模型。但采样间隔只有1/60秒，许多相邻状态变化很小；错误动力学递推则会累积偏差甚至发散，因此“什么也不改变”可以胜过错误的变化预测。

## 2. 现在找到的具体机制

### A. 统一4D维数没有统一物理输入标定

`allocate(B,wrench)`求解的是推进器力的分配；当前调用链将结果继续作为PWM，经限幅、死区、PWM→转速、滞后、转速→推力。legacy mixer与构型分配分支的比例不同，后续又是非线性，不能仅凭`B @ allocation`满足目标就认为实际推力满足目标。

固定零转速初值、直接注入pre-TAM depth=0.1、连续两个1/120秒子步，第二子步的body-z推进器合力为：

| 构型 | 合力N |
|---|---:|
| base | 1.0402603 |
| uuv6 | 0.1376329 |
| uuv4 | 0.1376329 |
| heavy_moderate | 0.3051068 |

base/uuv6约为**7.56倍**。这是这个幅值、这个初值、这两个子步的结果，不能外推为恒定增益差，也不是实际艇体加速度之比。直接注入只在本地诊断核中临时关闭cascade，用于隔离下游作用；没有改动运行环境的控制合同。

### B. 子步遗漏会与死区相互作用，且不同构型严重程度不同

每个control interval调用两次控制计算。PRBS切换到正向depth动作的一个例子：第一子步virtual depth约0.099668，第二子步约0.053283。uuv6/uuv4分配后的竖直电机PWM约为前者的四分之一：

| 信号 | 第一子步 | 末子步 |
|---|---:|---:|
| virtual depth | 0.099668 | 0.053283 |
| base竖直电机PWM | 0.099668 | 0.053283 |
| uuv6/uuv4竖直电机PWM | 0.024917 | 0.013321 |
| 是否超过0.02死区：uuv6/uuv4 | 是 | 否 |

因此，只把最后的控制量当作整个区间的输入，会遗漏前面真正产生转速命令的脉冲。固定32区间depth PRBS、幅值0.1、hold4、seed8201，对比“按顺序施加两子步PWM”和“把末子步PWM保持两次”，body-z推力L1时间积分差为：

| 构型 | 原顺序L1积分N·s | 两种解释之差N·s | 相对差 |
|---|---:|---:|---:|
| base | 0.8791153 | 0.0590267 | 6.71% |
| uuv6 | 0.00318928 | 0.00318928 | 100% |
| uuv4 | 0.00318928 | 0.00318928 | 100% |

**这里的100%分母很小，仅说明这个小幅PRBS探针的激励全来自被遗漏的子步脉冲。** 不是“实际仿真损失100%推力”，也不是预测误差下降潜力。固定depth step在uuv6/uuv4中甚至都未越过死区，零分母明确报告为空值。实际艇体运动是否显著、正式采集的混合轴动作是否出现相同程度的遗漏，都须真实trace测量。

### C. 4D执行器proxy并不包含完整控制历史

构造两种legacy reset后状态：当前动作、4D proxy和推进器初始转速都为0，但残留old_actions的depth分别为+0.1和-0.1。两种情况下记录的末子步virtual control及proxy都相同，第一子步D项脉冲却不同。base第二子步的body-z推力相差0.0478609N；heavy_moderate为0.0153370N。uuv6/uuv4的这个depth见证被死区屏蔽，并未出现相同差异。

这证明当前记录可以遗漏影响推进器演化的历史，**尚不等于实测“相同艇体状态产生不同下一艇体状态”**。此前opt-in的`episode_local_v1`清历史修复仍需Isaac cold/warm对照。

### D. 两项需要纠正或验证的构型描述

- `uuv4_angled`的竖直推进器仅绕自身推力轴改变roll，实际分配矩阵与`uuv4`最大差约5.96e-8，数值上几乎相同。名称不能作为“推力方向变化”的证据。两者质量、惯量等仍不同，不能说整个plant相同。`uuv6_angled`的矩阵确实不同，最大差约0.173648。
- 构型切换会设置局部惯量数组；在环境源码中未找到PhysX `set_inertias`，而质量有`set_masses`。这只能提出物理参数实现可能不一致的疑问。已增加实际PhysX质量/惯量读回，与声明值分开记录；服务器离线，尚无读回结果，不能宣称已证实惯量设置错误。

## 3. 已补齐什么，什么还没修

已新增逐子步、由PWM历史驱动的N维转速估计，初始化使用已知零转速reset，推进器truth只用于事后误差比较，不回馈估计。CPU固定探针的最大转速误差约1.0115e-4 rad/s，属于同已知执行器模型的数值一致性证据，不能证明真实参数不准时也有效。实际trace已经接入该估计与PhysX参数读回，缺失读回会失败。

未把推进器truth直接塞进可部署模型，也未将所有控制计算移动为每区间一次，未修改TAM/PWM标定、艇体几何或惯量。这些变化可能改变plant，须各自测量、版本化并重新取得数据。

本地相关回归187项通过；独立源码包重克隆后同187项通过。新增源码输出隔离回归确保专用`tmp/phase8_3/`结果不会阻止第二次运行，其他未审查文件和源码变更仍会被clean-source gate拒绝。测试与包身份见[包证据](evidence/phase8_3/runtime-package-20260912-r2/package.json)。这些均不算Isaac验收。

## 4. 下一步如何接近并超过persistence

1. **先测控制合同。** 服务器首次仅base cold、seed8201、恒定0.1动作的trace-on/off，各32区间，共64区间；通过逐状态、时钟、PWM、执行器和加载源码验收后，再推进base/uuv6/uuv4矩阵。当前服务器由用户确认离线，未启动仿真。具体预算、命令和停止条件见[运行手册](phase8_3_trace_runbook.md)。
2. **在相同轨迹上比较输入表征。** 比较末子步4D、按顺序的子步控制、可因果估计的推进器状态/推力或冲量，并分离平台参数作用。区间冲量的事后值只能作oracle诊断；用于规划的量必须可由当前状态及候选控制序列预测，不能偷看未来子步。
3. **再做一个fresh小规模辨识试验。** 保留可验证的运动学，动力学优先比较受约束的增量线性/LPV或物理条件化模型。分构型作为诊断对照。检查PWM有效激励覆盖、饱和、死区和不同频率访问状态；不能仅增加episode数量或任意加大幅值。
4. **以误差和递推稳定性共同决定继续。** 在预先固定的、完整episode分离的数据上，对同一预测任务报告一步、多个固定/滑动起点短时及完整递推；分构型、激励家族、活动区间逐项比较persistence。精确定义“接近”的非劣界限及所需运动通道提升，须在fresh结果揭盲前写入8.4 pilot合同。存活但所有指标更差，仍是NO_GO；MPC可用还需控制敏感性、约束和闭环验证。

当前判断：**支持先修复输入/状态的可辨识性，并核实构型物理语义；不支持“单构型已好，所以只需换共享模型”或“修控制链一定能打败persistence”。** 8.3仍未关闭，8.4条件性，Phase9继续阻塞。原Phase8.2的VERIFIED/NO_SELECTION和全部正式结果保持冻结。
