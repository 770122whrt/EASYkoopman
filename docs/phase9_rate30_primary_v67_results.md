| base俯仰 | 综合跟踪误差降低**18.535%**；深度RMSE从2.785mm降至1.328mm，姿态RMSE从.018512降至.017245rad；MPC接管14次 | 命令变化量1.821倍、力矩平方积分3.871倍、力平方积分.810倍 |

| asymmetric其余、uuv4 | 按首次失败停止条件未运行 | CPU READY不能代替实际闭环结果 |

四个完整r3案例均通过服务器物理/因果验收与本地独立重放；指标由回传原始轨迹重算。只对完整匹配配对判断收益，失败前缀不作效果对照。[独立复核](evidence/phase9/rate30-primary-v67-20260921/r3/review.json)

这支持“当前Koopman-MPC接入在部分base场景有收益”；不能据此声称跨构型普遍有效、长期稳定、统计显著或独特Koopman表示优势。控制代价增加必须与误差改善共同报告。

## 修复了什么延迟

r2反馈臂完整完成，MPC臂在第145个物理步停止：该周期284.311ms，决策1.776ms，同段记录到generation-2 GC耗时270.459ms。回执计算截止被触发，实际已发生的部分历史保留。

r3唯一控制段策略调整是：进入有界短episode之前执行GC，控制段内暂缓自动回收，退出/异常时恢复；RSS增长仍限64MiB。反馈/MPC均如此，不放宽10ms反馈、100ms求解或33.333ms周期门。两项GC生命周期回归通过，另9项相关部署/比较检查通过。

- 两次完整反馈轨迹的命令与状态最大差均0；峰值周期从469.007ms降至72.813ms。本次p50仍约47.7ms，p95没有改善，不能称整体延迟问题已解决。
- MPC新运行在原失败前145个物理步的命令/状态最大差均0，随后完成全部240步；峰值57.032ms。GC已恢复，反馈/MPC RSS增量约6.8MiB。
- 新MPC周期p50=46.792ms、p95=49.633ms，59个稳态周期全部超过33.333ms。包含实际物理推进、观测与完整审计；这仍是仿真效果证据。不得从CPU求解快或取消GC暂停推断完整实时系统合格。

## asymmetric失败在哪里

直接触发量已查清：滚转角速度`p=1.502304 rad/s`，超过该构型由冻结fit建立的支持上限`1.472868 rad/s`。当时总角速度1.607513rad/s，仍低于3rad/s物理安全限；接触/离地筛查通过，船体最低间隙约5.193m。

本次是**零转速冷启动早期的滚转支持范围越界**，不是旧记录中约1.6秒的偏航安全限事件。MPC请求数为0，不能据此判定Koopman预测或MPC控制失败。

已见到的机制线索：该构型浮心横向偏置为.05/.05m，惯量尤其滚转轴较小；静态逆求解准备的首命令并不能让零转速执行器瞬间达到静态力矩。实际记录显示转速与力矩尚在建立，第三个宏区间的反馈还受到slew限制。**直接停止原因已确认，哪种启动策略能避免越界仍待验证**，不把这一推断包装为已修复。

[实际状态、支持边界及力矩记录](evidence/phase9/rate30-primary-v67-20260921/asymmetric-startup-diagnosis.json)。原阈值保留，没有因仅超出约2%而扩大fit盒。

## 下一步顺序

1. 先补冷启动取证：用同一初态比较“立即跟踪目标”和“先建立配平再跟踪”的实际输入需求、执行器建立过程及预测支持范围。先做冻结模型/机械模型的有界离线诊断；模型预测结果只作诊断。
2. 决定是否需要明确的启动获取阶段。若采用，必须保留全部实际冷启动轨迹与执行器历史，按统一规则用于所有构型；分别报告启动时间/误差和后续跟踪，不将预热后reset或跳过失败段当作成功。学习控制只在已有支持范围内接管。
3. 启动阶段通过原物理与支持要求后，重新固定asymmetric匹配实验，再继续uuv4。若保持原零转速与命令限制时无法进入支持范围，就如实记录该合同不适用，另行设计数据覆盖；不逐构型手调来隐藏失败。
4. 把周期耗时分解到物理推进、观测/审计和控制计算，再选择降低开销的实现；现阶段不能承诺CPU/GPU某一项加速就达到30Hz。

Phase9继续；8.4保持关闭。模型表示/参数收益、八构型普遍泛化、在线适应与Agent收益仍是独立后续问题。
