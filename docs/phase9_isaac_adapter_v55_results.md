# Phase 9 实际执行确认接口 v55

新增[Isaac执行桥接](../workflows/isaac_execution_v55.py)，本地29项新合同测试、包含它们的205项相关测试通过。八构型分别通过两个控制区间的调用顺序检查；它们使用原控制分配与执行器代码、归档DirectRLEnv物理循环，但船体与传感读回为CPU fixture。没有启动Isaac，不是八构型真实闭环通过。

接口在一个观测到的reset后读取状态、后端位姿/速度、零转速与零执行器时钟，再绑定同一episode/reset账本。绑定前再次读回，拒绝过期reset。每次发令核对实际配置、mask、控制命令、PWM映射、子步序号与token；只在物理完成边界进行ack。

源码检查发现计数器`_sim_step_counter`在apply前递增：它单独不能证明physics完成。测试直接提取SHA核验过的服务器归档循环，桥接以回调位置、计数器和scene时间戳共同核对。初版假设错误的反例及其输出完整保留。

| 情况 | 行为 |
|---|---|
| 第一子步完成后接触、越域、接触读取失败/过期 | 保留已经确认发生的子步；拒绝第二次apply |
| 物理步骤不明、时钟/序号跳变、命令或PWM不符 | 停止；不生成猜测ack，不自动重发 |
| 意外reset | 先确认可证已发生的pending步，然后在reset清除状态前停止 |
| 同一dispatch重复pre，或绕过协调器env.step | 拒绝额外发令 |
| 准备期间reset快照过期 | 绑定前重新读回并拒绝 |

本地测试时使用诊断域、合成时钟和静态船体读回；没有以这些测试评价模型误差、跟踪收益或实时性。接口记录边界读回+决策+env.step+确认的完整墙钟，不自动把记录提升为16.67ms周期通过。实际环境的配置、机械参数、接触传感器绑定与完整周期验收仍由后续collector负责。
