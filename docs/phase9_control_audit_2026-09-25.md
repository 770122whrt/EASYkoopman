# 当前控制链路与结果独立审核

2026-09-25。范围：v77/v78实际控制实现、v78四构型2秒结果，以及现有结论的证据边界。一个独立subagent审查控制与模型代码；主agent独立从回传原始轨迹重算结果。不改控制器、不训练、不新增服务器实验。

**总判断：已建立可工作的连续MPC闭环和可核验的短任务对照；控制效果尚未稳定超过反馈。当前投影分支不能承担“独特Koopman表示带来收益”的证明，主要缺口已从链路打通转向模型归因与控制性能。**

## 2. 最大研究缺口：学了什么，实际用了什么

[identify_sparse_world_v30.py](../workflows/identify_sparse_world_v30.py)第83–92行先拟合完整提升矩阵，再用`core_matrix(D,Q)`覆盖速度列`matrix[:,10:16]`。

[prepared_projected_v40.py](../koopman/prepared_projected_v40.py)第92行的实际预测只读取这6列；[continuous_prediction_v76.py](../koopman/continuous_prediction_v76.py)第63行的优化器符号预测同样只读取这6列。姿态和z随后通过几何积分更新，下一步重新构造特征。

因此：数据确实参与了D/Q参数辨识，不应说“完全没有学习”；但自由拟合的其余提升矩阵列没有通过当前控制路径贡献预测。当前读出与同参数辨识物理方程等价。

[physical_control_v76.py](../koopman/physical_control_v76.py)第19–25行明确区分：`identified=True`使用冻结D/Q；实际名义对照使用D=0、Q=1。两者保留同构型质量、惯量、浮力等已知信息。这是合理的“名义参数—辨识参数”工程对照，却不是隔离Koopman表示优势的充分对照。

**优先级高：这是实验与研究目标之间的缺口，不是命令执行bug。** 应核实/设计真正使用学习提升动力学的预测路径，并增加同数据辨识物理对照；不能靠继续调当前等价分支来证明独特表示收益，也不能由其负结果否定整个Koopman路线。

## 3. 控制链路确认

三臂详图和变量定义见[控制链说明](phase9_control_chain_contract.md)。本次审核确认：

- 外部反馈是PD加重力/浮力/恢复力矩补偿，没有积分项；不是persistence，也不是原EasyUUV级联PID的原样对照。
- MPC与反馈都在TAM前接入。四维命令是归一化虚拟通道，不是角度或直接的物理wrench；物理目标wrench是反馈内部中间量。
- 当前11维状态为世界z、wxyz姿态、机体线速度/角速度；执行器记忆从已核对的零转速开始，仅由已确认实际命令递推。
- 每个模拟控制区间1/30秒，包含4个1/120秒物理子步。首个区间使用共同启动反馈，随后每个MPC案例有59次决策。
- 连续优化结果需要经float32分配、执行器递推与预测约束复核。无可行序列则停止；局部求解未找到序列不等于物理不可控。
- 求解期间仿真暂停。当前可评估控制效果，不能声称实时时延合格或实机部署完成。

关键入口：[reliable_runtime_v77.py](../koopman/reliable_runtime_v77.py)第30–61行、[continuous_mpc_v76.py](../koopman/continuous_mpc_v76.py)、[rate30_v67.py](../koopman/rate30_v67.py)、[control_v67.py](../easyuuv_nc/control_v67.py)、[command_state_v39.py](../koopman/command_state_v39.py)。

## 5. 问题按证据强弱区分

### 高优先级：确定存在的方法缺口

1. **表示贡献没有被实验隔离。** 当前投影读出与辨识物理等价，结论见第2节。
2. **独立效果验证不足。** 单个目标、初态、seed、2秒开发任务；uuv4又参与过调参。应在冻结设置后使用独立任务/初态及更长时间验证。

### 中优先级：确定的接口/验收边界，但尚非已证实运行bug

3. **内部参照过于简化。** `reliable_runtime_v77.py:45`用`np.tile`把当前反馈命令保持20步；实际反馈每步随状态更新。优化器胜过该参照并不保证胜过真实反馈。这种实现本身不使MPC无效，也不能单凭差异断言它是负收益根因。应单因素加入因果反馈预演，再比较实际闭环。
4. **选择规则的独立验收仍可加强。** `reliable_mpc_v77.py:150–184`在代码中对可行保留序列和求解结果按重算代价取最小。`validate_reliable_v77.py:128–134`独立重放选中序列及其代价，但未穷尽重算全部held/shifted备选并证明最终确为它们中最低代价。当前是验收覆盖边界，不是已发现选错。宜补全备选代价复算与篡改拒绝检查。

### 仍待定位，不能直接归为Koopman失败

5. 局部优化、预测时域、末端条件、完整时域模型误差都可能影响结果；已执行首个控制区间预测接近，不足以证明未来0.667秒均准确。
6. 求解中位数约7.6–21.8秒，明显未达到实时；但用户已将速度后置，不应在效果未厘清时只追求加速或换GPU。

## 6. 本次局部检查与推荐顺序

主agent运行`test_physical_control_v76.py`、`test_reliable_runtime_v77.py`、`test_reliable_mpc_v77.py`：**16 passed，1 skipped**。本地没有CasADi，包含符号模型对照的测试文件跳过；通过项是局部控制/选择契约，不是新物理效果证据。

Subagent另一次局部测试调用未取得终态和退出码，不计入通过证据；收尾按原命令精确核查后，确认该测试进程已不在运行。

另运行不依赖CasADi的NumPy比较：8种构型、每种8个合成状态、两种物理模型设定；辨识物理对投影读出、名义物理对直接已知方程，最大绝对差`9.99e-16`，容差`1e-11`。这是数值实现等价性检查，不是新增真实环境验证。

建议顺序：

1. 明确当前版本是“结构化辨识模型MPC”，保留它作为可工作的基准，避免错归因。
2. 在冻结模型/目标/时域下，验证因果反馈预演，并补选择验收；先检查现有负例与uuv4正例是否改善/退化，不假定必有改善。
3. 同步明确真正学习提升动力学的输入、读出、多步传播接口；安排同一MPC下“名义物理、同数据辨识物理、学习提升模型”的模型消融，外加反馈控制对照。不要混合改模型与改求解器后一次性归因。
4. 有可复现短任务效果后，冻结版本做独立初态/任务、长时和其余构型测试，再解决实时性与Agent贡献。

本审核不要求废弃现有工程，也不认可“Koopman已经有效/已经无效”的二选一结论。明确答案是：**控制链路已可工作，短任务结果可靠但总体效果不足；Koopman独特收益的关键验证仍未完成。**
