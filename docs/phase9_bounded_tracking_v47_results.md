# Phase 9：受限跟踪提案通过本地检查，闭环仍待验证

2026-09-20。新回退v47在八构型的120次固定请求中均生成合法提案，完整耗时1.53–7.86ms；39项针对性合同包含在198项通过的相关测试中。**这只允许继续准备运行接口，不能称为控制性能、稳定性或实时系统通过。** 旧v46的NO_GO及其来源归档保持。

## 修正了什么

[新实现](../koopman/bounded_feedback_v47.py)将两项不同要求分开：

1. 完整静态逆解必须满足原始需求及原物理残差、未裁剪PWM和死区门。固定几何伪逆在READY前准备，运行以原PWM曲线反演建立种子，再作至多4轮局部精化；没有把慢v31多分支逆解放进控制周期。
2. 实际命令用一个公共插值比例满足0.01变化率和原fit命令范围，随后独立重算原始PWM、mask及死区余量。静态逆解可以作为内部参考超过fit盒；实际命令不能因此越界，也不能把该参考交给学习模型作范围外预测。

深度/姿态需求、完整逆解及实际受限命令的残差分别保存。`target_attained`仅表示静态源wrench达到原残差要求，**不表示深度/姿态到达参考，也不表示实际转速已达到稳态**。`tracking_limited`保留未达到的原目标残差，不将实际推力重新命名为目标。限幅比例为0时明确记录零进展；不能据此声称恢复成功。

几何种子倍率为1/1.0002/0.9998；限制器比例尝试1/0.999/0.99/0.9/0.5。所有候选非法就不给命令，不回填未检查的旧命令。内部预算仍为10ms，物理残差、PWM余量、死区余量、控制增益和变化率未放宽。

## 路线判断与下一步

“因果预测接口 → 有界控制 → 匹配闭环 → 环境适应 → Agent增量”仍合理。v45求解器的本地计算门保持；本轮补上回退需求和约束冲突的表达。停止继续孤立的预测提速，优先补齐实际运行所需的三项：

1. 一次性启动许可及唯一发令接口。当前`prepare_startup`只是提案；需绑定新episode、真实零转速reset和空历史，在第一次真实发令确认时消费许可。worker重启、重复请求或换reference不能重新获得许可。
2. 原子捕获真实状态/命令历史，逐物理子步确认后才推进执行器估计。重复、乱序、丢失或不确定的确认须拒绝/停止，不能把试算状态写回。两子步hold、上一真实命令及历史版本一起核对。
3. 非阻塞worker、固定队列上限、承诺前缀/激活时间及当前状态偏差核验。独立验证worker阻塞时低层仍可返回；100ms协作式截止不能充当进程隔离证据。完整周期还须包含这些新增开销。

42次受限跟踪以及内部逆解越fit范围揭示了后续风险：合法命令未必足以在支持域内恢复目标。运行接口必须明确持续无进展/状态越域的停止条件；若实际闭环失败，应保留失败并判断是否需要新的操作范围标定/数据，不能直接扩大fit盒追求通过。

跨构型比较还要单列信息访问范围：本轮八构型使用pooled模型的训练支持域，不是未见构型控制证据。LOCO模型不得借用heldout构型的fit盒；独立物理操作域及其来源须在后续协议中预先规定。

完成上述本地接口与完整耗时检查后，再准备单独资源范围的服务器冷启动及匹配闭环提案。比较名义物理、辨识物理、当前投影模型使用同一控制器；Legacy/S-Surface另作控制器对照。相同D/Q代数等价不能成为独特Koopman增益，Agent贡献仍需后续独立消融。

本轮新增已测60.967秒，本地阶段累计299.256/1200秒、剩余900.744秒；新证据约1.95MB，128MiB本地输出上限保持。未启动服务器、安装依赖、拟合模型或访问正式test；Phase8.4收尾、handoff与已关闭预算的哈希保持。
