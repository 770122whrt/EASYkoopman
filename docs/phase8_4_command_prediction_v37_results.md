# 4D因果命令预测接口已通过本地等价核查

2026-09-13。新接口接收当前状态、完整已发命令历史及未来计划的4D pre-TAM命令，按本构型的mask/TAM/PWM和N维执行器状态推进两个物理子步。八构型固定fit起点的64个对照子步与旧路径**状态、PWM、转速、作用加速度和时钟差异全为0**。两组命令分支执行后重新计算原分支，结果逐数组完全相同。

这是接口等价与历史继承证据，不是新的模型精度验证、MPC控制结果或Agentic收益。

## 补齐的接口

- 分支之间不共享控制器、转速或时钟状态；从明确零转速起点的完整历史恢复执行器。
- 4D命令保持两个物理子步，但估计转速和实际作用加速度分别更新，不把末子步值误当整个区间输入。
- 实际质量、惯量及其余context沿用已接收对象，经过mask/TAM得到正确数量的推进器信号。
- 不接收未来真实状态、未来实测wrench或转速；历史长度、控制边界索引、命令范围与context不一致会拒绝。历史长度检查不等于认证历史内容，调用者仍需数据/运行来源验收。
- 中途出现非有限或无效预测返回明确失败位置与完整子步数，不能把部分输出标成成功。数值界不替代未来控制器的安全边界。

当前使用冻结v30预测器的已知运动学和结构化速度输出，模型没有重新拟合。这个接口并未创造新的Koopman算法或消除已知的参数模型等价性。

## 真实读回暴露并修复了一个准入问题

v36的42个相关测试通过，但真实fit核查到uuv6时停止：我把实际质量与名义float32质量写成严格相等。uuv6与uuv6_angled分别相差±1.9073486e-6 kg。这个拒绝发生在接口准入，四个此前构型逐子步差0；不是新模型发散或再次套用base。

两个实际值都严格等于float32的质量倒数往返。NVIDIA公开PhysX实现将质量存为inverseMass、读取时再取倒数，与该解释一致；公开main不代表已证明部署二进制版本完全相同。[官方源码](https://raw.githubusercontent.com/NVIDIA-Omniverse/PhysX/main/physx/source/physx/src/NpRigidBodyTemplate.h)。

v37只允许名义float32值或这一明确的倒数往返值，其余任意近似值仍拒绝。**用于wrench/mass及传给预测器的始终是实际读回质量**。未放宽旧数据或精度门；原v36失败源码、native1和四例结果保留。[修复依据与精确数值](phase8_4_command_mass_admission_v37.md)。

八构型各取原fit第一条PRBS，在控制起点128，让旧policy_forecast根据自身预测状态产生4个命令；新接口接受相同命令，从相同历史和初态计算。再各做±.01深度命令的两组分支并重复原分支。新接口共256个预测子步，其中64个与旧反馈路径比较。没有新增真实Isaac子步。

46项相关测试通过。八例核查16.516秒，native0。[独立核验](evidence/phase8_4/command-prediction-v37-20260913/audit.json)从命令历史重新展开每个子步的执行器和状态更新，差异均0；核对492源码、46输入、旧v36的13项失败/部分证据及旧145项正式证据。修复前四例与修复后逐数组相同；forecast函数AST完全相同，仅质量准入改变。独立审核8.281秒，native0。

v36/v37共用原300秒source额度：包括原60秒保守测试、失败核查10.578秒、原因调查30秒、新测试45秒、新核查16.516秒及审核8.281秒，共170.375秒。混合了保守额度和实测运行时间，不是CPU实测合计。原服务器与分析历史账本继续保留，未因修复编号重置。
