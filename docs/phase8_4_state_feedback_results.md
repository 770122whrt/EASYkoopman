# asymmetric 姿态补偿修复与八构型校准

2026-09-13。**asymmetric固定初态配平失稳已在本次限定测试中修复；八构型全部通过4.267秒冷启动配平和5.333秒脉冲测试，并完成本地独立拉回验收。** 共16条完整轨迹、9,216个物理子步。物理参数、零转速初始化和原停止门不变；没有训练新模型或放行Koopman/MPC/Agentic结果。

## 原因与修复

原先的配平只抵消单位姿态下的恢复力矩。asymmetric有横向浮心偏置，推进器又需要时间从零建立推力；船体开始转动后，恢复力矩随姿态改变，固定偏置无法继续平衡，约1.6秒达到角速度上限。这个问题不需要通过改质量、浮心或放宽角速度门来掩盖。

恢复力矩随姿态改变本身是这套物理模型的正常行为；需要补齐的是采集控制器的状态反馈与可实现输入分配。此次“修复”针对原有采集方式的能力缺口，不把正常物理耦合当成应该删掉的仿真错误。

新采集控制在每个1/60秒控制边界读取当前状态，计算 `−r_COB × (rho V g R(q)ᵀ e_z)`，加上有界姿态/角速度反馈，再经过原pre-TAM接口、PWM曲线和一阶推进器滞后。每个控制间隔的两个物理子步、所有物理参数和零转速初始化均保持原值。八构型采用同一规则，按真实惯量、浮心与可控轴参数化；控制器看到的当前状态和每条实际命令都被记录。

**r14 asymmetric 配平结果：** 完成512个物理子步、4.267秒；全程最大角速度1.5592 rad/s，末尾64子步最大角速度0.003075 rad/s、最大倾角0.0391°。没有接触或未解释平移冲量。该结果支持本次固定起点的启动修复，不等于任意初态、长时悬停或Koopman控制收益。[八构型配平验收](evidence/phase8_4/server-feedback-20260913-r14/trim/acceptance.json)。

## 校准中进一步补出的缺口

1. **PWM死区重建的精度语义不一致。** 实际float32的0.02，在转成float64后是0.01999999955。旧离线重建把它误判成死区内，运行时则判为有效边界。r12的新反馈轨迹命中该边界，使转速重建误差达到17.317；修正比较语义后，同一原始轨迹的最大误差为4.57×10⁻⁵，原1e-3门限不变。r12原始批次失败状态保留，修正回放只作诊断。[诊断](evidence/phase8_4/server-feedback-20260913-r12/closeout/fixed-replay-audit.json)。
2. **失败码会被SDK退出过程覆盖。** 仅在清理后重新抛出异常并不够。新父进程不启动SimulationApp，分别保留底层退出码、原始报告哈希和对外退出码。r14七次真实分配失败均记录child native=0、guarded collector=1，未被误认成成功。[r14脉冲验收](evidence/phase8_4/server-feedback-20260913-r14/excitation/acceptance.json)。
3. **静态求逆器把局部停止误当成没有可行指令。** r14八条配平通过，但脉冲仅heavy完整通过，其余七条在发送下一条指令前被分配误差门停止。对失败目标的源码反例检查发现，某一死区轴会阻止完整Newton步，多个PWM边界也可能需要同时切换。long_body的限定753,571点搜索找到872个满足原门限的指令，说明这个目标不能被解释成物理上不可实现。新的有界分组修正和局部搜索已为七个失败目标找到实际可行指令；仍需新运行检验后续控制目标。[原失败目标](evidence/phase8_4/server-feedback-20260913-r14/closeout/allocation-failure-targets.json)、[long_body源码见证](evidence/phase8_4/server-feedback-20260913-r14/closeout/long-body-local-grid.json)、[七个修正反例](evidence/phase8_4/server-feedback-20260913-r14/closeout/source-inverse-refinement-final.json)。

本次还主动撤回了额外加入的高度PD：它在base上要求约0.572 N的纯升沉力，而该通道的死区输出从0跳至约1.329 N。当前保留已校准升沉工作点和物理脉冲，重点修复姿态变化；不宣称精确高度保持。这是本次设计中发现并纠正的问题，不是把新增问题归给原始代码。

旧24条fit协议的源码输入没有命中此次0.02边界，旧/新重建差为0。因此这个新发现不能解释原来的全部模型失败；旧模型错误耦合、long_body外推与数据覆盖问题仍需处理。该检查只读取fit协议生成的命令，未读取validation/test轨迹、没有重拟合旧模型。[影响检查](evidence/phase8_4/server-feedback-20260913-r14/closeout/old-fit-deadzone-impact.json)。

第二类PWM问题发生在r15：CPU和GPU计算出的PWM最多仅差9.69×10⁻⁸，却在四个子步分别位于0.02死区的两侧，使基于CPU指令重建的转速误差达到5.166。以实际已发PWM重新递推，误差仅1.34×10⁻⁵，说明原因是命令映射的分支不一致，不是初始转速缺失。r16增加大于2×10⁻⁶的边界距离要求，并用实际源码的有界批量候选搜索处理后续long_body目标；原物理误差门不变。[CPU/GPU诊断](evidence/phase8_4/server-feedback-20260913-r15/closeout/cpu-gpu-boundary-audit.json)。

有界求逆搜索是当前采集工具，尚未证明每次都能在1/60秒内完成，也不保证任意状态目标都有可行解。仿真按固定物理步长运行，计算耗时另外计入采集预算；进入实时MPC之前仍需单独检查分配算法的耗时和约束。

## 下一步

后续按下列顺序推进：

1. 冻结独立的新fit/validation角色、种子、持续时间及外部激励。先以已验证的短时域为边界，不直接恢复旧512区间矩阵；校准记录继续保持calibration身份，不改名训练。
2. 补新数据适配器：逐子步输出当前状态、实际已发指令、由完整命令历史重建的推进器状态/作用wrench和下一状态。两子步顺序、float32死区语义、初始化、真实构型参数、控制器版本全部绑定；未来状态及转子真值只用于核对，不进入因果输入。
3. 先审查实际作用力/力矩、状态覆盖、各轴信号变化与输入/状态共线性。反馈会让输入与状态相关，短配平稳定不保证可辨识性，不能直接扩大采样并期待模型变好。训练标签使用实际发送控制及其因果作用，不把未实现的理想目标力矩当作真实输入。
4. 再实现受物理结构约束的Koopman候选，分别比较persistence、线性诊断、已知物理基线与新增学习项。persistence在状态预测中直接令下一步等于当前状态，小时间步下本来就很强；应同时检查相同信息下的单步误差和多步递推，并把同构型新轨迹、未见构型两种泛化分开报告。已知物理补偿带来的稳定性不能记成Koopman收益。新的独立预测证据通过以后，才继续MPC与Agentic消融。
