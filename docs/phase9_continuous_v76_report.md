# Phase 9 连续优化与匹配模型对照 v76

2026-09-24，本轮用户授权的首组连续优化开发实验已结束：四构型×三臂共12个主案例均尝试，8个完整通过独立验收、4个失败停止。连续控制序列优化已接入，固定方向候选不再是新分支的搜索方法；模型冻结、零训练、控制频率性能后置。**结果支持搜索能力改进，但尚不支持稳定的跨构型控制收益或独特Koopman表示收益。Phase9仍开放。**

## 实现和已获得证据

- `continuous_prediction_v76` 将冻结投影模型与执行器记忆转为可微表达；连续数值代理的解仍经过原 float32/TAM/PWM/执行器/状态预测链复核。
- `continuous_mpc_v76` 使用 CasADi/IPOPT 联合求解多轴、多时段序列，不枚举固定方向候选。允许基线不可行时独立恢复，不声称非凸全局最优。旧 v67 源码与失败保持冻结。
- 新服务器定向套件46项通过，另2项原目标函数等价检查通过，共48项；本地15项执行/几何/验收反例通过，4项因本地缺CasADi跳过、已在服务器实际运行。属于定向实现证据，不称全仓库测试通过。
- 六条历史轨迹的最终r3离线回放完成，共24次连续求解。uuv4 与 uuv4_angled 均找到精确复核可行的恢复序列，保留原四个30Hz区间前缀时亦可行。uuv4_angled旧七候选全失败不能证明模型下无解。第一次回放的base输入误选为较短60Hz记录，索引失败保留，第二次替换为匹配30Hz成功记录；最终r3使用修复后的统一数值表达。
- 名义物理模型直接积分已知方程（附加辨识阻尼D=0、二次阻力倍率Q=1）；辨识物理模型直接使用冻结D/Q，不重新拟合。后者与当前投影模型的速度读出数值等价，不能把它们的等价结果包装为独立Koopman表示收益。

## 本轮闭环协议

最多12个研究案例：`base / uuv4 / long_body / uuv6` × `feedback / projected_koopman / nominal_physics`。依次完成base匹配三臂，再扩展构型。每例60个30Hz控制区间、240个120Hz物理子步（2秒），共同seed19760；z=5.5、姿态水平、零速度与零执行器起步；目标pitch0.04rad、z=5.5。

三臂共享机械参数、实际静态初始化、本地立方体地面、TAM、执行器、输入约束、支持域与实际安全检查。两个MPC共享10区间时域、目标权重、求解器和精确验收；只替换预测模型。反馈为现有PD加物理补偿，不称为PID。第一控制区间使用相同已验证启动命令；后续MPC每次求解再执行首个命令，求解时仿真不推进。未来实际反馈指令只用于离线诊断，不进入在线优化。

每次求解最多160次迭代、30秒CPU；完整决策上限60秒（非实时诊断）；单例墙钟540秒软停止、600秒外层终止。首组总墙钟上限90分钟、研究输出128MiB；不是旧v73额度续用。首次原生启动/接口错误停止队列以修复，保留失败，最多4次额外诊断启动。已定位单构型支持域/可行性失败可隔离后继续同任务其他对照，环境、执行回执、模型绑定异常全局停止。

开发修订：首个base MPC r1在4物理步后首次求解触发10秒CPU上限（墙钟5.135秒，64次迭代），无MPC指令发出。对同一真实状态的离线单因素诊断显示，原算法30秒CPU预算下约7.03秒墙钟完成160次迭代，返回精确可行、代价较低的序列；目标缩放无明显改善，精确Hessian更慢。按用户控制性能后置的范围，将自设诊断预算调整为30秒CPU，保留模型/权重/约束/迭代数。此时`Maximum_Iterations_Exceeded`不能表述为最优收敛，仅为独立复核可行且优于参照的有限迭代解。旧超时保留。

进一步单因素定位：平方范数≥0、单位旋转分量≤1等天然成立的界限，在静止附近形成零梯度活跃边界。移除优化表达中的冗余界限（不改变可行集合，实际状态检查全部保留）后，同一初态65次迭代`Solve_Succeeded`，末次对偶残差4.30e-9、内部原始残差7.94e-13。新增真实起步收敛回归先失败、修复后通过；服务器定向套件更新为46通过。本地独立验收器5项原始/篡改反例测试通过。

r2未修复冗余边界的完整base MPC已独立验收：分数0.224059，对照反馈0.233574，改善4.07%，小于原5%实质改善门。它保留为开发对照。当前r3统一采用上述数值修复进行正式的首组小范围比较，不能挑选r2/r3较好值作主结果。

求解未找到精确可行序列即停止本例；不扩大支持域、不强行忽略饱和/死区、不执行历史固定候选。保留真实触碰、净空、位移、角速度、状态支持域、确认回执和生命周期检查。实际越界不再发下一物理指令。

独立验收要求原生exit0、清理完成、240条已确认物理回执、每控制区间四次同指令、实际控制/PWM/执行器重放一致、状态与接触检查通过；完整真实轨迹本地拉回并校验hash后才称闭环完成。采集器写完文件本身不算验收成功。

记录分项深度/姿态RMSE、归一化跟踪分数、控制变化、失败/基线保留/优化激活与完整求解耗时。2秒单seed是开发机制证据，不能证明长期稳定、未见构型泛化或统计显著性；后续独立验证需另冻结更长任务和新初态。

## 首组结果

分数越低越好；改善百分比为`100×(反馈−MPC)/反馈`。失败案例不报告完整两秒收益。

| 构型 | 反馈分数 | 投影Koopman-MPC | 名义物理-MPC | 结论 |
|---|---:|---:|---:|---|
| base | 0.233574 | 0.226440（+3.05%） | 0.226201（+3.16%） | 两种MPC小幅改善；Koopman比名义物理略差0.11% |
| uuv4 | 0.213930 | 0.226316（−5.79%） | 0.219597（−2.65%） | 均完成，但总体变差；Koopman比名义物理差3.06% |
| long_body | 0.210121 | 0.30s停止：CPU上限 | 0.40s停止：CPU上限 | 无完整配对收益结论 |
| uuv6 | 0.210295 | 1.60s停止：CPU上限 | 0.767s停止：未找到精确可行解 | 无完整配对收益结论，另有明显控制问题 |

base的59次求解全部正常收敛，其中7次采用改进序列、52次保留代价更低的可行内部反馈参照；不能将59次都算优化控制收益。uuv4为46次优化、11次保留、2次恢复；姿态RMSE改善7.81%，但深度RMSE从1.693mm增至4.498mm，合并评分变差。base约3.1%的改善小于原5%实质改善参考门；单次短案例也不足以判定显著差异。

uuv6投影分支在超时前已表现不佳：1.6s处深度误差3.92cm，pitch为−0.00170rad，而目标为+0.04rad。只比较相同前1.6s的原始轨迹，其归一化分数约为反馈的3.73倍。因此不能把uuv6问题全部归为运行超时；即使解除超时，当前目标/时域/规划连续性仍需修复。这是失败部分轨迹的描述性诊断，不是完整案例验收或模型间正式收益比较。[部分轨迹诊断](evidence/phase9/continuous-v76-20260924/partial-diagnostics.json)。

## 模型形式审核

`validate_matrix`将控制使用的六个速度输出分量强制绑定到`core_matrix(D,Q)`；其余学习的提升矩阵输出未用于当前投影控制预测，姿态由已知物理积分更新。独立直接物理方程使用同一冻结D/Q时，与当前投影预测在代数上等价。八构型各100个合成状态的交叉实现最大差异1.12e-16；此为代数/数值一致性证据，不是800次物理实验。六条真实历史轨迹中，同参数物理与投影模型的离线解代价差异亦约1e-19。[数值审核记录](evidence/phase9/continuous-v76-20260924/representation-audit.json)。

因此，当前冻结模型与名义物理的差异是辨识参数收益问题，不能独立证明Koopman表示收益。若下一步目标是证明独特Koopman优势，需要让学习的提升动力学实际参与多步预测，并在相同数据预算下对照辨识物理模型；不能通过只调MPC权重或更换对照名称获得该结论。本轮不进行此类重训。

## 已定位的问题与仍需验证的归因

1. **搜索空间缺陷已修复。** 新接口联合优化完整连续序列；原固定候选漏解、基线不可行阻止恢复接纳的问题不再主导新分支。旧源码及旧结果保持冻结，不能写成旧实验自动转为成功。
2. **数值退化已部分修复。** 静止状态下天然成立的零梯度活跃约束导致迭代困难，去除冗余表达后真实起步回归正常收敛。非凸PWM分段/死区、支持约束、仅反馈初值和有限迭代仍会导致困难。
3. **long_body为求解超时失败。** Koopman和名义物理两臂分别运行36/48物理步后触发30秒CPU上限，停止在仿真时间0.30/0.40秒。已确认模型/机械绑定、执行回执、清理正常，失败求解时反馈参照仍精确可行；不能表述为模型证明不可行或物理失稳。队列每次停下审核后，保留该负结果并继续其他已授权对照，未重试、扩大预算或修改权重。当前严格超时停止规则不使用可行参照续跑，后续需把超时处置与收益评估分开验证。
4. **目标与评分存在差别。** MPC原目标对深度平方米和姿态弧度平方权重均1，另含末端、速度、输入及变化项；报告分数为`mean(depth_error²/0.02² + attitude_error²/0.04²)`，其相对深度权重是4。这提供uuv4“姿态更好、深度更差、总分更差”的设计解释；0.333秒时域和末端速度惩罚也可能影响行为，尚未逐项消融证明主因。本轮没有为了得正结果中途修改目标。
5. **不能笼统归因跨构型预测失准。** base/uuv4已执行相同首个命令后的4物理步预测，深度最大误差低于1e−6m，姿态角最大误差约2.3e−5rad。此为短时同输入检验，不证明整个时域和未见状态都准确；也不能用反事实未来指令与实际重规划轨迹直接计算预测误差。
6. **独特表示收益尚未建立。** 当前投影控制映射与同参数物理模型等价；名义物理与投影分支的差异仅支持辨识参数及其与有限迭代求解的交互分析。用名称“Koopman”替代这个检验会夸大创新。

7. **uuv6物理-MPC的局部搜索失败已定位到初值。** 停止时当前状态仍合格，保持当前反馈的预测在第34个未来物理步触及`up_body_x`下界（预测−0.046564，下界−0.046475）；160次迭代返回序列仍有约8.53e−4约束残差。移到独立进程后，保持反馈初值仍失败；只把初值/可行参照换成因果的上一计划平移，59次迭代、2.57秒收敛，原模型/约束下残差0、精确复核通过。目标函数、机械模型和支持域均不变，证明该起点并非无可行方案。这是有限预算局部优化的初始化缺陷；热启动需接入新运行版本并重做配对，不能改写r3失败。[原初值](evidence/phase9/continuous-v76-20260924/.v76-feasibility-uuv6-held/summary.json)、[平移初值](evidence/phase9/continuous-v76-20260924/.v76-feasibility-uuv6/summary.json)。

## 下一步建议

补充超时归因：保持模型、状态、反馈初值、160迭代和30秒CPU预算不变，两个long_body失败起点移出Isaac进程后，分别用8.69/8.51秒CPU返回精确可行且优于参照的序列（都达到160迭代上限，仍非收敛最优）。见[独立进程重放](evidence/phase9/continuous-v76-20260924/.v76-stopped-r1/summary.json)。Ipopt在Unix上的CPU计时使用进程级`getrusage(RUSAGE_SELF)`，会计入同进程其他线程；据此推断Isaac后台线程消耗求解CPU预算，是现场约14秒墙钟触发30秒CPU上限的重要原因。该推断有源码机制和重放支持，尚未通过独立求解进程的新闭环验证。[Ipopt计时实现](https://github.com/coin-or/Ipopt/blob/stable/3.14/src/Common/IpUtils.cpp)。

uuv6投影分支的超时状态也在独立进程9.50秒返回精确可行改进序列，仍是160迭代非收敛结果。[uuv6超时重放](evidence/phase9/continuous-v76-20260924/.v76-stopped-uuv6/summary.json)。这恢复了该状态的可行求解证据，不能消除之前1.6s已经发生的控制负收益。

离线诊断初次写入采集根目录后，旧队列把该`summary.json`列表当作案例字典，导致最后一例在启动前报错。该记录保留；诊断目录移到既有离线工作区后继续，没有额外物理启动。后续队列应以显式案例清单/类型校验汇总费用，而不是扫描任意同名summary。

首先完成控制问题本身：用当前冻结模型，单独验证超时后经最新状态精确复核的可行参照/平移计划与进程隔离，再把任务评分、无量纲权重、时域和末端条件分开消融。保持安全域不变，失败与回退都计入完成率；不回到固定方向搜索。之后冻结较长任务、新初态及多seed，验证超调、稳定时间和完整任务收益，再决定第二组四构型。

为回答独特Koopman收益，另立模型接口实验：让学习的提升动力学实际决定预测，明确外部输入、执行器状态与机械描述符；先审查现有矩阵未使用部分能否组成可控、稳定、无未来信息泄漏的多步预测器。若不能，才设计新的辨识/训练，不在本轮偷偷重训。对照必须包含名义物理、相同数据辨识物理和真正使用学习提升动力学的模型，三者使用同一MPC、任务、约束、调参和数据预算。

该建议延续Koopman-UUV目标；当前模型形式的限制是需要修正的实现/识别边界，不是证明Koopman理论无效。30Hz优化、第二组覆盖、未见构型、自适应和Agent增量仍为后续，Phase9不关闭。
