## 3. 物理模型与Koopman分离到了哪里

[model_separation_v79.py](../koopman/model_separation_v79.py)明确区分三个可调用预测器：

| 名称 | 实质 | 当前用途 |
|---|---|---|
| `nominal_physics` | 已知物理方程，D=0/Q=1 | 名义物理基线 |
| `identified_physics` | 同方程，使用冻结数据辨识D/Q | 参数学习对照 |
| `structured_projected` | 当前冻结投影读出 | 历史可用模型，明确等价于上一行 |
| `frozen_full_lift_probe` | 冻结完整提升矩阵自由递推、已知状态相关输入项、几何读出 | 只允许离线诊断，禁止冒充已准入控制模型 |

含糊的`koopman`名称不会自动映射成辨识物理。优化器中辨识物理和旧投影分支使用代数等价的符号表达，接口显式记录这种等价；这不是新增的独特学习模型。

12个相同起点、同一未来命令序列、80物理步的诊断中，辨识物理与结构化投影的最大逐坐标差为`5.55e-17`。此处使用记录的未来命令只作离线同输入模型诊断，不进入反馈预演或在线控制。

完整提升探针真正传播所有潜在观测量、不每步重新提升、不偷偷用物理积分替换学习的位姿。对12个起点，它都在第26–30个预测物理步触发旋转矩阵投影残差门，之前完成25–29步；约0.21–0.25秒，未完成所需80步。0.05是事前代码固定的旋转矩阵Frobenius投影残差诊断门，不是弧度误差，也不是旧正式精度门。未完成的预测不计算幸存者完整精度。

这是对原冻结算子的复核，不是新训练模型失败，更不否定全部Koopman方法。

## 4. 为什么不能直接恢复旧完整矩阵

此次重新追溯到了此前的明确负证据，修正“仿佛只需把其余矩阵列接上”的过度简化：

- [v33](phase8_4_controlled_lift_v33_results.md)：自由提升递推使二次阻力观测量离开物理关系，出现正功和发散；只修输入时序仍不足。
- [v34](phase8_4_state_projection_v34_results.md)：每步重新提升避免数值退出，但自由姿态读出的跨构型误差明显放大。
- [v35](phase8_4_kinematic_dictionary_v35_results.md)：补旋转运动学乘积仍未通过heldout门，因此当时有依据地保留解析运动学与结构化速度模型。

**建议的新模型方向：保留已知姿态/位置运动学，在速度动力学层引入真正数据学习的提升读出或残差，使其表达能力超出D/Q阻尼参数。** “使用全部矩阵列”并不是Koopman形式成立或有收益的必要条件；关键是学习部分确实影响预测、数学形式清楚，并有非等价的公平对照。

这一新动力学模型尚未拟合或接入MPC。本轮不扫描字典、不恢复已否决的自由位姿路线、不使用开发或正式test重训。下一阶段需单列模型身份、原fit数据分割、状态/输入映射、投影方式和独立验证；同数据辨识物理模型保留为必须的比较项。

## 5. 新发现：实际PWM检查缺口

24个旧MPC决策起点抽查：20个在本地重新检查通过；4个因本地重算PWM距离死区边界略小于`2e-6`被拒绝，不能包装成24/24完全通过。

进一步比较实际服务器回执与本地分配，uuv4/uuv6存在约`3e-8–4e-8`级差异，base/long_body无该差异。旧独立验收对重算计划执行严格PWM门，但实际PWM主要通过`1e-6`重建误差容差；没有对实际输出单独执行同一死区余量门。

新的直接回执检查发现：uuv6两臂各16个物理子步（各4个控制区间）的实际余量略低于`2e-6`，最小分别`1.99117e-6`、`1.98744e-6`。两臂实际死区分支均未因此改变。原v77验收记录保持原样，v78实际误差数字仍可复算；但不能再扩展声称这些记录满足新增的“直接检查实际PWM余量”条件。

已补充`audit_observed_pwm`及会拒绝这一反例的测试。[全部后端差异与回执检查](evidence/phase9/separation-v79-20260925/platform-boundary-receipts.json)，此前[纯平台比较](evidence/phase9/separation-v79-20260925/platform-boundary.json)保留。

后续应在原服务器上复核分配矩阵及CPU/GPU差异，再给求解端设置有依据的数值内缩裕量，并将实际回执门接入新验收。不得直接放宽`2e-6`门来消除红项；这也不是已经证明负收益来自PWM。
