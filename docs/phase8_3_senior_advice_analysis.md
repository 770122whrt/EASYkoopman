## 先把控制链讲清楚

当前这批数据的主要路径是：

```text
预设raw action激励（不读取轨迹）
  → 默认S-surface的action和action差分处理
  → 4D virtual control与mask
  → 当前构型的TAM / legacy mixer
  → PWM限幅、死区与非线性转速命令
  → N个推进器的一阶转速状态
  → 实际推进器wrench
  → AUV物理状态变化
```

一个control interval有两个physics子步。Bridge在整个interval结束后取最后的virtual control和wrench，再把它们与区间首尾状态配成一行。

这里要修正上一轮讨论的一个细节：默认采集并不是两个子步都根据新姿态误差重新闭环控制；外部action是预设激励，默认控制函数使用它及其差分。因此“每步只计算一次并hold”在本路径中主要改变D项的时间分布。若切换为SO(3)反馈或启用其他状态反馈，hold才同时涉及反馈更新频率的变化。不能仅凭名字叫S-surface/PID就混淆两种情况。

我们真正需要明确的是：模型输入代表“区间开始就知道且能够执行的命令”，还是“区间结束才记录到的结果”。这比把输入统一成4D、8D或6D本身更重要。

## 为什么不能直接解释NO_SELECTION

正式结果仍为 `VERIFIED + NO_SELECTION + model_handoff=false`。它表示冻结协议下没有候选获准进入下一阶段，不是模型家族理论被否定。

已有八折账本显示：conditional的384个候选记录中，378个是 `source_validation_rollout_failed`，6个是 `regularized_condition_above_limit`；全部未形成可选候选。pooled各折最后选中的都是identity，与相同设置的simple-linear等价。这里的384是跨折候选记录数，不是384次独立科学重复。

因此至少有四种可竞争的解释：

1. **时间输入缺失：** 模型没有看到首子步的控制贡献。
2. **状态缺失：** 当前proxy不能表达足够的执行器或控制历史。
3. **模型/递推问题：** 非线性或conditional模型可能短步还可用，长rollout才失败，也可能有更早的数值/实现失败。
4. **跨构型与数据问题：** pooled没有足够的平台条件，conditional描述或拟合结构不合适，或激励覆盖不支持识别。

它们可以同时存在。只修reset再看到分数变化，不能说明其他问题消失；同时改hold、memory、PCA和lift，即使改善也不知道哪个改动起作用。下一轮需要一次只改变一个因素。

原始raw action和固定参数原则上可能帮助推导未记录的首子步控制，因此“不可能从旧数据恢复任何信息”也过强。但推导值必须与实际trace对照，不能冒充历史测量，不能改写冻结数据或借旧test反复选新方案。

## 下一步的主线：先定位，再定接口，最后决定是否重采

### Phase 8.3：控制与辨识机制核查

这是当前新增并详细规划的阶段，三个计划依次回答不同问题：

1. **08.3-01 本地诊断准备：** 对一个固定source-only失败案例定位最早失败步和原因；准备默认控制路径、token、reset的本地fixture与只读trace入口。先不改变控制行为。
2. **08.3-02 有界Isaac trace：** 在base/uuv6/uuv4上核实真实加载源码、两子步调用与cold/warm reset影响。先证明加日志不改变轨迹，再测控制差异和执行器估计误差。服务器运行仍需具体就绪条件和启动授权。
3. **08.3-03 表示与接口决策：** 用同一trace做可部署表示的有限对照，区分模型失败与输入/状态缺口，选择一个接口并给出继续、停止或证据不足的决定。

**8.3的完成条件是把判断变得可信，不要求修完后Koopman一定变好。** 没有运行证据时可以交付明确的未完成/阻塞说明，但不能把缺证据写成完成，也不能用“没发现改善”宣布模型无效。

### Phase 8.4：条件触发的选定合同与新实验

8.4是占位的后续阶段，不是已获准执行的96段重采任务。只有8.3确定值得继续，才把它细化成可执行计划：先实现一种合同，做独立的新pilot；pilot支持收益后，才准备新D-23和正式采集/评价。

架构A（MPC直接输出bounded pre-TAM control）最接近已有Phase9目标，因此作为优先评审方向。架构B（MPC输出reference/raw action，保留内环）保留为对照；选择B需要明确改Phase9目标。架构C的子步表示可服务A或B，它不是必须另建一套MPC的理由。

memory优先评估由命令、TAM、非线性映射、dt和参数驱动的因果执行器估计。暂不预选8D padding或6D wrench-memory。前者需推进器几何语义，后者可能丢失对未来响应有影响的状态；两者均不能只凭维度宣布优越。

### Phase 9及以后：保留目标，补齐入口

Phase9仍以有界4D pre-TAM MPC为当前目标，明确模型输入、hold/子步时间语义、mask、TAM、限制器与实际执行一致。Legacy/S-surface通过并联仲裁保留，不能让两个控制器串行重复解释命令。8.2没有提供模型入口。

如果最终选择local-linear/per-config + fallback，需要记录科学问题变化，并验证它的闭环效果。现在的simple-linear同样没有胜过persistence，不能因它更简单就直接获准部署。Phase10–12继续等待前序验证，不提前宣称适应或Agent效果。

## 什么情况下继续，什么情况下停止

先看合同是否正确，再看投入是否值得：

- reset隔离和命令时间语义是正确性要求，不以预测误差改善作为修复必要性的唯一依据。
- 相同轨迹/相同模型家族的表示对照，才能衡量输入或memory的信息增量。比较不同架构的控制效果，应匹配外部任务而非机械使用相同数值输入。
- 一轮有限pilot后，若只有不可部署oracle改善，或状态不足/未来命令依赖仍未解决，则停止正式重采。
- 若线性在相同新表示下已足够，而非线性没有额外价值，则考虑收窄模型路线；这是新的研究决定，不是将8.2线性结果晋级。
- 新pilot的暂定筛查为20/60步误差macro改善至少10%、单构型退化不超过5%、至少2/3验证seed方向一致；小样本不等于显著性检验，正式门必须重新预注册。这些数值是预算讨论起点，不是已经验证的性能指标。

8.3的trace预算、两种对照如何匹配以及退出条件见 [08.3-CONTEXT.md](../.planning/phases/08.3-control-identification-forensics/08.3-CONTEXT.md)。8.4只保留触发条件，避免现在为未知接口编造详细实施步骤。
