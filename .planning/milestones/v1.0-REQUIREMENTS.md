# Requirements Archive: v1.0 Koopman-UUV Single-Configuration Control

**Closed:** 2026-08-09
**Scope:** Phases 1 through 5.4
**Closure:** Functional outcomes recorded; formal traceability gaps accepted

## Interpretation

The original `REQUIREMENTS.md` was not kept in sync with execution and still showed every checkbox as pending. This archive records the final functional outcome from code, phase summaries, server reports and local verification. It does not erase the stricter audit finding that several phases lack a formal `VERIFICATION.md`.

Status meanings:

- **Met:** implementation and direct phase verification align.
- **Met with traceability gap:** implementation/server evidence exists, but the phase lacks one or more GSD verification artifacts.
- **Met as comparison only:** comparison was completed, but the backend was not promoted.

## Deferred Beyond v1.0

The old planning file listed these as future v2 ideas. They are not accepted requirements for any new milestone because the user has not started that milestone:

- online Koopman KF/RLS adaptation;
- sensor-log replay and Sim2Real bias analysis;
- broader 6-DOF or direct actuator control;
- low-frequency LLM planning/tuning interface;
- multi-configuration AUV model and controller generalization.

These items must be reconsidered and rewritten as testable requirements when the next milestone is deliberately created.
