# Milestone v1.0: Koopman-UUV Single-Configuration Control

**Status:** SHIPPED AS RESEARCH BASELINE 2026-08-09
**Phases:** 1 through 5.4
**Total phase plans:** 14
**Environment:** Isaac Sim 5.0 + Isaac Lab 2.2.1

## Overview

v1.0 migrated EasyUUV to the verified Isaac Lab 2 stack and built a single-configuration Koopman-MPC-PPO research pipeline. It preserved the original thruster and hydrodynamic plant, added offline system identification and model gates, integrated bounded Koopman-MPC, retrained PPO inside the changed transition dynamics, and completed matched ablation/Pareto experiments.

The milestone closed after Phase 5.4. Planned Phase 5.5 and later work was not executed and is recorded only as deferred context.

## Execution Strategy

- **Local:** architecture, data schema, Koopman training, MPC implementation, validators, selectors, documentation and unit tests.
- **Server:** Isaac environment creation, data collection, controller rollout, PPO training and matched step/sine/irregular evaluation.
- **Safety:** every controller change preserved legacy fallback, bounded PWM and explicit evidence labels.

## Phases

### Phase 1: Baseline Data And Controller Boundary

**Goal:** Preserve legacy behavior while exposing the controller seam and collecting Koopman transitions.

**Delivered:**

- controller mode boundary around the pre-thrust PWM path;
- `_last_pwm_8d` cache;
- JSONL schema for state/reference/action/PWM/next-state;
- direct-controller rollout independent of PPO.

**Outcome:** Local helper tests passed and the data seam was later validated in Isaac Lab 2.2.1.

### Phase 1.5: Isaac Lab 2.x Compatibility Migration (Inserted)

**Goal:** Run the Phase 1 data path on Isaac Sim 5.0 + Isaac Lab 2.2.1.

**Delivered:**

- compatibility imports and valid Gym registration;
- correct `AppLauncher` import ordering;
- direct `EasyUUV-Direct-v1` rollout;
- USD/articulation compatibility repairs.

**Outcome:** Server smoke created valid Koopman JSONL records.

### Phase 2: Offline Koopman Identification

**Goal:** Train a reusable predictor from Isaac transitions.

**Delivered:** dataset conversion, direct-state lifting, ridge EDMD, model serialization, one-step and multi-step evaluation CLIs.

**Outcome:** Offline model training and reload path established.

### Phase 2.5: Offline Koopman Model Qualification Gate (Inserted)

**Goal:** Prevent a poorly generalized model from entering MPC.

**Delivered:**

- log-level train/validation/test split;
- direct-state and paper-lifted candidate sweeps;
- persistence/simple-linear baselines;
- normalization/ridge variants;
- divergence-aware evaluation;
- selected manifest and gate report.

**Outcome:** `direct_state_selected_quadratic_ridge_0p0001_norm_off` passed with `multi_step_rmse@20 = 0.5243264020` on held-out test data.

### Phase 3: Koopman MPC Controller Integration

**Goal:** Close the loop through a bounded model-predictive controller.

**Delivered:**

- manifest-first Koopman runtime;
- pure NumPy short-horizon 8D PWM MPC;
- control-energy and smoothness cost;
- timeout/non-finite fallback;
- environment controller branch and diagnostic logging.

**Outcome:** Local and server verification passed; one-env Isaac smoke completed with bounded PWM, no fallback and latency within the declared smoke budget.

### Phase 3.5: Paper-Style Lifted EDMD Qualification (Inserted)

**Goal:** Add a paper-aligned lifted-space backend as an explicit comparison.

**Delivered:** separate manifest, lifted observables, prediction comparison, offline MPC replay and Isaac controller comparison.

**Outcome:** The backend remained research-only because depth RMSE was approximately 13 to 14 in controller-only evaluation.

### Phase 4: Evaluation, Documentation And Isaac Runbook

**Goal:** Establish controller-only baselines before reconnecting PPO.

**Delivered:** matched legacy/direct-state/paper-lifted runs over step, sine and irregular trajectories, a common metrics workflow, server commands and artifact pullback instructions.

**Outcome:** Legacy remained the strongest nominal baseline; direct-state MPC was runnable but required fallback/tracking improvement; paper-lifted was not eligible as default.

### Phase 4.5: PPO/RL Reference Adapter Integration (Inserted)

**Goal:** Put PPO above Koopman-MPC without allowing it to command PWM directly.

**Delivered:** `heuristic_reference_delta_v0`, quaternion-safe reference updates, action clipping diagnostics, stub/checkpoint modes and evidence-level validation.

**Outcome:** Stub and guarded old-checkpoint smokes passed; adapter semantics remained explicitly heuristic.

### Phase 4.6: PPO Training Entrypoint And Checkpoint Evidence Gate (Inserted)

**Goal:** Distinguish “training entrypoint exists” from “a valid PPO checkpoint exists.”

**Delivered:** checkpoint discovery and selection rules, save-interval handling, sidecar summaries, legacy baseline labels and provenance preflight.

**Outcome:** Server generated and loaded checkpoint evidence without mislabeling it as Koopman-MPC retraining.

### Phase 5: Koopman-MPC PPO Retraining Smoke

**Goal:** Train PPO under the changed adapter + Koopman-MPC transition dynamics.

**Delivered:** training wrapper inside `env.step(action_4d)`, Phase 5 training entrypoint, checkpoint provenance validator and retrained-policy smoke path.

**Outcome:** Server smoke produced `model_0.pt`, refreshed the adapter before each environment step and passed checkpoint/evaluation validation. This was smoke evidence, not convergence evidence.

### Phase 5.1: Koopman-MPC PPO Stability Training (Inserted)

**Goal:** Prove a longer training run remains finite and loadable before optimizing rewards.

**Delivered:** 50-iteration sentinel, 200-iteration stability candidate, training-health summary, selected-checkpoint manifest and matched step/sine/irregular evaluation.

**Outcome:** Stable-training candidate evidence passed. Main bottlenecks were PWM saturation, fallback and action clipping.

### Phase 5.2: Reward, Adapter And MPC Health Optimization (Inserted)

**Goal:** Run controlled one-factor ablations.

**Delivered:**

- `baseline_rerun`;
- `reward_v1_only`;
- `adapter_soft_v1_only`;
- `mpc_health_v1_only`;
- profile registry, reward penalties, provenance and matched metrics.

**Outcome:** `reward_v1_only` reduced fallback from 0.2333 to 0.1248 but increased PWM saturation from 0.2293 to 0.3379, so it was not fully promoted.

### Phase 5.3: Cross-Combination PPO Health Screening (Inserted)

**Goal:** Test whether reward, adapter and MPC changes work better in combination.

**Delivered:** three pairwise candidates, one triple sentinel, multi-metric selector and provenance gates.

**Outcome:** `selection_status=no_selection`. `cross_reward_v1_mpc_health` improved PWM/depth/clip but raised fallback to 0.3105.

### Phase 5.4: Dual-Track Reward/MPC Pareto Optimization (Inserted)

**Goal:** Refine the reward-only and reward+MPC tracks with small, bounded parameter changes.

**Delivered:**

- explicit parameter-distance formula;
- latency mean/max/violation gates;
- fallback reason-level gate;
- `full_pass`, `track_pass`, `promising_partial`, `no_selection` states;
- 11-profile Round 1 with sentinel, 200-iteration candidate and matched evaluation for every profile.

**Outcome:** `selection_status=no_selection`. Latency was not the primary bottleneck; reward/MPC micro-tuning could not simultaneously preserve fallback, saturation, clip and tracking strengths.

## Milestone Summary

### Key Decisions

- Preserve EasyUUV physics and replace only the controller/policy layers.
- Separate Isaac data generation from offline model learning.
- Require a selected-model manifest before MPC integration.
- Keep direct-state as the engineering backend and paper-lifted as a research comparison.
- Optimize 8D PWM because it matches the identified model input.
- Keep PPO above Koopman-MPC through an explicit adapter.
- Reuse RSL-RL PPO rather than implement a new PPO algorithm.
- Use provenance and evidence-level gates for every checkpoint claim.
- Defer LLM and online adaptation beyond v1.0.

### Issues Resolved

- Isaac Lab 2.2.1 import order and task registration.
- Missing USD/articulation compatibility issues.
- Direct controller observation API drift.
- Model-data leakage risk through log-level splitting.
- Unsupported model/backend loading through manifest validation.
- PPO checkpoint absence, discovery ambiguity and provenance relabeling.
- Cross-profile parameter and evidence drift through versioned registries.

### Issues Deferred

- Diagnose or replace `heuristic_reference_delta_v0`.
- Explain `no_cost_improvement` fallback using cost-margin diagnostics.
- Produce a controller that consistently beats legacy across matched metrics.
- Add configuration-conditioned data/model/controller contracts.
- Add online Koopman adaptation, Sim2Real and hardware evidence.
- Consider LLM only as a later low-frequency supervisor.

### Technical Debt

- Nine phase directories do not have a formal `VERIFICATION.md`; Phase 3.5 also lacks a summary.
- Raw experiment artifacts are stored outside the v1.0 Git tag.
- Result selection is sensitive to PPO training stochasticity and used limited 200-iteration candidates.
- The current pipeline is validated for one EasyUUV configuration only.
