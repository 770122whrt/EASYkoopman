# Phase 5.3: Cross-Combination PPO Health Screening - Plan

**Spec:** `.planning/phases/05.3-cross-combination-ppo-health-screening/05.3-SPEC.md`
**Mode:** local code and tests first, Isaac training/evaluation on `agentic-AUV` after review
**Primary objective:** screen Phase 5.2 reward/adapter/MPC cross-combinations and select the best multi-metric parameter family for the next tuning/evaluation phase
**Default comparison baseline:** Phase 5.2 `reward_v1_only`
**Health floor:** Phase 5.2 `baseline_rerun`
**Readiness:** draft for user review, not ready for implementation until approved

## Current Evidence

Phase 5.2 server results:

```text
baseline_rerun:
  fallback_mean = 0.2333
  pwm_saturation_mean = 0.2293
  action_clip_mean = 0.0517
  depth_rmse_mean = 0.8564

reward_v1_only:
  fallback_mean = 0.1248
  pwm_saturation_mean = 0.3379
  action_clip_mean = 0.1393
  depth_rmse_mean = 0.9360
```

Phase 5.3 starts from this interpretation:

```text
good signal:
  reward_v1_only reduced fallback by about 46.5 percent versus Phase 5.2 baseline_rerun

bad signal:
  reward_v1_only increased PWM saturation from 0.2293 to 0.3379
  reward_v1_only also increased clip from 0.0517 to 0.1393
  reward_v1_only increased depth RMSE from 0.8564 to 0.9360

working hypothesis:
  the reward now discourages fallback enough that the policy/controller pair may use stronger PWM instead.
  Increase saturation pressure carefully, optionally make fallback penalty reason-aware,
  and rank candidates by saturation, fallback, clip, depth RMSE and attitude RMSE together.
```

## Stage A Cross-Combination Matrix For Review

Initial Phase 5.3 cross-combination matrix:

| Profile ID | Reward profile | Adapter profile | MPC profile | Risk | Why run it |
|---|---|---|---|---|---|
| `cross_reward_v1_adapter_soft` | `koopman_mpc_stability_v1` | `adapter_scale_soft_v1` | `mpc_default_v0` | medium | Directly tests whether reward and soft adapter complement each other. |
| `cross_reward_v1_mpc_health` | `koopman_mpc_stability_v1` | default | `mpc_health_v1` | high | Tests reward+MPC interaction despite Phase 5.2 MPC-only regression. |
| `cross_adapter_soft_mpc_health` | `legacy_easyuuv_v0` | `adapter_scale_soft_v1` | `mpc_health_v1` | high | Isolates adapter+MPC interaction without reward v1. |
| `cross_reward_v1_adapter_soft_mpc_health` | `koopman_mpc_stability_v1` | `adapter_scale_soft_v1` | `mpc_health_v1` | very_high | Full Phase 5.2 profile cross; sentinel-only until pairwise results are reviewed. |

This is the main Phase 5.3 question. Reward variants such as higher `w_pwm_sat` move after this screening if the best combination still needs parameter tuning.

Execution priority:

```text
1. cross_reward_v1_adapter_soft is the first 50 -> 200 candidate path.
2. MPC-containing pairwise crosses are sentinel-first and lower priority.
3. The full triple cross cannot run 200 iterations until pairwise results are reviewed.
4. Reward-variant sweeps are Stage B handoff work, not Stage A.
```

## Stage B Parameter-Tuning Handoff

After Stage A, choose the best combination family and only then tune its parameters.

Possible handoff routes:

| Stage A result | Next tuning axis |
|---|---|
| reward+adapter wins | Sweep adapter scales and saturation/action penalties around that pair. |
| reward+MPC wins | Sweep MPC smoothness/control weights cautiously. |
| adapter+MPC wins | Revisit whether reward v1 is over-constraining fallback. |
| no combination wins | Return to model/MPC diagnostics before more PPO tuning. |

## Wave 4: Selection Gate And Report Builder

Likely files:

- Create: `workflows/select_phase5_3_candidate.py`
- Extend: `workflows/analyze_phase5_2_health.py`, or create `workflows/analyze_phase5_3_health.py`
- Test: `tests/test_phase5_3_candidate_selection.py`

Selection rule:

```text
hard gates:
  finite logs
  bounded PWM inside [-1, 1]
  valid checkpoint provenance
  adapter refresh before env.step
  matched step/sine/irregular logs validate

promotion gates against reward_v1_only:
  pwm_saturation_rate_mean <= reward_v1_only_mean - 0.05
  or relative PWM saturation improvement >= 15 percent

  and at least one of:

    policy_action_clip_rate_mean <= reward_v1_only_mean - 0.02
    or relative clip improvement >= 10 percent

    depth_rmse_mean <= reward_v1_only_mean - 0.03
    or relative depth RMSE improvement >= 5 percent

  fallback_rate_mean <= reward_v1_only_mean + 0.02
  attitude_rmse_mean <= reward_v1_only_mean * 1.05
  latency_ms_mean < 20.0

health floor:
  report each metric relative to baseline_rerun
  label the candidate partial_improvement if it improves versus reward_v1_only
  but remains clearly worse than baseline_rerun on PWM saturation or depth RMSE

health_score:
  0.30 * pwm_saturation_improvement
  + 0.20 * fallback_improvement
  + 0.20 * clip_improvement
  + 0.20 * depth_rmse_improvement
  + 0.10 * attitude_rmse_improvement

normalization:
  improvement = clamp((baseline_metric - candidate_metric) / max(abs(baseline_metric), eps), -1.0, 1.0)
```

Acceptance:

- If a candidate passes, write `source/results/koopman_phase5_3/selected_cross_candidate_manifest.json`.
- If no candidate passes, write a `no_selection` report with failure reasons.
- The selector names the best non-promoted candidate separately from a promoted candidate.
- The selector reports the selected combination family and next tuning axis.
- `health_score` ranks only candidates that pass hard safety gates and regression guards.
