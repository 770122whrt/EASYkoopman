## Adapter Contract

The first adapter is explicitly named:

```text
heuristic_reference_delta_v0
```

It maps:

```text
policy_output_4d = [roll_delta, pitch_delta, yaw_delta, depth_delta]
base_reference_5d = [depth_ref, qw, qx, qy, qz]

adapted_depth = clip(base_depth + depth_delta_scale * clipped_depth_delta)
adapted_quat = normalize(base_quat * quat_from_scaled_rpy_delta)
adapted_reference_5d = [adapted_depth, adapted_quat]
```

This is a bounded engineering bridge. It does not claim that PPO's original legacy-controller action semantics transfer losslessly to Koopman+MPC.

## Safety Gates

The adapter rejects non-finite policy outputs, clips 4D actions, normalizes quaternions, bounds depth references and records:

```text
adapter_mode
action_semantics
adapter_quat_convention
ppo_evidence_level
policy_action_clip_rate
base_reference_goal_match_max_error
```

Allowed `ppo_evidence_level` values:

```text
stub_only
checkpoint_smoke
training_entrypoint_only
retrained_policy_smoke
```

The server workflow checks that the selected Koopman manifest is a passing `direct_state` manifest before creating the environment.

## Workflow

`workflows/play_ppo_koopman.py` follows this chain:

```text
PPO/stub 4D policy output
  -> heuristic_reference_delta_v0 adapter
  -> per-step env._koopman_reference_5d refresh
  -> env.step(policy_output_4d)
  -> direct_state Koopman+MPC
  -> 8D PWM
  -> PPO/Koopman JSONL validation
```

The workflow supports:

- `--policy_mode stub`
- `--policy_mode checkpoint`
- `--policy_mode training_smoke` as a clear training-entrypoint handoff, not a trained-policy result
