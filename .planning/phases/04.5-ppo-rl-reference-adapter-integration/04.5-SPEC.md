# Phase 4.5: PPO/RL Reference Adapter Integration - Specification

**Created:** 2026-07-03
**Ambiguity score:** 0.10 (gate: <= 0.20)
**Requirements:** 8 locked

## Goal

Reconnect the existing EasyUUV PPO/RSL-RL policy layer above the `direct_state` Koopman+MPC controller through an explicit adapter so PPO outputs a bounded high-level reference or correction, while Koopman+MPC remains the only layer that outputs 8D PWM.

## Background

Current code facts:

- `easyuuv_env.py` exposes `observation_space = 9` and `action_space = 4`.
- PPO observes `[goal_quat(4), current_depth_z(1), current_quat(4)]`.
- PPO outputs a 4D action currently interpreted by legacy `Ssurface/PID` as roll, pitch, yaw and depth correction.
- Legacy control maps `4D action -> Ssurface/PID -> 8D PWM -> thruster/physics`.
- Koopman+MPC maps `11D state + 5D reference + previous 8D PWM -> 8D PWM`.
- `workflows/play_eval*.py` currently force `controller_mode = 'legacy'`, so existing PPO inference is not connected to Koopman+MPC.
- `workflows/play_controller.py` already supports controller-only Koopman+MPC by setting `_koopman_reference_5d` from scripted references.

Phase 4 showed that:

- `legacy/Ssurface` is the strongest controller-only baseline.
- `direct_state` Koopman+MPC is runnable with bounded PWM but still has fallback and latency limitations.
- `paper_lifted_edmd` is useful as a research comparison backend, but its depth RMSE is too high for default PPO integration.

The control expert review adds one hard warning:

```text
Do not connect PPO to Koopman+MPC by merely flipping play_eval.py to controller_mode=koopman_mpc.
PPO's current 4D action is not the same object as the 5D reference consumed by Koopman+MPC.
```

Therefore Phase 4.5 must build a policy adapter, not a direct rewiring.

The Phase 4.5 adapter review adds a second hard warning:

```text
The first adapter is an engineering bridge named heuristic_reference_delta_v0.
It interprets PPO's legacy 4D action as a bounded reference delta, but this is
not proof that PPO's original control semantics transfer losslessly.
```

## Requirements

1. **Interface contract**: The phase must document and enforce the current PPO, legacy and Koopman+MPC input/output contracts.
   - Current: The contracts are spread across `easyuuv_env.py`, `workflows/play_eval*.py`, `workflows/play_controller.py` and Phase 4 docs.
   - Target: Phase 4.5 code and docs state that PPO input is 9D observation, PPO output is 4D action/correction, Koopman+MPC input is 11D state plus 5D reference, and only Koopman+MPC outputs 8D PWM.
   - Acceptance: A local test or source-contract check fails if the Phase 4.5 workflow bypasses the adapter or lets PPO directly produce 8D PWM.

2. **`heuristic_reference_delta_v0` adapter**: The phase must add a deterministic adapter that converts bounded PPO 4D output into a bounded 5D Koopman reference correction around a base reference, under an explicitly logged heuristic assumption.
   - Current: `play_controller.py` can set a scripted 5D reference, but PPO output is not converted into a Koopman reference.
   - Target: A pure Python adapter named `heuristic_reference_delta_v0` maps `[roll, pitch, yaw, depth]` correction to `[depth_ref, quat_ref]`, clips non-finite or out-of-range inputs, and records the adapted reference.
   - Semantic disclaimer: The adapter treats PPO's current 4D legacy controller input as a bounded reference delta only for smoke and comparison. It must not be described as "PPO semantics migrated without loss".
   - Acceptance: Unit tests cover zero correction, clipped correction, quaternion normalization, non-finite rejection and depth bound behavior without importing Isaac.

3. **Stub-policy smoke path**: The phase must provide a no-checkpoint smoke path that proves the adapter and `direct_state` Koopman+MPC can run before any real PPO checkpoint is trusted.
   - Current: Phase 4 controller-only smoke runs scripted reference directly into Koopman+MPC.
   - Target: A deterministic stub policy emits 4D actions, the adapter converts them to reference corrections, and Koopman+MPC outputs bounded 8D PWM.
   - Acceptance: Server Isaac can run a short one-env smoke with `stub policy -> adapter -> direct_state Koopman+MPC -> 8D PWM`, producing valid JSONL logs with policy and adapter fields.

4. **Checkpoint discovery and guarded inference**: The phase must discover PPO checkpoints and either run guarded inference or fail clearly.
   - Current: Existing PPO workflows expect checkpoints under RSL-RL logs, but the server may not have one.
   - Target: A workflow reports whether a checkpoint exists under `logs/rsl_rl/easyuuv`; if found, it runs a short guarded inference smoke; if missing, it runs only stub smoke or an explicitly labeled short training smoke.
   - Acceptance: Server output clearly states `checkpoint_found=true/false`, path if found, and whether the run used `stub`, `checkpoint`, or `training_smoke`.

5. **Diagnostics logging**: The phase must extend PPO-driven logs to show what the policy asked for and what Koopman+MPC actually executed.
   - Current: Koopman JSONL logs state/reference/action/PWM and optional solver diagnostics, but not PPO adapter details.
   - Target: PPO-driven logs include `policy_output`, `base_reference`, `adapted_reference`, `adapter_mode`, `action_semantics`, `ppo_evidence_level`, `adapter_quat_convention`, `base_reference_goal_match_max_error`, `controller_mode`, `backend_used`, `solver_diagnostics`, `pwm_8d`, fallback and latency fields.
   - Acceptance: `workflows/validate_koopman_log.py` or a Phase 4.5 validator accepts the extended records and rejects missing adapter fields for PPO-driven runs.

6. **Phase 4 baseline comparison**: The phase must compare PPO-adapter smoke logs against Phase 4 controller-only logs without claiming performance superiority.
   - Current: Phase 4 metrics exist for scripted legacy, direct_state MPC and paper_lifted MPC.
   - Target: Phase 4.5 summary reports whether PPO-driven or stub-policy runs remain bounded, whether fallback/latency worsens, and which Phase 4 baseline they should be compared against.
   - Acceptance: The Phase 4.5 summary cites Phase 4 logs and states whether new instability is attributable to policy/reference, MPC solver, or checkpoint absence where possible.

7. **Backend boundary**: The phase must use `direct_state` Koopman+MPC as the default backend and keep `paper_lifted_edmd` out of the default PPO path.
   - Current: Phase 4 proved `paper_lifted_edmd` can run but has high depth RMSE.
   - Target: Phase 4.5 defaults to the Phase 2.5 selected `direct_state` manifest; paper-lifted may only be used behind an explicit research flag or separate diagnostic run.
   - Acceptance: Default server commands and tests use `direct_state`; paper-lifted cannot be selected accidentally as the default PPO low-level controller.

8. **Adapter evidence and timing gates**: The phase must make the adapter assumption measurable before any checkpoint result is interpreted.
   - Current: PPO checkpoint availability is unknown and no code yet proves the 4D action can safely become a Koopman reference.
   - Target: Every PPO-driven run records `ppo_evidence_level` as `stub_only`, `checkpoint_smoke`, `training_entrypoint_only` or `retrained_policy_smoke`; the base reference quaternion matches the goal quaternion present in the policy observation for the same step; `_koopman_reference_5d` is refreshed before each `env.step`; `adapter_quat_convention` is recorded; controller-swap distribution shift is called out in the run summary.
   - Acceptance: Source-contract tests or validators reject PPO-driven records missing `ppo_evidence_level`, `action_semantics`, `adapter_quat_convention` or `base_reference_goal_match_max_error`, and the workflow code shows reference refresh before stepping the env.

## Boundaries

**In scope:**

- A local, Isaac-free PPO-to-Koopman reference adapter.
- Source-compatible tests for adapter shape, clipping, quaternion handling and non-finite rejection.
- A new or clearly isolated PPO+Koopman inference workflow.
- Deterministic stub-policy smoke before real PPO inference.
- PPO checkpoint discovery on the Isaac server.
- Optional short PPO training smoke only when no checkpoint exists and only to validate the training entrypoint.
- Extended logging for policy output, adapted reference, MPC diagnostics and final PWM.
- Explicit adapter evidence fields: `action_semantics`, `ppo_evidence_level`, `adapter_quat_convention` and `base_reference_goal_match_max_error`.
- Comparison against Phase 4 controller-only baselines.

**Out of scope:**

- Training PPO to convergence - this phase only proves reconnection and smoke behavior.
- Claiming PPO improves tracking over legacy - Phase 4.5 may only report smoke and comparison metrics.
- Claiming PPO's original 4D control semantics have been losslessly migrated to Koopman references.
- Letting PPO directly command 8D PWM - violates the controller boundary.
- Making `paper_lifted_edmd` the default PPO backend - Phase 4 depth results are not acceptable for that.
- LLM planning or tuning - Phase 5 owns LLM supervision.
- Online Kalman/RLS Koopman adaptation - Phase 6 owns online adaptation.
- Real hardware validation - this phase is Isaac-only.

## Constraints

- Local workstation still cannot run Isaac; all closed-loop rollouts run on `agentic-AUV`.
- Local adapter and validator tests must not import Isaac, Omniverse, CUDA-only modules or RSL-RL.
- Server stack remains Isaac Sim 5.0 + Isaac Lab 2.2.1.
- The default low-level backend is the Phase 2.5 selected `direct_state` manifest.
- PWM output must remain bounded in `[-1, 1]`.
- Adapter must reject or clip non-finite and out-of-range policy outputs before they can affect Koopman+MPC.
- Adapter mode string must be exactly `heuristic_reference_delta_v0` for the first implementation.
- `policy_output_4d` must not be renamed or logged as `reference_5d`; the adapted reference is a separate field.
- Base reference quaternion must match the PPO observation goal quaternion for the same step, using a sign-equivalence-aware quaternion comparison.
- The workflow must refresh `env._koopman_reference_5d` before every `env.step(...)`.
- Logs must preserve enough fields to distinguish policy failure, adapter failure, MPC fallback and physics instability.
