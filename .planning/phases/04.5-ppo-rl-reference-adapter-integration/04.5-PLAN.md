# Phase 4.5: PPO/RL Reference Adapter Integration - Plan

**Spec:** `.planning/phases/04.5-ppo-rl-reference-adapter-integration/04.5-SPEC.md`
**Upstream handoff:** `.planning/phases/04-evaluation-documentation-and-isaac-sim-runbook/04-PHASE45-HANDOFF.md`
**Mode:** local adapter/tests first, then server Isaac smoke
**Primary controller backend:** `direct_state` Koopman+MPC
**Research backend:** `paper_lifted_edmd`, excluded from default PPO path

## Purpose

Create the missing layer between EasyUUV PPO and Koopman+MPC:

```text
PPO 9D obs -> PPO 4D action -> adapter -> 5D Koopman reference -> direct_state Koopman+MPC -> 8D PWM
```

The phase succeeds when PPO or a deterministic stub policy can drive the adapter and the Koopman+MPC controller without bypassing the controller boundary. It does not need to prove PPO improves tracking.

The first adapter is intentionally conservative:

```text
adapter_mode = "heuristic_reference_delta_v0"
action_semantics = "heuristic_reference_delta_v0_legacy_4d_as_reference_delta"
```

This is an engineering assumption for smoke testing and comparison. It is not a claim that PPO's original legacy-controller semantics transfer losslessly to Koopman+MPC.

## Algorithm Contract Addendum

The Phase 4.5 implementation must enforce these contracts before any checkpoint inference result is trusted:

- `policy_output_4d` remains a 4D policy action/correction record and must not be renamed as a 5D reference.
- `adapted_reference_5d` is the adapter output consumed by Koopman+MPC.
- `base_reference_5d` uses the same goal quaternion that appears in the PPO observation for the same step.
- `_koopman_reference_5d` is refreshed before every `env.step(...)`, not only once at rollout start.
- Quaternion composition convention is logged as `adapter_quat_convention = "reference_frame_right_multiply"` for `adapted_quat = normalize(base_quat * delta_quat)`.
- Each run logs `ppo_evidence_level`: `stub_only`, `checkpoint_smoke`, `training_entrypoint_only` or `retrained_policy_smoke`.
- Each run summary states controller-swap distribution shift: the PPO policy was trained or designed against the legacy controller interface, while Phase 4.5 evaluates it through an adapter plus Koopman+MPC.

## Wave 1: Local Adapter Core

Likely files:

- Create: `koopman/policy_adapter.py`
- Create: `tests/test_policy_adapter.py`

Implement a pure Python/Torch-light adapter that does not import Isaac:

```text
PolicyAdapterInput:
  policy_output_4d
  base_reference_5d
  current_state_11d optional

PolicyAdapterOutput:
  adapted_reference_5d
  policy_output_4d_clipped
  adapter_mode
  diagnostics
```

Default mode:

```text
adapter_mode = "heuristic_reference_delta_v0"
policy_output_4d = [roll_delta, pitch_delta, yaw_delta, depth_delta]
adapted_depth = base_depth + depth_scale * clipped_depth_delta
adapted_quat = normalize(base_quat * quat_from_scaled_rpy_delta)
action_semantics = "heuristic_reference_delta_v0_legacy_4d_as_reference_delta"
```

Required safeguards:

- reject NaN/Inf policy output;
- clip 4D action to configured limits;
- normalize output quaternion;
- bound depth reference;
- record `base_reference_goal_match_max_error` using a sign-equivalence-aware quaternion comparison against the observation goal quaternion;
- preserve `q`/`-q` equivalence only in cost/metrics, not by mutating training conventions silently.

Tests:

```powershell
python -m pytest -q tests/test_policy_adapter.py
```

Acceptance:

- Zero policy output returns the base reference.
- Large finite policy output is clipped.
- Non-finite policy output raises a clear error or returns a safe rejected status.
- Output quaternion norm is near 1.
- Output depth stays inside configured reference bounds.
- Adapter diagnostics include `action_semantics`, `adapter_quat_convention` and `base_reference_goal_match_max_error`.

## Wave 3: Stub-Policy Koopman Workflow

Likely files:

- Create: `workflows/play_ppo_koopman.py`
- Create or update: `tests/test_phase45_source_contract.py`

Add a server workflow that can run without a PPO checkpoint:

```text
scripted base reference
  -> deterministic stub policy output
  -> policy adapter
  -> set env._koopman_reference_5d before each env.step
  -> env.step(policy_output_4d)
  -> direct_state Koopman+MPC
  -> 8D PWM
```

Important detail:

`env.step(policy_output_4d)` is still useful because `_compute_dynamics()` computes a legacy PWM fallback from the 4D action. The actual MPC target must come from `env._koopman_reference_5d`, refreshed by the adapter before every step.

CLI shape:

```bash
WANDB_MODE=disabled ./isaaclab.sh -p /root/EASYkoopman/workflows/play_ppo_koopman.py \
  --task EasyUUV-Direct-v1 \
  --num_envs 1 \
  --headless \
  --policy_mode stub \
  --controller_mode koopman_mpc \
  --koopman_manifest_path /root/EASYkoopman/source/results/koopman_phase2_5_verify_20260701_231802/selected_model_manifest.json \
  --trajectory_type step \
  --trajectory_cycles 1 \
  --steps_per_action 50 \
  --ppo_koopman_log_path /root/EASYkoopman/source/results/koopman_phase4_5/stub_step.jsonl
```

Acceptance:

- Source-contract tests verify the workflow starts Isaac before importing environment modules.
- Source-contract tests verify it supports `--policy_mode stub`.
- Source-contract tests verify it sets or refreshes a Koopman reference before each `env.step()`.
- Stub policy cannot require an RSL-RL checkpoint.

## Wave 4: PPO Checkpoint Discovery And Guarded Inference

Likely files:

- Update: `workflows/play_ppo_koopman.py`
- Create: `workflows/discover_ppo_checkpoints.py`
- Create: `tests/test_phase45_checkpoint_discovery.py`

Checkpoint discovery:

```text
search roots:
  logs/rsl_rl/easyuuv
  /root/EASYkoopman/logs/rsl_rl/easyuuv
  /root/IsaacLab/logs/rsl_rl/easyuuv

patterns:
  model_*.pt
  *.pt
```

Policy modes:

```text
stub
checkpoint
training_smoke
```

Rules:

- `checkpoint` mode requires an explicit or discoverable checkpoint.
- Missing checkpoint exits clearly unless `--allow_stub_fallback` is set.
- `training_smoke` is labeled as training-entrypoint verification, not as a trained policy result.
- Checkpoint mode logs `ppo_evidence_level=checkpoint_smoke`.
- Stub mode logs `ppo_evidence_level=stub_only`.
- Training entrypoint checks log `ppo_evidence_level=training_entrypoint_only`.
- Any later short run with a newly trained checkpoint must be labeled `ppo_evidence_level=retrained_policy_smoke`, not mixed with a pre-existing checkpoint smoke.
- `paper_lifted_edmd` is not the default backend.

Server discovery command:

```bash
cd /root/EASYkoopman
/opt/conda/envs/isaaclab/bin/python workflows/discover_ppo_checkpoints.py --json
```

Acceptance:

- Discovery returns JSON with `checkpoint_found`, `count`, `paths`.
- Missing checkpoints do not look like successful PPO inference.
- Checkpoint inference logs `policy_mode=checkpoint`.
