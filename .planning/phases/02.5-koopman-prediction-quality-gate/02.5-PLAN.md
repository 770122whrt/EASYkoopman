# Phase 2.5: Offline Koopman Model Qualification Gate - Plan

**Spec:** `.planning/phases/02.5-koopman-prediction-quality-gate/02.5-SPEC.md`
**Recommendation source:** `docs/phase2_5_koopman_model_gate_recommendations.md`
**Target branch:** `isaaclab2-migration`
**Mode:** local-first, Isaac-free implementation

## Purpose

Phase 2 proved that Koopman training and evaluation can run. Phase 2.5 decides whether any trained model is trustworthy enough for MPC.

The core gate question is:

```text
Is the selected Koopman model stable, generalizable, reproducible, and theoretically close enough to Koopman-Sim2Real to be used as the Phase 3 MPC prediction model?
```

## Key Design Decisions

- Preserve the current direct-state model as `model_class = direct_state`.
- Add a paper-style lifted-space EDMD candidate as `model_class = paper_lifted_edmd`.
- Compare against `persistence` and `simple_linear` baselines.
- Use log-level split only; do not implement row-level random split.
- Rank candidates by held-out validation multi-step behavior, not training loss.
- Treat divergence as blocking even if one-step RMSE is small.
- Generate a selected model manifest and gate report; Phase 3 consumes the manifest, not implicit code defaults.

## Wave 4: Divergence-Aware Multi-Horizon Evaluation

Tasks:

- Extend metrics with:
  - `multi_step_rmse@5`
  - `multi_step_rmse@20`
  - `multi_step_rmse@60`
  - `attitude_angle_rmse`
  - `max_error`
  - `nonfinite_count`
  - `divergence_rate@20`
  - `divergence_rate@60`
- Record physical envelope in metrics or manifest.
- Mark divergence when:
  - NaN/Inf appears,
  - quaternion norm becomes unreasonable,
  - depth or velocity leaves envelope,
  - `multi_step_rmse@60 > 3 * one_step_rmse`,
  - `divergence_rate@20 > 0`.
- Keep existing Phase 2 metrics keys for backward compatibility.

Verification:


## Wave 5: Candidate Sweep

Tasks:

- Sweep:

```text
ridge: [1e-8, 1e-6, 1e-4, 1e-2]
model_class: direct_state, paper_lifted_edmd
lifting_variant: linear, selected_quadratic
normalization: off, on where implemented
```

- Train candidates on train logs.
- Evaluate candidates on validation logs.
- Evaluate baselines on validation logs.
- Save per-candidate model and metrics artifacts.
- Write `sweep_results.json` sorted by:
  1. non-diverged status,
  2. validation `multi_step_rmse@20`,
  3. validation `multi_step_rmse@60`,
  4. smaller validation-test gap when test is available,
  5. simpler lifting when metrics are comparable.

## Expected End State

At the end of Phase 2.5:

- We have a log-level split manifest.
- We have a sweep summary comparing direct-state, paper-style lifted EDMD and baselines.
- We have held-out validation/test metrics over multiple rollout horizons.
- We know whether predictions diverge under configured physical envelopes.
- We have one selected model manifest for Phase 3.
- We have a gate report that either authorizes or blocks MPC integration.
