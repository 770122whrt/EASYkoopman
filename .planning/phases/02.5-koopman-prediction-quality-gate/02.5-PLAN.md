# Phase 2.5: Koopman Prediction Quality Gate - Plan

**Spec:** `.planning/phases/02.5-koopman-prediction-quality-gate/02.5-SPEC.md`
**Target branch:** `isaaclab2-migration`
**Mode:** local-first, Isaac-free implementation

## Purpose

Phase 2 proved that Koopman training and evaluation can run. Phase 2.5 decides whether a trained model is trustworthy enough for MPC.

The core question:

```text
Can this Koopman model predict unseen EasyUUV trajectories for the same horizon MPC will optimize over, without diverging?
```

## File Plan

Create or modify:

- `koopman/splits.py` - split manifest dataclasses, validation and JSON read/write.
- `koopman/sweep.py` - candidate config expansion, training/evaluation loop and ranking.
- `koopman/selection.py` - selected model manifest creation and validation.
- `koopman/evaluation.py` - add divergence fields to metrics.
- `workflows/split_koopman_logs.py` - create train/validation/test split manifest.
- `workflows/sweep_koopman_models.py` - train/evaluate/rank candidates.
- `workflows/select_koopman_model.py` - write selected model manifest from sweep output.
- `tests/test_koopman_splits.py`
- `tests/test_koopman_sweep.py`
- `tests/test_koopman_selection.py`
- update `tests/test_koopman_evaluation.py`
- update `.planning/STATE.md` after implementation.

Do not modify Isaac runtime files in this phase unless a server collection bug blocks data generation.

## Wave 1: Split Manifest

Tasks:

- Add split manifest schema with `train`, `validation`, `test`, `created_at`, and optional `notes`.
- Add validation that all referenced logs exist.
- Reject overlap between train/validation/test.
- Add CLI to create a split manifest from explicit path lists.

Verification:

```powershell
python -m pytest tests\test_koopman_splits.py -q
python workflows\split_koopman_logs.py --help
```

## Wave 2: Divergence-Aware Evaluation

Tasks:

- Extend `evaluate_model()` output with:
  - `diverged`
  - `max_abs_state`
  - `max_abs_depth_error`
  - `max_abs_velocity`
- Treat NaN/Inf or state norm beyond threshold as divergence.
- Preserve existing metrics keys so Phase 2 tests remain compatible.

Verification:

```powershell
python -m pytest tests\test_koopman_evaluation.py -q
```

## Wave 3: Candidate Sweep

Tasks:

- Define candidate configs over ridge list and lifting mode.
- For each candidate:
  - Train on split train logs.
  - Evaluate on validation logs.
  - Save model artifact.
  - Save metrics artifact.
- Write summary JSON sorted by validation `multi_step_rmse`, with diverged candidates ranked last.

Verification:

```powershell
python -m pytest tests\test_koopman_sweep.py -q
python workflows\sweep_koopman_models.py --help
```

## Wave 4: Selected Model Manifest

Tasks:

- Add selected manifest containing:
  - selected model path
  - selected metrics path
  - split manifest path
  - candidate config
  - validation metrics
  - test metrics if available
  - selection reason
  - created timestamp
- Add CLI that selects the best non-diverged candidate from sweep summary.

Verification:

```powershell
python -m pytest tests\test_koopman_selection.py -q
python workflows\select_koopman_model.py --help
```

## Wave 5: Server Data Runbook

Tasks:

## Data Collection Guidance

Recommended server artifacts:

```text
source/results/koopman_phase1/koopman_step_long.jsonl
source/results/koopman_phase1/koopman_sine_long.jsonl
source/results/koopman_phase1/koopman_irregular_long.jsonl
```

If multi-env logging is later needed, first patch the logger to emit one JSONL row per env index. Until then, use multiple single-env runs as the safer data diversity path.

## Expected End State

At the end of Phase 2.5:

- We have a split manifest.
- We have a sweep summary comparing candidate Koopman models.
- We have held-out validation/test metrics.
- We know whether rollout predictions diverge.
- We have one selected model manifest for Phase 3 MPC.
