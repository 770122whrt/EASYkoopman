# Phase 2.5: Koopman Prediction Quality Gate - Specification

**Created:** 2026-06-30
**Ambiguity score:** 0.12 (gate: <= 0.20)
**Requirements:** 5 locked

## Goal

在进入 Koopman+MPC 闭环控制前，证明离线训练出的 Koopman 模型能在未见过的 EasyUUV 日志上稳定预测未来 50-200 步，并产出一个可被 Phase 3 使用的 selected model manifest。

## Background

Phase 2 已经实现了离线 Koopman identification 基础链路：

- `koopman/dataset.py`: JSONL 转 `X/U/R/Y/t` 矩阵。
- `koopman/lifting.py`: deterministic lifting。
- `koopman/edmd.py`: ridge EDMD。
- `koopman/model.py`: 模型保存、加载和预测。
- `koopman/evaluation.py`: one-step 和 multi-step RMSE。
- `workflows/train_koopman.py` / `workflows/evaluate_koopman.py`: 离线训练与评估入口。

当前问题是：用同一份 step 数据训练并评估，只能证明链路跑通，不能证明模型可以泛化到 sine、irregular 或新的初始条件。MPC 会依赖模型滚动预测未来控制效果，所以在 Phase 3 前必须先建立模型质量 gate。

## Requirements

1. **Log split manifests**: 训练、验证、测试日志必须显式分离。
   - Current: `train_koopman.py` 可以接收日志，但没有 train/validation/test split 概念。
   - Target: 新增 manifest 或 split workflow，记录哪些 JSONL 用于训练、验证和测试。
   - Acceptance: 本地测试能创建一个 split manifest，并确认同一日志不会同时出现在 train、validation、test 多个集合。

2. **Multi-log training**: Koopman 训练必须支持多日志联合输入。
   - Current: `load_dataset()` 已经支持多个 path，但 workflow 尚未围绕多轨迹数据建立流程。
   - Target: 训练流程明确支持 step、sine、irregular 以及可选多次初始条件运行的 JSONL。
   - Acceptance: fixture 测试能从多个 JSONL 构造训练集并生成模型。

3. **Candidate sweep**: 模型选择必须比较多个候选配置。
   - Current: 需要手动多次运行 `train_koopman.py` 和 `evaluate_koopman.py`。
   - Target: 新增 sweep workflow，至少支持 ridge 系数列表和 linear/quadratic lifting 对比。
   - Acceptance: 本地 fixture sweep 生成多个 model artifact 和统一 metrics summary。

4. **Rollout stability report**: 必须检测多步预测是否发散。
   - Current: `evaluate_koopman.py` 输出 multi-step RMSE，但没有明确 divergence 标记。
   - Target: 比较 horizon 内状态范数、depth/velocity 误差和 NaN/Inf，输出 `diverged: true/false`。
   - Acceptance: 测试能构造正常模型和异常预测结果，并验证 divergence flag。

5. **Selected model manifest**: Phase 3 必须只消费通过 gate 的模型。
   - Current: 训练后只有单个 model JSON 和 metrics JSON，没有“正式选择”的模型清单。
   - Target: 新增 selected model manifest，记录模型路径、训练/验证/测试日志、关键指标、候选配置和选择理由。
   - Acceptance: 本地测试能生成 manifest，并验证 manifest 指向的 model 和 metrics 文件存在。

## Boundaries

**In scope:**

- 日志 split manifest。
- 多日志训练与评估流程。
- ridge/lifting candidate sweep。
- rollout divergence 检测。
- selected model manifest。
- 本地纯 Python 测试和 CLI。
- 服务器采集多条日志的 runbook 更新。

**Out of scope:**

- MPC solver 实现 - Phase 3。
- Isaac 闭环控制 - Phase 3。
- 在线 RLS/Kalman 自适应 - Phase 5。
- 强化学习调参 - 当前路线不是 RL。
- 强制 vectorized multi-env logging - 当前可先用多次单 env 运行覆盖不同初始条件。

## Constraints

- Phase 2.5 代码仍然不得导入 Isaac、Omniverse、Gym task registration 或 Torch。
- 所有模型选择必须基于 validation/test 日志，而不是训练集自评。
- step、sine、irregular 三类轨迹在进入 Phase 3 前至少要各有一份通过 validator 的日志。
- 如果短期没有 vectorized multi-env 数据，可以用多次 server rollout 和不同目标/初始条件替代。
- selected model manifest 是 Phase 3 的输入 gate；没有 manifest 不进入 MPC integration。

## Acceptance Criteria

- [ ] split workflow 能创建 train/validation/test manifest。
- [ ] split manifest 检查能拒绝重复日志和不存在的日志路径。
- [ ] sweep workflow 能训练多个候选模型并输出 summary JSON/CSV。
- [ ] summary 至少包含 one-step RMSE、multi-step RMSE、horizon、diverged 和 candidate config。
- [ ] selected model manifest 能记录模型路径、metrics 路径、数据 split、选择理由和时间戳。
- [ ] `python -m pytest -q` 通过。
- [ ] `python -m compileall koopman workflows tests` 通过。
- [ ] Phase 2.5 新增代码路径不依赖 Isaac runtime。
