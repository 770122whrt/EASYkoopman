# Phase 2.5: Offline Koopman Model Qualification Gate - Specification

**Created:** 2026-07-01
**Ambiguity score:** 0.10 (gate: <= 0.20)
**Requirements:** 8 locked

## Goal

在进入 Koopman+MPC 闭环控制前，选出一个稳定、可泛化、可复现，并且方法上更接近 Koopman-Sim2Real 的 Koopman 模型；如果没有模型通过 gate，则明确阻止 Phase 3 使用该模型。

## Background

Phase 2 已经实现了离线 Koopman identification 基础链路：

- `koopman/dataset.py`: JSONL 转 `X/U/R/Y/t` 矩阵。
- `koopman/lifting.py`: deterministic lifting。
- `koopman/edmd.py`: ridge EDMD。
- `koopman/model.py`: 模型保存、加载和预测。
- `koopman/evaluation.py`: one-step 和 multi-step RMSE。
- `workflows/train_koopman.py` / `workflows/evaluate_koopman.py`: 离线训练与评估入口。

但是当前模型更接近 direct next-state predictor：

```text
x[k+1] = W * [lift(x[k], r[k]), u[k]]
```

这对工程 baseline 有用，但和 Koopman-Sim2Real 中的 lifted-space evolution 仍有差异：

```text
f[k+1] = Theta^T * f[k]
```

其中 `f[k]` 是 observable vector，raw state 只是 lifted observable 的一部分。Phase 2.5 因此不只是“调参”，而是一个正式模型资格 gate：比较当前 direct-state 模型、paper-style lifted EDMD、baseline，并用 held-out multi-step rollout 证明选出的模型不会明显发散。

## Requirements

1. **Log-level split**: 训练、验证、测试日志必须显式分离，禁止 row-level random split。
   - Current: `train_koopman.py` 可以接收日志，但没有 train/validation/test split 概念。
   - Target: 新增 split manifest，记录 `train_logs`、`validation_logs`、`test_logs`、`split_rule`、`seed` 和 notes。
   - Acceptance: 本地测试能拒绝重复日志、不存在日志路径，以及 validation/test 为空导致的 data-insufficient 状态。

2. **Multi-log and multi-trajectory data**: 模型训练必须支持多个 JSONL 日志联合输入。
   - Current: `load_dataset()` 支持多个 path，但 workflow 尚未围绕 step/sine/irregular 建立质量 gate。
   - Target: 训练流程明确支持 step、sine、irregular，以及可选多次初始条件或重复单 env 运行。
   - Acceptance: fixture 测试能从多个 JSONL 构造训练集；gate 文档要求 step/sine/irregular 均通过 validator 后才能做最终选择。

3. **Candidate A - direct-state predictor**: 保留当前模型作为工程 baseline。
   - Current: Phase 2 已实现 `x[k+1] = W * [lift(x[k], r[k]), u[k]]`。
   - Target: sweep 中继续训练和评估该候选，标记 `model_class = direct_state`.
   - Acceptance: sweep summary 中至少包含一个 `direct_state` candidate。

4. **Candidate B - paper-style lifted EDMD**: 必须新增 lifted-space EDMD 候选。
   - Current: 没有 `f[k+1] = Theta^T f[k]` 形式的模型候选。
   - Target: observable 至少包含 state、reference error、selected squared velocity/rate terms、PWM 和 PWM squared terms；模型预测时从 lifted observable 中选择 raw state。
   - Acceptance: sweep summary 中至少包含一个 `paper_lifted_edmd` candidate，并能保存/加载/预测。

5. **Baselines**: 选中模型必须和 persistence 与 simple linear baseline 比较。
   - Current: 没有 baseline comparison。
   - Target: 新增 `persistence` baseline 和 `simple_linear` baseline，在 validation/test 上输出同一套 metrics。
   - Acceptance: gate report 明确说明 selected model 是否优于两个 baseline；若没有优于 baseline，gate_status 必须为 fail。

6. **Normalization and sweep**: sweep 必须比较 ridge、lifting variant 和 normalization 选择。
   - Current: ridge/lifting 可手动调整，但没有统一 sweep，也没有 normalization contract。
   - Target: sweep 至少覆盖 ridge `[1e-8, 1e-6, 1e-4, 1e-2]`，linear 与 selected quadratic lifting；如启用 normalization，必须记录 normalizer artifact。
   - Acceptance: sweep summary 对每个 candidate 记录 ridge、lifting_config、normalizer、train_metrics、validation_metrics 和 status。

7. **Divergence-aware held-out metrics**: 评估必须包含多 horizon rollout 与 divergence 判定。
   - Current: `evaluate_koopman.py` 输出 one-step 和单个 horizon multi-step RMSE。
   - Target: 输出 `multi_step_rmse@5`、`multi_step_rmse@20`、`multi_step_rmse@60`、`attitude_angle_rmse`、`max_error`、`nonfinite_count`、`divergence_rate@20`、`divergence_rate@60`。
   - Acceptance: 测试能验证 NaN/Inf、物理 envelope 越界、`multi_step_rmse@60 > 3 * one_step_rmse` 或 `divergence_rate@20 > 0` 会导致 candidate fail。

8. **Selected manifest and gate report**: Phase 3 只能消费通过 gate 的 manifest。
   - Current: 训练后只有 model JSON 和 metrics JSON，没有正式 gate artifact。
   - Target: 新增 `selected_model_manifest.json` 和 `gate_report.md`，记录 gate_status、model_class、model_path、dt、维度、lifting_config、normalizer_path、ridge、train/validation/test logs、metrics、baselines 和 known limitations。
   - Acceptance: 本地测试能生成并验证 manifest；gate report 明确 pass/fail；没有 pass 状态时 Phase 3 不能开始。

## Boundaries

**In scope:**

- 日志 schema validation 汇总。
- log-level train/validation/test split manifest。
- direct-state predictor 保留为 baseline candidate。
- paper-style lifted-space EDMD candidate。
- persistence 和 simple linear baselines。
- ridge/lifting/normalization sweep。
- 多 horizon held-out evaluation。
- divergence check 与 physical envelope 记录。
- selected model manifest。
- gate report。
- 本地纯 Python 测试和 CLI。
- 服务器采集 step/sine/irregular 长日志的 runbook。

**Out of scope:**

- MPC solver 实现 - Phase 3。
- `easyuuv_env.py` 闭环控制改造 - Phase 3。
- PPO retraining。
- LLM tuning。
- Kalman/RLS online adaptation，除非作为完全独立的非阻塞 prototype。
- 强制 vectorized multi-env logging - 当前先用多日志/多次单 env 运行覆盖数据多样性。

## Constraints

- Phase 2.5 代码不得导入 Isaac、Omniverse、Gym task registration 或 Torch。
- 不允许 row-level random split，因为连续轨迹相邻行高度相关，会造成信息泄漏。
- 如果日志数量不足以做 train/validation/test split，gate 必须输出 data-insufficient，而不是伪造评估。
- 模型排名优先使用 held-out validation multi-step behavior，而不是训练 loss。
- selected model 必须优于 persistence 和 simple linear baselines，否则 gate fail。
- selected model manifest 必须显式记录 `dt`、feature/控制/状态维度和 normalization 行为，Phase 3 不能从代码默认值推断。
- step、sine、irregular 三类轨迹在进入 Phase 3 前至少要各有一份通过 validator 的日志。

## Acceptance Criteria

- [ ] split workflow 创建 log-level train/validation/test manifest，并拒绝重复路径。
- [ ] data-insufficient 情况会明确 fail，而不是退回 row-level split。
- [ ] sweep workflow 输出 direct-state 和 paper-style lifted EDMD candidates。
- [ ] sweep workflow 输出 persistence 和 simple linear baseline metrics。
- [ ] sweep summary 至少包含 ridge、lifting_config、normalizer、one-step RMSE、multi-step RMSE@5/@20/@60、divergence flags 和 status。
- [ ] selected model manifest 记录 model_class、model_path、normalizer_path、dt、维度、data split、metrics、baselines 和 known limitations。
- [ ] gate report 明确 pass/fail、选择理由、baseline 对比、held-out test 指标和限制。
- [ ] `python -m pytest -q` 通过。
- [ ] `python -m compileall koopman workflows tests` 通过。
- [ ] Phase 2.5 新增代码路径不依赖 Isaac runtime。
