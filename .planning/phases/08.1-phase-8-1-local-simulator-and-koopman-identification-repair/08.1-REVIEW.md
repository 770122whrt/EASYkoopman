# Phase 8.1 Code Review Report

**Verdict:** **NOT READY** for D-23-authorized collection/formal LOCO/selection or research release.

The additive timing, actuator-memory, SO(3), observable/PCA, and pending-protocol primitives are substantial, and the frozen Phase 8 source/protocol/result paths inspected in the diff remain unchanged. However, the submitted tree stops at locally tested scaffolding: both formal post-approval runners are placeholders, multiple release-state objects are not bound to the exact selected model or registered episode set, and the collector can emit evidence with unverified source provenance. These defects can produce non-executable or falsely attributable research output even when unit tests pass.

No server, collection, formal LOCO, bundle, or historical held-out evaluation was run. Read-only/static checks confirmed `git diff --check` passes and the Phase 8.1 proposal hashes are:

- analysis policy: `711a91b541b0aab8b00ca7642da2a0f69545b61ef15701b64944d60d1c519433`

## Critical Findings

### CR-01: Formal LOCO and selection runners are unconditional placeholders

**Required classification:** BLOCKER (Critical)
**Files:** `workflows/run_koopman_v21_loco.py:31-37`, `workflows/select_koopman_v21.py:29-35`
**Issue:** After a valid D-23 record is accepted, both formal entrypoints merely import a module, discard it, and raise `phase81_authorized_*_runner_not_configured`. Consequently, an approved Phase 8.1 experiment can neither execute the exact-eight fold state machine nor produce outer evidence/final publication. The entrypoint tests hide this by monkeypatching the runners (`tests/test_phase81_entrypoints.py:91-136`) instead of exercising the authorized implementation. This is explicit fake completeness, not a deferred runtime detail.

**Minimal fix:** Implement the two authorized runners end-to-end: validate protocol-bound inventory/splits before any data open, execute all eight source-ledger/freeze/diagnostic/expert/test sequences, persist and validate the evaluation envelope, then run the frozen outer-family selector and selected-family-only final refit. Add an Isaac-free synthetic authorized full-chain test that calls the real runners; retain the existing missing-approval side-effect spies.

### CR-02: “Canonical” D-23 authorization accepts arbitrary caller-supplied files

**Required classification:** BLOCKER (Critical)
**Files:** `workflows/collect_koopman_v21_identification.py:27-32`, `workflows/run_koopman_v21_loco.py:17-24`, `workflows/select_koopman_v21.py:17-24`, `koopman/d23_approval_v21.py:490-507`, `tests/test_phase81_entrypoints.py:91-136`
**Issue:** Every formal CLI requires arbitrary `--approval-record`, `--role-protocol`, and `--analysis-policy` paths, while `require_canonical_d23_approval_v21()` never verifies that any path resolves to the repository's canonical Phase 8.1 location. The test suite explicitly copies the proposals to a temp directory, self-writes an `approved` JSON record, and treats that as sufficient authorization. Thus the absence of `protocols/phase8_1/d23_approval.json` does not actually fail closed: a caller can authorize side effects with an ad hoc record and copied proposals. This contradicts KIDR-09's canonical-record boundary; `identity_assurance=none` does not mean “any path is canonical.”

**Minimal fix:** Define canonical resolved paths in `d23_approval_v21.py`, make formal entrypoints use those paths without caller override (or reject any resolved mismatch), and reserve arbitrary paths only for a non-side-effecting validation utility. Change the synthetic approval test to validate the record directly, while formal runner tests require the canonical path.

### CR-03: Primary freeze can bind a different model than the ledger winner

**Required classification:** BLOCKER (Critical)
**File:** `koopman/loco_v21.py:508-580`
**Issue:** `freeze_primary_v21()` copies caller-provided `model_identities`, `normalizer_identities`, and `pca_identities` after checking only the family-key sets. It never looks up each `selected_candidates[family]` entry in the sealed ledger or compares the identities recorded for that selected candidate. A caller can therefore rank candidate A, freeze arbitrary model B, then legitimately obtain held-out-test authorization because `FoldEvaluationSessionV21` checks only the ledger hash and selected candidate IDs. The current test even supplies identities different from the ledger entry (`tests/test_koopman_loco_v21.py:248-263`), normalizing the defect.

**Minimal fix:** Derive all frozen identities from the selected ledger entries, or strictly compare supplied identities against those entries before constructing `FrozenPrimaryV21`. Enforce normalization- and family-specific PCA presence/absence, and add mutation tests proving any model/normalizer/PCA identity mismatch is rejected before diagnostic or test authorization.

### CR-04: Outer selection and final refit accept incomplete, protocol-unbound episode sets

**Required classification:** BLOCKER (Critical)
**Files:** `koopman/selection_v21.py:106-157`, `koopman/selection_v21.py:206-220`, `koopman/selection_v21.py:388-403`, `koopman/selection_v21.py:456-489`
**Issue:** `select_outer_family_v21()` checks eight held-out configuration names and a caller-provided `completed=True`, but baseline/family evidence needs only a nonempty episode tuple. Episode IDs and `family_repetition` labels are not checked against the D-23 role protocol or the authorized test token. A single fabricated episode per configuration is enough to reach `SELECTION`. Likewise, final refit requires only at least one fit and one validation episode per configuration; it does not require the registered 48 fit plus 24 validation episodes, transition hashes, or protocol roles. The positive refit test uses only 16 total episodes (`tests/test_koopman_selection_v21.py:215-225`, `:289-307`) rather than the protocol's 72 non-test episodes. This breaks the exact role/state-machine boundary and allows selection/publication from incomplete or substituted evidence.

**Minimal fix:** Bind fold evidence to the validated role protocol and `PrimaryTestTokenV21`: require the exact three registered test episode IDs/family repetitions for every role in each fold. Bind final-refit data to the exact 48 fit and 24 validation IDs and their validated transition hashes. Derive `completed` from those checks rather than accepting it as a boolean assertion.

### CR-05: Collector provenance can claim an unrelated commit and permits dirty-source collection

**Required classification:** BLOCKER (Critical)
**File:** `workflows/collect_koopman_v21_identification.py:63-73`
**Issue:** `--source-commit` is accepted if it merely looks like 40 lowercase hex characters; if omitted, the collector records `git rev-parse HEAD` without checking the working tree. Therefore server episodes can be generated by modified/untracked code while manifests claim the clean HEAD, or can claim an entirely unrelated supplied commit. That invalidates the provenance link needed to interpret the simulator clock repair and v2.1 data.

**Minimal fix:** Reuse the existing clean-tree/source binding contract from the v2 collector: reject tracked or unexpected untracked changes, derive the commit from the actual checkout, and if a wrapper supplies an expected commit require exact equality with `HEAD`. Carry that verified commit into every manifest and aggregate envelope.

## Important Findings

### IM-01: Conditional candidate and model APIs use incompatible conditioning identifiers

**Required classification:** WARNING (Important)
**Files:** `koopman/loco_v21.py:92-96`, `koopman/model_v21.py:86`, `koopman/model_v21.py:491-515`
**Issue:** `CandidateSpecV21` requires conditional candidates to use `structured_pca_r2_v1`, but `ControlledEDMDV21` accepts only `structured_pca2`. There is no production adapter or formal runner that translates and verifies these names. A future runner cannot pass a registered conditional candidate directly to the model API, and an ad hoc translation would not be represented in candidate identity/provenance.

**Minimal fix:** Freeze one shared conditioning constant/value across protocol, candidate, model, serializer, and tests. Add a positive conditional path that creates a candidate, fits/serializes/loads the model plus PCA projector, evaluates it, and completes final refit without string translation.

### IM-02: Metric aggregation drifts from the frozen diagnostic contract

**Required classification:** WARNING (Important)
**File:** `koopman/metrics_v21.py:640-709`
**Issue:** The v2.1 analysis policy still declares row-weighted aggregation as `diagnostic_only`, but the aggregator returns only per-configuration, equal-macro, and worst-configuration outputs. It also dropped the v2 guard rejecting duplicate `expected_configurations`; duplicates silently repeat entries in the macro/worst loops and can bias a supposedly equal-configuration result. These are protocol/code drift even though row-weighted results are non-promoting.

**Minimal fix:** Restore a separately labelled `row_weighted_diagnostic` output, reject duplicate/incorrect configuration sequences, and validate that each artifact exposes the exact required horizon map before aggregation. Keep promotion logic restricted to equal-configuration macro and per-configuration sentinels.
