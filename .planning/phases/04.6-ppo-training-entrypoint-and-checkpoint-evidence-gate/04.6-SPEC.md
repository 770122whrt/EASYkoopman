# Phase 4.6: PPO Training Entrypoint And Checkpoint Evidence Gate - Specification

**Created:** 2026-07-03
**Document type:** planning contract plus explanation
**Audience:** project owner, future implementation agent and Isaac server operator

## Goal

Restore and verify the PPO/RSL-RL training, checkpoint generation and checkpoint loading path under the current Isaac Sim 5.0 + Isaac Lab 2.2.1 server stack, without claiming PPO performance improvement.

Phase 4.6 is not the final PPO phase. It is the bridge that makes Phase 5 possible. The required Koopman-MPC-specific PPO checkpoint is trained in Phase 5, where the adapter and Koopman-MPC controller are inside the training loop.

Phase 4.6 exists because Phase 4.5 proved only this chain:

```text
stub policy -> heuristic_reference_delta_v0 -> direct_state Koopman+MPC -> 8D PWM
```

It did not prove PPO inference or PPO training because no PPO checkpoint existed on the server.

The Phase 4.6 success claim is therefore narrow:

```text
PPO/RSL-RL training and checkpoint workflows are usable again.
A checkpoint can be generated, discovered and loaded.
Any checkpoint result is labeled by evidence level and controller path.
No PPO superiority or convergence claim is made.
The next required PPO phase is Phase 5: train a new PPO checkpoint inside
the Koopman-MPC closed loop.
```

## Background

Current source facts:

- `easyuuv_env.py` keeps the original EasyUUV PPO interface: 9D observation and 4D action.
- The original EasyUUV PPO path is `PPO -> legacy/Ssurface -> 8D PWM`.
- Phase 4.5 added `heuristic_reference_delta_v0`, which maps PPO or stub 4D action into a 5D Koopman reference.
- Phase 4.5 server verification found no PPO checkpoint under the expected RSL-RL log roots.
- `workflows/train.py`, `workflows/play_eval.py` and `workflows/gen_policy.py` still contain legacy Isaac Lab import patterns and must be treated as migration targets before training claims.
- `workflows/play_ppo_koopman.py` already has guarded policy modes, but it cannot create a PPO checkpoint by itself.

Control/RL review conclusion:

```text
PASS_WITH_WARNINGS:
Phase 4.6 is reasonable only if it is defined as training-entrypoint and checkpoint evidence work.
It must not be written as a PPO performance phase.
```

## Required Separation Of Result Buckets

Phase 4.6 must keep these buckets separate in file names, logs, summaries and claims.

| Bucket | Chain | What It Proves | What It Does Not Prove |
| --- | --- | --- | --- |
| `legacy_ppo_baseline` | PPO checkpoint -> legacy/Ssurface -> 8D PWM | Original EasyUUV PPO training/eval path can run. | Koopman-MPC integration or improved control. |
| `old_checkpoint_adapter_smoke` | old PPO checkpoint -> heuristic adapter -> Koopman+MPC -> 8D PWM | Existing checkpoint can be loaded through the adapter path. | Semantic equivalence or controller-swap robustness. |
| `retrained_ppo_koopman_mpc` | PPO trained while adapter and Koopman+MPC are in the loop | Phase 5 target bucket. | Not implemented by Phase 4.6 unless explicitly expanded later. |

`result_bucket` and `ppo_evidence_level` are separate fields. `legacy_ppo_baseline` is a `result_bucket`, not a valid `ppo_evidence_level` under the current Phase 4.5 adapter/validator contract.

Current valid `ppo_evidence_level` values remain:

```text
stub_only
checkpoint_smoke
training_entrypoint_only
retrained_policy_smoke
```

## Requirements

1. **Isaac Lab 2 PPO entrypoint compatibility**
   - `workflows/train.py` must start through `/root/IsaacLab/isaaclab.sh -p`.
   - It must use Isaac Lab 2 compatible imports via the existing `isaaclab_compat` pattern where practical.
   - It must avoid the known AppLauncher `--cpu` duplicate argument conflict.
   - Acceptance: a server command with `--num_envs 1 --max_iterations 1 --headless` starts and exits without import or argument errors.
   - Evidence label: `ppo_evidence_level = "training_entrypoint_only"`.
   - Important: this smoke does not require or imply checkpoint creation.

2. **Checkpoint generation**
   - A checkpoint generation smoke must produce at least one `model_*.pt` file.
   - `--max_iterations 1` alone is not checkpoint evidence because `agents/rsl_rl_ppo_cfg.py` currently sets `save_interval = 50`.
   - Checkpoint generation must use one of these save policies:
     - add a `--save_interval 1` CLI override and set `agent_cfg.save_interval = 1`;
     - add an explicit final `runner.save(...)` smoke checkpoint after `runner.learn(...)`;
     - run enough iterations to trigger the current `save_interval`.
   - The default expected location is one of:

```text
/root/IsaacLab/logs/rsl_rl/easyuuv/<timestamp>/model_*.pt
/root/EASYkoopman/logs/rsl_rl/easyuuv/<timestamp>/model_*.pt
```

   - Acceptance: `workflows/discover_ppo_checkpoints.py --json` returns `checkpoint_found=true` and a non-empty `selected_checkpoint` after the checkpoint generation smoke.

3. **Legacy PPO baseline smoke**
   - The first checkpoint smoke must use the original EasyUUV low-level path:

```text
PPO checkpoint -> legacy/Ssurface -> 8D PWM
```

   - Required labels:

```text
result_bucket = "legacy_ppo_baseline"
ppo_evidence_level = "checkpoint_smoke"
reward_profile = "legacy_easyuuv_v0"
controller_path = "legacy/Ssurface"
```

   - Acceptance: one short eval writes logs and a summary sidecar with the required Phase 4.6 evidence fields.

4. **Old checkpoint Koopman adapter smoke**
   - A checkpoint trained or found under the legacy controller may be routed through Phase 4.5 only as:

```text
ppo_evidence_level = "checkpoint_smoke"
result_bucket = "old_checkpoint_adapter_smoke"
```

   - Acceptance: logs include adapter fields from Phase 4.5 and explicitly state controller-swap distribution shift.

5. **Phase 5 retrained Koopman-MPC PPO handoff**
   - Phase 4.6 must preserve the contract for the required Phase 5 retraining work.
   - Phase 4.6 should not claim that Koopman-MPC PPO has been trained.
   - It is not enough for any later phase to set `controller_mode = "koopman_mpc"`.
   - The Phase 5 training loop or environment wrapper must ensure:

```text
policy_output_4d -> heuristic_reference_delta_v0 -> _koopman_reference_5d refresh -> env.step(policy_output_4d)
```

   - Acceptance: Phase 4.6 summary points to the Phase 5 spec/plan and states this retraining work is next, not complete.

6. **Reward profile versioning**
   - Phase 4.6 must keep the original EasyUUV reward profile unless explicitly versioned.
   - Default label:

```text
reward_profile = "legacy_easyuuv_v0"
```

   - Acceptance: all Phase 4.6 summaries state the reward profile and whether it was changed.

7. **Evidence-level logging**
   - Every PPO-related output must include one of:

```text
stub_only
training_entrypoint_only
checkpoint_smoke
retrained_policy_smoke
```

   - Acceptance: missing evidence level blocks completion. Result buckets such as `legacy_ppo_baseline` must be stored in `result_bucket`, not `ppo_evidence_level`.

8. **Checkpoint selection contract**
   - Discovery must return both the candidate list and the selected checkpoint.
   - Explicit checkpoint arguments take precedence over auto-discovery.
   - Auto-discovery should prefer `model_*.pt` over generic `*.pt`, then choose the newest candidate by modification time.
   - Required discovery fields:

```json
{
  "checkpoint_found": true,
  "count": 1,
  "paths": ["..."],
  "selected_checkpoint": "...",
  "selected_rule": "explicit_path|latest_mtime_model_pt"
}
```

   - Acceptance: later eval commands use `selected_checkpoint`, not an arbitrary path from `paths`.

9. **No performance overclaim**
   - Phase 4.6 may report tracking, fallback, latency and action statistics.
   - It must not claim PPO improves over legacy unless a later long evaluation phase proves it.
   - Acceptance: summary contains an "Allowed Claims" and "Disallowed Claims" section.

## In Scope

- Migrate PPO train/eval/export scripts enough for Isaac Lab 2.2.1.
- Run a short server training smoke to create a checkpoint.
- Discover generated checkpoints before launching checkpoint inference.
- Run a short legacy PPO baseline smoke.
- Run a short old-checkpoint adapter smoke if a checkpoint exists.
- Define the handoff contract for future Koopman-MPC PPO retraining.
- Version reward profile and evidence level.
- Write server commands and artifact paths.

## Out Of Scope

- Full PPO training to convergence.
- PPO hyperparameter optimization.
- Claiming PPO+Koopman-MPC is better than `legacy/Ssurface`.
- Changing the PPO observation from 9D to 11D Koopman state.
- Changing PPO action from 4D to 8D PWM.
- Letting PPO directly command thrusters.
- Making `paper_lifted_edmd` the default PPO training backend.
- LLM supervision.
- Real hardware or Sim2Real claims.
