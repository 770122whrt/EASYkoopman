# Phase 4.6: PPO Training Entrypoint And Checkpoint Evidence Gate - Plan

**Spec:** `.planning/phases/04.6-ppo-training-entrypoint-and-checkpoint-evidence-gate/04.6-SPEC.md`
**Mode:** local source-contract changes first, then server Isaac training smoke
**Default controller path for first training:** `legacy/Ssurface`
**Default PPO observation/action:** keep EasyUUV 9D observation and 4D action

## Purpose

Create a clean PPO checkpoint evidence layer before any further PPO+Koopman claims.

The Phase 4.6 progression is:

```text
1. restore PPO train/eval/export entrypoints
2. run short legacy PPO training smoke
3. discover generated checkpoint
4. load checkpoint through legacy eval/export
5. optionally route checkpoint through Phase 4.5 adapter as guarded smoke
6. hand off to Phase 5 for Koopman-MPC PPO retraining
```

This phase is deliberately not a performance phase, and it is not the final PPO phase. Phase 5 owns the required Koopman-MPC-specific PPO retraining.

## Non-Negotiable Boundaries

- PPO observation remains 9D: `[goal_quat, current_depth_z, current_quat]`.
- PPO action remains 4D: roll, pitch, yaw and depth correction/control input.
- PPO must not output 8D PWM.
- First generated checkpoint is a `legacy_ppo_baseline` checkpoint unless the training path explicitly proves adapter plus Koopman-MPC reference refresh.
- A legacy checkpoint routed through Koopman-MPC is `old_checkpoint_adapter_smoke`, not a migrated policy.
- Any Koopman-MPC retraining must put `heuristic_reference_delta_v0` in the training loop, not only in eval; that implementation belongs to Phase 5.
- Reward profile defaults to `legacy_easyuuv_v0`.

## Wave 2: Checkpoint Generation And Discovery

Likely files:

- Modify if needed: `workflows/discover_ppo_checkpoints.py`
- Modify: `workflows/train.py` to support one checkpoint save policy
- Test: `tests/test_phase45_checkpoint_discovery.py` or new `tests/test_phase46_checkpoint_discovery.py`

Checkpoint save policy:

`agents/rsl_rl_ppo_cfg.py` currently sets:

```text
save_interval = 50
max_iterations = 800
```

Therefore `--max_iterations 1` is not a reliable checkpoint generation command. Implement one of:

```text
Option A: add --save_interval 1 and set agent_cfg.save_interval = 1
Option B: add a Phase 4.6 smoke flag that writes an explicit final runner.save(...)
Option C: run at least save_interval iterations if server time allows
```

Recommended first implementation: add `--save_interval 1` because it is explicit, testable and keeps smoke runs short.

Expected checkpoint paths:

```text
/root/IsaacLab/logs/rsl_rl/easyuuv/<timestamp>/model_*.pt
/root/EASYkoopman/logs/rsl_rl/easyuuv/<timestamp>/model_*.pt
```

Discovery command:

```bash
cd /root/EASYkoopman
/opt/conda/envs/isaaclab/bin/python workflows/discover_ppo_checkpoints.py --json
```

Acceptance:

- Discovery returns JSON with `checkpoint_found`, `count`, `paths`, `search_roots`, `selected_checkpoint` and `selected_rule`.
- Selection rule is deterministic: explicit path wins; otherwise prefer newest `model_*.pt` by modification time; generic `*.pt` is a fallback.
- After a successful checkpoint generation smoke, `checkpoint_found=true`.
- If no checkpoint exists, the failure is reported before checkpoint inference starts.

## Wave 5: Phase 5 Koopman-MPC PPO Retraining Handoff

Likely files:

- Reference: `.planning/phases/05-koopman-mpc-ppo-retraining/05-SPEC.md`
- Reference: `.planning/phases/05-koopman-mpc-ppo-retraining/05-PLAN.md`
- Reference: `docs/phase5_koopman_mpc_ppo_training_strategy.md`

This wave is a handoff, not an implementation wave. Phase 4.6 completes the PPO checkpoint evidence gate; Phase 5 implements the actual Koopman-MPC PPO training wrapper.

Critical rule:

```text
Do not claim retrained PPO with Koopman-MPC unless training itself uses the adapter.
```

Phase 5 training path must be:

```text
obs_9d -> PPO policy -> action_4d
action_4d + base_reference_5d -> heuristic_reference_delta_v0
adapted_reference_5d -> env._koopman_reference_5d
env.step(action_4d) -> Koopman+MPC -> pwm_8d
```

Acceptance:

- Phase 4.6 summary links to Phase 5 spec/plan.
- Phase 4.6 summary states Koopman-MPC PPO retraining is required next.
- Phase 4.6 summary does not mark retraining as failed merely because it is deferred to Phase 5.

## Execution Stop Conditions

Stop and ask the user before continuing if:

- `train.py` requires a larger redesign than import and wrapper migration.
- RSL-RL API changed enough that the checkpoint format is uncertain.
- Training under Koopman-MPC would require changing reward or observation.
- Checkpoint generation starts but produces no `model_*.pt`.
- Server GPU/driver errors prevent even one RSL-RL training iteration.
