## 解释

Track R 的方向是从 `reward_v1_only` 出发，尝试压低 PWM/clip/depth 的副作用。结果证明：增加 `w_pwm_sat` 或 action smoothness 确实能压 PWM saturation，有些 profile 甚至把 depth 或 clip 做得很好，但它们都没有保住 `reward_v1_only` 的 fallback 优势。因此 Track R 不能推广。

Track RM 的方向是从 `cross_reward_v1_mpc_health` 出发，尝试修复 fallback。结果证明：某些 profile 能把 fallback 压得很好，例如 `rm_timeout14`、`rm_timeout16`、`rm_midweights_timeout14`、`rm_lightweights_timeout14`，但它们会丢掉原来 MPC-health 的 clip/depth/attitude 强项，或者把 fallback reason 从 `timeout` 转移成更严重的 `no_cost_improvement`。因此 Track RM 也不能推广。

最接近“有研究价值但不能晋级”的候选是：

```text
rm_horizon4_timeout14:

  但 PWM saturation = 0.2938，depth RMSE = 1.1573，且 no_cost_improvement fallback 明显增加
```

## Phase 5.4 的技术收获

1. latency 不是当前瓶颈。
   - 所有正式候选 `latency_ms_mean < 20 ms`，`latency_ms_max < 50 ms`，violation rate 接近 0。

2. 单纯 reward/MPC 小参数搜索不足以找到全指标 Pareto winner。
   - 这说明瓶颈可能在 PPO policy 学到的 reference correction、adapter 映射、或 MPC fallback 判定本身，而不是单个权重大小。

3. fallback reason gate 很有价值。
   - 多个 RM profile 表面上降低了 timeout fallback，但 `no_cost_improvement` 上升，说明“给更多时间/降低 regularization”不等于更健康的求解。

4. 初始禁用 adapter tuning 的边界是正确的。
   - 本轮结果显示下一步很可能需要诊断 adapter 或 reference action 语义，但它不应混进 Phase 5.4 的结论里。

## 建议下一步

推荐进入 Phase 5.5，而不是直接接 LLM。

Phase 5.5 建议目标：

```text
diagnose PPO action -> heuristic_reference_delta_v0 -> Koopman reference 的语义瓶颈，
并检查 fallback reason 中 no_cost_improvement 的形成机制。
```

候选方向：

1. Adapter/reference diagnosis：
   - 固定 PPO checkpoint，离线 sweep adapter scale。
   - 检查 action_4d 到 reference_5d 的映射是否过度激进或方向错误。

2. Fallback reason-aware MPC diagnostics：
   - 把 `timeout` 和 `no_cost_improvement` 分开记录 cost trajectory。
   - 检查 MPC candidate action 是否总被 smoothness/control cost 否决。

3. PPO training health：
   - 不改变控制链，增加训练长度或 curriculum，但必须保留同样的 matched eval gate。

Phase 5.4 的结论应作为 Phase 5.5 的入口证据，而不是失败回滚。
