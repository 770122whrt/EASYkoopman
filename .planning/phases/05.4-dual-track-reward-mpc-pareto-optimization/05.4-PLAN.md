## Non-Negotiable Planning Rules

1. **Small parameter values are preferred.**
   - If `w_pwm_sat=0.25` and `0.35` both work, choose `0.25`.
   - If `mpc_timeout_ms=14` and `16` both work, choose `14`.
   - If `control=0.02/smoothness=0.075` works about as well as `0.03/0.10`, choose the lighter weights.

2. **One good run is not enough.**
   - Finish the scheduled Round 1 sweep unless a hard safety failure appears.
   - Run Round 2 local refinement before writing a final selected profile.

3. **Preserve prior strengths.**
   - Track R must not lose the `reward_v1_only` fallback advantage.
   - Track RM must not lose the `cross_reward_v1_mpc_health` PWM/clip/depth/attitude gains.

4. **No forced winner.**
   - `no_selection` is a valid result if every candidate has a major tradeoff.

5. **Initial Round 1 does not tune the adapter.**
   - All Round 1 profiles keep `adapter_profile=heuristic_reference_delta_v0_default`.
   - Adapter tuning requires a reviewed addendum or a later Phase 5.5.

## Wave 4: Pareto Selector And Small-Parameter Tie-Breaker

Likely files:

- Create: `workflows/select_phase5_4_candidate.py`
- Test: `tests/test_phase5_4_candidate_selection.py`

Selection inputs:

```text
comparison_baselines:
  baseline_rerun
  reward_v1_only
  cross_reward_v1_mpc_health

candidates:
  Track R and Track RM matched metrics
```

Hard gates:

```text
finite logs
bounded PWM
valid checkpoint provenance
matched step/sine/irregular logs
latency_ms_mean < 20.0
latency_ms_max < 50.0
latency_budget_violation_rate <= 0.10
fallback_reason_counts_by_trajectory present
```

Small-parameter rule:

```text
When two candidates pass:
  if health_score difference < 0.03, choose smaller parameter_distance.

When a larger candidate wins:
  require larger_parameter_justification.
```

Pareto logic:

```text
candidate A dominates B if A is no worse on all ranked metrics and better on
at least one ranked metric, after protected-strength guards.
```

Acceptance:

- Selector writes `no_selection` if no profile passes.
- Selector reports Pareto frontier even when there is no selection.
- Selector names best Track R, best Track RM, best overall and nearest smaller candidate.
- Selector refuses final selection if Round 2 has not been completed.
- Selector emits `selection_status` as one of `full_pass`, `track_pass`, `promising_partial`, `no_selection`.
- Selector reports `latency_ms_mean`, `latency_ms_max` and `latency_budget_violation_rate`.
- Selector reports `timeout_fallback_delta`, `no_cost_improvement_fallback_delta` and `exception_fallback_count`.

Selection status meanings:

```text
full_pass:
  candidate reaches the baseline_rerun health floor and passes track guards.

track_pass:
  candidate preserves its track protected strength and repairs its main bottleneck,
  but does not beat every baseline_rerun metric.

promising_partial:
  candidate has one clear useful signal but one key bottleneck remains outside gate.

no_selection:
  no candidate is promotable; write Pareto report only.
```

Fallback reason checks:

```text
If mpc_timeout_ms is increased:
  timeout fallback should decrease.
  no_cost_improvement fallback must not materially increase.

If control/smoothness weights are reduced:
  no_cost_improvement fallback should decrease or remain stable.
  PWM saturation must not lose the Track RM advantage.

material increase:
  absolute increase > 0.02
  or relative increase > 25 percent
```
