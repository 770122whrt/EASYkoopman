# Phase 5.4: Dual-Track Reward/MPC Pareto Optimization - Specification

## Goal

Run a broad but bounded parameter search over the two useful Phase 5.2/5.3 signals, then select a PPO-Koopman-MPC profile only if it improves the overall health tradeoff while preserving the original strengths.

This phase answers:

```text
Can we find a smaller, safer parameter set that improves PWM saturation,
fallback, policy action clipping, depth RMSE and attitude RMSE together,
rather than accepting the first single profile that looks good?
```

Phase 5.4 is not a final-performance phase. It is a disciplined search phase whose output is either:

```text
selected_phase5_4_profile:
  a profile that passes the Pareto gate and a second-round local refinement check

or

no_selection:
  a ranked Pareto report explaining which metric remains the bottleneck
```

## Input Evidence

Phase 5.2 produced the current best single-axis candidate:

| Profile | Fallback | PWM saturation | Clip | Latency ms | Depth RMSE | Attitude RMSE |
|---|---:|---:|---:|---:|---:|---:|
| `baseline_rerun` | 0.2333 | 0.2293 | 0.0517 | 11.8990 | 0.8564 | 0.8135 |
| `reward_v1_only` | 0.1248 | 0.3379 | 0.1393 | 11.7225 | 0.9360 | 0.7434 |

Interpretation:

```text
reward_v1_only preserves fallback well, but it increases PWM saturation,
action clipping and depth RMSE.
```

Phase 5.3 produced no promoted cross candidate, but it exposed the best non-promoted signal:

| Profile | Fallback | PWM saturation | Clip | Latency ms | Depth RMSE | Attitude RMSE |
|---|---:|---:|---:|---:|---:|---:|
| `cross_reward_v1_mpc_health` | 0.3105 | 0.1192 | 0.0400 | 11.8692 | 0.7173 | 0.7354 |

Interpretation:

```text
reward_v1 + MPC health strongly helps PWM saturation, action clipping,
depth RMSE and attitude RMSE, but fallback becomes unacceptable.
```

Phase 5.4 therefore keeps two tracks alive:

```text
Track R:
  start from reward_v1_only and reduce PWM/clip/depth regressions without
  losing its fallback strength.

Track RM:
  start from cross_reward_v1_mpc_health and reduce fallback while preserving
  its PWM/clip/depth/attitude strengths.
```

## Algorithm Contract

The control chain remains fixed:

```text
obs_9d
  -> RSL-RL PPO policy
  -> action_4d
  -> heuristic_reference_delta_v0
  -> koopman_reference_5d
  -> direct_state Koopman+MPC
  -> pwm_8d
  -> Isaac EasyUUV physics
```

Phase 5.4 may tune only versioned profile metadata:

```text
reward terms:
  w_fallback
  w_pwm_sat
  w_action
  w_delta_action
  optional reason-aware fallback weights

MPC terms:
  mpc_control_weight
  mpc_smoothness_weight
  mpc_timeout_ms
  optional mpc_horizon

adapter terms:
  only if Round 1 evidence shows adapter is the remaining bottleneck
```

Initial Round 1 is explicitly reward/MPC-only:

```text
Initial Phase 5.4 Round 1 does not change adapter_profile.
Adapter tuning requires a reviewed addendum or a later Phase 5.5.
```

Phase 5.4 must not:

```text
replace RSL-RL PPO
change PPO observation/action dimensions
let PPO output 8D PWM directly
rewrite the MPC solver
promote paper_lifted_edmd as the default low-level controller
introduce LLM tuning or LLM control
claim final convergence, deployment readiness or broad legacy superiority
```

## Small-Parameter-First Rule

The user requirement is now a hard selection rule:

```text
If multiple candidates pass the health gate, choose the smallest parameter
change that preserves the gains, unless a larger parameter change improves
the composite health score by a meaningful margin.
```

Parameter smallness is measured from the parent profile:

```text
Track R parent:
  reward_v1_only
  w_fallback = 0.30
  w_pwm_sat = 0.20
  w_action = 0.01
  w_delta_action = 0.02
  mpc_default_v0

Track RM parent:
  cross_reward_v1_mpc_health
  reward_v1_only reward terms
  mpc_control_weight = 0.03
  mpc_smoothness_weight = 0.10
  mpc_timeout_ms = 12.0
  mpc_horizon = 5
```

The selector must report:

```text
parameter_distance_from_parent
minimal_parameter_selected
larger_parameter_justification
nearest_smaller_candidate_result
```

Parameter distance must be computable, not qualitative:

```text
parameter_distance_from_parent =
  sum(abs(candidate_value - parent_value) / step_size(parameter))
```

Initial step sizes:

```text
w_pwm_sat: 0.05
w_fallback: 0.05
w_action: 0.005
w_delta_action: 0.01
mpc_timeout_ms: 2.0
mpc_control_weight: 0.005
mpc_smoothness_weight: 0.015
mpc_horizon: 1
```

Each profile summary must record:

```text
changed_parameter_count
parameter_step_count
parameter_distance_from_parent
```

A larger parameter set may beat a smaller one only if:

```text
health_score improves by >= 0.03
or at least two bottleneck metrics improve by >= 10 percent

and

no protected strength regresses beyond its guard.
```

## Broad-Search Requirement

Phase 5.4 must not stop after one good run. The first implementation must support:

```text
Round 1:
  at least 4 Track R reward-side profiles
  at least 5 Track RM reward+MPC profiles

Round 2:
  mandatory local refinement around the best passing candidate or the best
  single-bottleneck non-promoted candidate
```

If Round 1 finds a candidate that appears good, the phase still continues through the scheduled Round 1 matrix, then runs Round 2 neighborhood probes before final selection.

Round 2 may be skipped only under this exception:

```text
every Round 1 candidate has multiple protected-strength failures
and selector outputs no_selection + Pareto report
and the user accepts diagnostic stop
```

The final report must answer:

```text
Is this truly the best profile found so far?
Did a smaller parameter set perform equally well?
Which metric blocks further promotion?
Which nearby parameter should be tried next if the user wants one more round?
```

## Initial Parameter Sweep Matrix

### Track R: Preserve `reward_v1_only` fallback, reduce PWM/clip/depth regressions

Parent:

```text
reward_profile = koopman_mpc_stability_v1
adapter_profile = heuristic_reference_delta_v0_default
mpc_profile = mpc_default_v0
w_fallback = 0.30
w_pwm_sat = 0.20
w_action = 0.01
w_delta_action = 0.02
```

Round 1 Track R candidates:

| Profile ID | Changed terms | Purpose |
|---|---|---|
| `r_pwm025` | `w_pwm_sat=0.25` | Smallest saturation-pressure probe above Phase 5.2. |
| `r_pwm030` | `w_pwm_sat=0.30` | Gentle saturation-pressure increase already suggested by Phase 5.3 handoff. |
| `r_pwm035` | `w_pwm_sat=0.35` | Middle value before the stronger `0.40` probe. |
| `r_pwm030_action_smooth` | `w_pwm_sat=0.30`, `w_action=0.015`, `w_delta_action=0.03` | Check whether action smoothness lowers PWM/clip without large tracking loss. |
| `r_pwm030_fallback025` | `w_pwm_sat=0.30`, `w_fallback=0.25` | Test whether slightly lower fallback pressure reduces aggressive PWM use while preserving fallback guard. |

Optional Track R Round 2 candidates:

```text
r_best_minus_step:
  lower the strongest changed weight by one step

r_best_plus_step:
  raise only the bottleneck-related weight by one step

r_reason_aware_v0:
  replace scalar fallback penalty with reason-aware fallback only if fallback
  reasons show mixed timeout/no_cost behavior under the best Track R profile
```

### Track RM: Preserve `cross_reward_v1_mpc_health` PWM/clip/depth gains, reduce fallback

Parent:

```text
reward_profile = koopman_mpc_stability_v1
adapter_profile = heuristic_reference_delta_v0_default
mpc_control_weight = 0.03
mpc_smoothness_weight = 0.10
mpc_timeout_ms = 12.0
mpc_horizon = 5
```

Round 1 Track RM candidates:

| Profile ID | Changed terms | Purpose |
|---|---|---|
| `rm_timeout14` | `mpc_timeout_ms=14.0` | Smallest timeout relaxation. |
| `rm_timeout16` | `mpc_timeout_ms=16.0` | Medium timeout relaxation; still below the 20 ms latency guard. |
| `rm_midweights` | `control=0.02`, `smoothness=0.075`, `timeout=12.0` | Reduce MPC regularization strength to lower fallback pressure. |
| `rm_midweights_timeout14` | `control=0.02`, `smoothness=0.075`, `timeout=14.0` | Combine moderate weights with smallest timeout relaxation. |
| `rm_lightweights_timeout14` | `control=0.015`, `smoothness=0.06`, `timeout=14.0` | Smaller MPC weight change to test whether the original `0.03/0.10` is too strong. |
| `rm_horizon4_timeout14` | `horizon=4`, `timeout=14.0`, `control=0.02`, `smoothness=0.075` | Reduce solver burden while preserving MPC health pressure. |

Optional Track RM Round 2 candidates:

```text
rm_timeout15:
  if 14 ms is not enough and 16 ms works, test the smaller middle value

rm_weight_interpolate:
  if midweights pass but lightweights lose PWM gains, test control=0.0175,
  smoothness=0.0675

rm_reason_timeout_v0:
  reason-aware fallback with lower timeout penalty only if timeout dominates
  fallback reasons
```

## Metrics And Promotion Gates

Every candidate is evaluated on matched `step`, `sine` and `irregular` rollouts after checkpoint training.

Metrics:

```text
fallback_rate_mean
pwm_saturation_rate_mean
policy_action_clip_rate_mean
latency_ms_mean
latency_ms_max
latency_budget_violation_rate
depth_rmse_mean
attitude_rmse_mean
fallback_reason_counts
fallback_reason_counts_by_trajectory
timeout_fallback_delta
no_cost_improvement_fallback_delta
exception_fallback_count
parameter_distance_from_parent
```

Latency must distinguish training-loop diagnostics from matched-evaluation diagnostics:

```text
training_loop_latency:
  used for early warning and failure classification

matched_eval_latency:
  used for candidate selection
```

Protected strengths:

```text
Track R protected strength:
  fallback_rate_mean from reward_v1_only

Track RM protected strengths:
  pwm_saturation_rate_mean, clip rate, depth RMSE and attitude RMSE from
  cross_reward_v1_mpc_health
```

Hard gates for every candidate:

```text
finite logs
bounded PWM inside [-1, 1]
valid Phase 5.4 checkpoint provenance
adapter refresh before env.step
matched step/sine/irregular logs validate
latency_ms_mean < 20.0
latency_ms_max < 50.0
latency_budget_violation_rate <= 0.10
```

Fallback reason gate:

```text
fallback_reason_counts must be reported per trajectory.

If mpc_timeout_ms is increased:
  timeout fallback should decrease.
  no_cost_improvement fallback must not materially increase.

If control/smoothness weights are reduced:
  no_cost_improvement fallback should decrease or remain stable.
  PWM saturation must not lose the Track RM advantage.
```

Material increase is defined as:

```text
absolute increase > 0.02
or relative increase > 25 percent
```

Full-pass target:

```text
candidate improves or preserves all main metrics versus baseline_rerun:
  fallback_rate_mean <= 0.2333
  pwm_saturation_rate_mean <= 0.2293
  policy_action_clip_rate_mean <= 0.0517
  depth_rmse_mean <= 0.8564
  attitude_rmse_mean <= 0.8135
```

Track R promotion target:

```text
fallback_rate_mean <= 0.1448
pwm_saturation_rate_mean <= 0.2879
policy_action_clip_rate_mean <= 0.1393
depth_rmse_mean <= 0.9360
attitude_rmse_mean <= 0.7806
```

Track RM promotion target:

```text
fallback_rate_mean <= 0.2333     # interim pass
target_fallback_rate_mean <= 0.1448  # full reward_v1 preservation
pwm_saturation_rate_mean <= 0.1500
policy_action_clip_rate_mean <= 0.0600
depth_rmse_mean <= 0.7500
attitude_rmse_mean <= 0.7434
```

If a candidate satisfies every Track RM target except the full reward-v1 fallback target, it may be labeled:

```text
promising_partial_rm
```

but it must not become the default profile until Round 2 confirms no smaller/better fallback-preserving variant exists.

Selection status vocabulary:

```text
full_pass:
  candidate reaches the baseline_rerun health floor and passes track protected-strength guards.

track_pass:
  candidate preserves its track's protected strength and fixes the main bottleneck,
  but does not beat every baseline_rerun metric.

promising_partial:
  candidate shows a clear useful signal but still has one key bottleneck outside gate.

no_selection:
  no candidate can be promoted; output Pareto report only.
```

## Composite Health Score

For ranking after hard gates:

```text
health_score =
  0.25 * pwm_saturation_improvement
  + 0.25 * fallback_improvement
  + 0.20 * clip_improvement
  + 0.20 * depth_rmse_improvement
  + 0.10 * attitude_rmse_improvement
  - 0.05 * parameter_distance_penalty
```

The score is a ranking tool only. It cannot override hard gates or protected-strength guards.

The report must include separate score views:

```text
vs_reward_v1_only
vs_baseline_rerun
vs_cross_reward_v1_mpc_health
```

## Requirements

1. **Phase 5.4 profile contract**: Define versioned profiles for Track R and Track RM without mutating Phase 5.2 or Phase 5.3 historical profiles.
   - Acceptance: profile lookup rejects unknown Phase 5.4 IDs and reports parent profile, changed parameters, track and sweep round.

2. **Small-parameter-first selector**: Candidate ranking must prefer smaller parameter changes when performance is statistically or practically similar.
   - Acceptance: selector output includes `parameter_distance_from_parent`, `nearest_smaller_candidate_result` and `larger_parameter_justification`.

3. **Broad Round 1 sweep**: The first server run must cover both tracks rather than only the current favorite.
   - Acceptance: Round 1 contains at least four Track R profiles and five Track RM profiles unless a hard server failure blocks the sweep.

4. **Mandatory Round 2 refinement**: A good Round 1 result is not enough.
   - Acceptance: no final selected profile is written until a local-neighborhood Round 2 around the best candidate or best single-bottleneck non-promoted candidate is completed.

5. **Matched evaluation and Pareto report**: Every candidate that reaches selection must complete step/sine/irregular matched evaluation.
   - Acceptance: final report contains per-trajectory metrics, mean metrics, Pareto frontier, dominance relationships and bottleneck explanation.

6. **Preserve previous strengths**: The selector must explicitly protect `reward_v1_only` fallback and `cross_reward_v1_mpc_health` PWM/clip/depth/attitude signals.
   - Acceptance: failure reasons distinguish `lost_reward_fallback_strength` from `lost_mpc_health_strength`.

7. **Evidence/provenance labels**: Phase 5.4 checkpoints cannot be relabeled Phase 5.3 candidates.
   - Acceptance: validators reject Phase 5.1, 5.2 and 5.3 summaries when Phase 5.4 evidence is required.

8. **No forced winner**: If no candidate beats the gates, select `no_selection`.
   - Acceptance: report still includes best non-promoted candidates and the recommended next axis.

9. **Latency max and violation gate**: Candidate selection must not rely on latency mean alone.
   - Acceptance: matched evaluation reports `latency_ms_mean`, `latency_ms_max` and `latency_budget_violation_rate`; selection requires mean `<20 ms`, max `<50 ms` and violation rate `<=0.10`.

10. **Fallback reason gate**: Track RM must prove that fallback repair does not merely trade one fallback reason for another.
   - Acceptance: reports include fallback reason counts by trajectory and deltas for `timeout`, `no_cost_improvement` and `exception`; material increases are flagged.

11. **Selection status layering**: Final reports must distinguish strong, track-local and diagnostic outcomes.
   - Acceptance: `selection_status` is one of `full_pass`, `track_pass`, `promising_partial` or `no_selection`.

12. **Initial adapter exclusion**: Initial Round 1 must not tune adapter profile.
   - Acceptance: all initial Round 1 profiles keep `adapter_profile=heuristic_reference_delta_v0_default`; adapter tuning requires reviewed addendum or a later phase.

## Gate Model

Phase 5.4 uses a nine-layer gate:

| Gate | Name | Required Evidence |
|---:|---|---|
| 1 | Entry Evidence | Phase 5.2 `baseline_rerun`, Phase 5.2 `reward_v1_only`, Phase 5.3 `cross_reward_v1_mpc_health`, and Phase 5.3 `no_selection` source paths. |
| 2 | Architecture | `observation_dim=9`, `action_dim=4`, `adapter_mode=heuristic_reference_delta_v0`, `koopman_backend=direct_state`, `pwm_dim=8`. |
| 3 | Profile Contract | `profile_id`, `track`, `parent_profile_id`, overrides, `sweep_round`, protected strengths, parameter distance and changed-parameter counts. |
| 4 | Sentinel | 50-iteration checkpoint, finite signals, bounded PWM, adapter refresh before env step, valid Phase 5.4 provenance, classified failure on stop. |
| 5 | Candidate | 200-iteration checkpoint reload, matched logs validate, latency mean/max/violation gates, fallback reason counts. |
| 6 | Track R | Preserve `reward_v1_only` fallback and repair at least one primary shortcoming. |
| 7 | Track RM | Repair fallback while preserving PWM/clip/depth/attitude advantages. |
| 8 | Small Parameter | Prefer smaller parameter distance unless larger candidate proves meaningful multi-metric gain. |
| 9 | Round 2 / Final | Round 2 completed or skipped only under diagnostic-stop exception; Pareto frontier reported; final status layered. |

## Boundaries

**In scope:**

- Phase 5.4 SPEC and PLAN.
- Local profile registry, selector and validator changes.
- Bounded Round 1 and Round 2 parameter sweeps.
- Isaac server sentinel/candidate training and matched evaluation.
- Pareto report and small-parameter-first selection.

**Out of scope:**

- LLM integration.
- PPO algorithm rewrite.
- PPO observation/action shape changes.
- Direct 8D PWM policy.
- MPC solver rewrite.
- Paper-lifted EDMD default promotion.
- Full random search or unbounded hyperparameter optimization.
- Adapter tuning in the initial Round 1 matrix.
- Final deployment or broad legacy-superiority claim.

## Stop Conditions

Stop and discuss if:

- A profile causes NaN/Inf rewards, observations or actions.
- PWM leaves `[-1, 1]`.
- Mean latency reaches or exceeds `20 ms`.
- Fallback exceeds `0.40` in any matched candidate.
- Every Track R candidate worsens fallback beyond `0.1448`.
- Every Track RM candidate loses PWM saturation advantage above `0.20`.
- A larger parameter set looks better but the nearest smaller candidate was not tested.
- The results suggest adapter scale, not reward or MPC, is the true remaining bottleneck.
