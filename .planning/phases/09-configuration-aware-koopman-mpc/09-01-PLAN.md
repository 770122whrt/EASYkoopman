# 控制集成第一步：因果执行器状态与可复制预测分支

2026-09-20。前置证据为[Phase 8.4 正式结果](../../../docs/phase8_4_v38_formal_results.md)及[更正后的交接 v2](../../../docs/evidence/phase8_4/server-projected-formal-v38-r23/prediction-control-handoff-v2.json)。本计划沿用用户授权的4D直接pre-TAM方向，只做本地接口及耗时验证；完成它不等于MPC2-01..03或整个Phase 9完成。

## 已有事实与设计选择

`koopman.command_prediction_v37.forecast_commands`每次从已知零转速起点重放全部已发物理子步命令。它已获新数据预测证据，但对优化器的多个候选分支重复重放同一历史会增加开销。先解决这项接口开销，再比较优化方法。

| 选择 | 与现有证据的关系 | 本阶段决定 |
|---|---|---|
| 缓存因果执行器状态，分支内继续非线性预测 | 保留实际mask/TAM、float32累计时钟、转速动态和已验证模型 | 首选；先验证等价性及隔离，再讨论优化器 |
| 把提升模型直接转成固定A/B线性QP | 当前六速度读出加已知位姿积分并非合格完整线性提升递推 | 不作为当前实现；不能由预测GO推导其正确性 |
| 优化内环控制器参考量并保留串联PID | 改变已验证输入含义及优化对象 | 本轮不采用；需要新合同与匹配证据 |

已验证的预设策略自行递推支持继续投入，不证明任意优化命令、实时截止时间或闭环稳定性。所有新结果标为本地接口证据。

## 顺序任务

1. **锁定边界并写针对性失败测试。** 使用冻结r23/v37作为参考；新代码采用独立版本，不修改正式包。输入顺序从`easyuuv_nc.embodiments.CONTROL_CHANNELS`读取：`[roll,pitch,yaw,depth]`，不是surge/sway，也不是实际角度/深度目标。状态仍为`z + quaternion_wxyz + body linear/angular velocity`，无平面位置。命令每个控制区间保持两个1/120秒子步，控制频率60Hz，绝对值不超过0.95；`uuv4*`的index2 yaw不可用。
2. **实现单一实际执行状态与分支副本。** 实际状态只能由已实际发送的命令按序推进，计时、N维转速和构型/context绑定一致。预测候选只修改其副本；优化器试探、失败和超时均不得提交执行历史。状态复制必须覆盖执行器递推的全部内部记忆，不能只复制当前转速。未知起始转速、跳步/重复、跨构型状态接管和不匹配context拒绝准入；在线换构型仍未获证据。
3. **八构型等价/隔离验证。** 用fit角色记录或确定性本地输入测试零起点、非零历史、多起点和20/60/128区间；比较状态、PWM、转速、作用输入、掩码及时钟。独立分支次序互换不改变结果，失败分支不污染下一分支。先声明字段容差，不凭看到结果后放宽；沿用既有数值合同，保留任何差异。不以正式test数据调参或选实现。
4. **测量实际成本并形成下一项具体方案。** 报告CPU型号/线程、历史长度、预测时域、重复次数、p50/p95和最坏值；比较完整历史重放与缓存分支。只测小型本地固定样例，不启动Isaac、重拟合或无界搜索。需要的控制周期由实际耗时约束；没有实测前不承诺60Hz MPC。后续优化器、限幅/fallback与Legacy并行仲裁另行设计并测试。

## 验收与停止条件

- 有可复现的等价性和分支不污染证据；当前输出、构型/TAM、掩码、时钟、截止时间错误均能明确拒绝。
- 小型本地计时证据明确是否适合进一步控制集成。性能不足允许有界修复或NO_GO，不降低物理/接口正确性要求。
- 运行相关新测试及既有命令预测/执行器合同测试；不把CPU fixture声明为真实Isaac或闭环控制证据。
- 旧v38模型、源包、数据、评分和预算不变。新Phase 9实验不得消费v38剩余额度或使用其批准记录扩大范围。
- 新服务器实验前先就绪具体源包、场景、比较器、资源和停止条件，再按已有授权边界提请需要的新资源决定；普通本地实现不重复询问。
