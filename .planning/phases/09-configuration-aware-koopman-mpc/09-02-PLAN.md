# 预测计算成本定位与等价优化

前置：[路线审核](../../../docs/phase9_roadmap_review.md)、[09-01结果](09-01-SUMMARY.md)。现有20步预测中位耗时43.71–200.03ms，先解决可测量的工程开销，不预选通用求解器。

## 执行顺序

1. 一次本地固定剖析：八构型已有fit PRBS，固定pooled模型，origin=128、H=20；每例一次预热、三次无插桩计时、一次cProfile及一次冻结v37等价对照。单进程Torch/BLAS1线程，180秒、16MiB输出上限。记录模型、TAM、执行器、创建/复制/校验的函数成本；profile计时只定位，不混入无插桩速度。
2. 依据热点只实施一项保持数学和执行语义的优化，再测下一热点。优先不变量预计算、受构型/context绑定的缓存；不改物理dt、两子步hold、PWM死区、累计float32时钟、mask或状态准入，不以绕过检查获得虚假加速。使用新增版本/适配器，冻结r23及旧v39基准保留。
3. 修改前建立具体失败测试；边界非法值、context变更、分支隔离、两个子步及长历史均需保持。用原先声明的小容差，不能看到失败后放宽；允许差异在既有容差内，不要求逐比特相等。
4. 单次候选优化有效后再做八构型、pooled/heldout、origin0/64/128、H20/60/128固定等价计时，新的结果根/协议，不改旧记录。CPU总计时明确；若考虑GPU先作小型端到端比较，禁止把批吞吐量当单个控制周期延迟。
5. 提出09-03具体计算配置：完整求解候选数、预测长度、更新频率、低层仲裁周期、允许计划年龄和超时行为。未达到60Hz可考虑经实测支持的较慢优化+60Hz安全仲裁；不得将停表仿真当实时证据。仍不可行时输出NO_GO，重新审视模型执行形式，不强行进入服务器大实验。

后续微型CPU检查累计先限制在30分钟、256MiB新增结果；每次运行前写明具体变更和范围、失败保留。不拟合、不读正式test、不修改旧数据，不启动Isaac。该本地工程预算不消费v38正式实验账本。
