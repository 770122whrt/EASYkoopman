# Phase 3.5 Context

## Current State

Phase 3 is complete. The codebase now has:

- a manifest-first Koopman runtime loader;
- a pure NumPy first-pass MPC solver;
- a `koopman_mpc` branch in `easyuuv_env.py`;
- offline MPC replay;
- backend check between direct-state and paper-lifted candidates;
- one successful Isaac smoke using `direct_state`.

The current closed-loop proof is therefore real but conservative:

```text
direct_state predictor -> MPC -> bounded 8D PWM -> EasyUUV physics
```

The research gap is that `direct_state` predicts raw next state directly. It does not make the strongest possible connection to the Koopman-Sim2Real lifted-space formulation.

## Existing Code Contracts

### Lifted EDMD

`koopman/lifted_edmd.py` defines `LiftedEDMDModel`.

Important behavior:

- `model_class = "paper_lifted_edmd"`;
- model stores a square `transition_matrix` over observable features;
- `predict_next(state, control, reference)` builds observables, applies the transition matrix, and selects the raw state slice;
- save/load uses JSON;
- optional standard normalization is supported.

### Observables

`koopman/observables.py` defines `PaperObservableConfig`.

Current variants:

```text
linear:
  [state, state[:5] - reference, pwm]

selected_quadratic:
  [state, state[:5] - reference, pwm, state[5:11]^2, pwm^2]
```

The feature set is intentionally small and interpretable, which matches the Phase 2.5 recommendation to avoid large generic dictionaries.

### Sweep

`koopman/sweep.py` already trains both:

- `direct_state`;
- `paper_lifted_edmd`.

It sweeps:

- ridge values;
- `linear` and `selected_quadratic`;
- normalization on/off.

The current problem is not absence of lifted EDMD code. The problem is that model selection still chose `direct_state`, and we have not promoted the best `paper_lifted_edmd` candidate into a separate comparison manifest and Isaac smoke track.

### Runtime

`koopman/runtime.py` supports both `direct_state` and `paper_lifted_edmd`, but it requires:

```text
gate_status == "pass"
state_dim == 11
reference_dim == 5
control_dim == 8
dt > 0
model_path exists
```

Therefore Phase 3.5 must produce a valid `paper_lifted_edmd` manifest with `gate_status = "pass"` before using it in `play_controller.py`.

## Prior Review Items To Absorb

### From Phase 2.5 Recommendations

Carry forward:

- direct-state is an engineering baseline;
- paper-style lifted EDMD is needed for theoretical alignment;
- held-out multi-step behavior matters more than one-step fit;
- log-level splits are mandatory;
- divergence is a blocking issue;
- manifest must record assumptions instead of letting Phase 3 infer them.

### From Phase 3 Algorithm Alignment Review

Carry forward:

- Phase 3 is an engineering integration, not a full paper replication;
- runtime must support both `direct_state` and `paper_lifted_edmd`;
- reports must state backend used and whether it is paper-style lifted EDMD;
- the first solver is a first-pass receding-horizon optimizer;
- future RL/PPO should feed references, not direct PWM;
- quaternion sign handling belongs in cost calculations, not model input mutation.

## Design Decision

Phase 3.5 should not force the paper-style backend to become the primary model merely because it is more paper-aligned.

Instead, Phase 3.5 should produce one of two honest outcomes:

```text
Outcome A:
  paper_lifted_edmd passes offline and Isaac smoke gates.
  Phase 4 compares legacy, direct_state MPC and paper_lifted_edmd MPC.

Outcome B:
  paper_lifted_edmd fails one or more gates.
  Phase 4 records the failure and compares legacy vs direct_state MPC first.
```

This protects the project from overstating the paper connection while still making the paper-style method visible and testable.
