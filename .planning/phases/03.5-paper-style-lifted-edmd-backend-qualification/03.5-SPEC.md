# Phase 3.5: Paper-Style Lifted EDMD Backend Qualification - Specification

## Goal

Phase 3.5 qualifies a `paper_lifted_edmd` Koopman backend as an explicit research comparison target before Phase 4.

The phase exists because Phase 3 correctly proved a fallback-safe Koopman-MPC engineering loop, but the first closed-loop smoke used the Phase 2.5 selected `direct_state` model. That is useful, but it is not the closest form to the Koopman-Sim2Real paper.

Phase 3.5 therefore asks:

```text
Can we produce, evaluate and smoke-test a paper-style lifted EDMD backend
well enough that Phase 4 can compare:

1. legacy controller
2. direct_state Koopman-MPC
3. paper_lifted_edmd Koopman-MPC
```

## Why This Phase Exists

Two prior review documents both point to the same gap:

- `docs/phase2_5_koopman_model_gate_recommendations.md` says the current direct-state predictor is an engineering baseline and recommends a paper-style lifted-space EDMD candidate for theoretical alignment.
- `docs/phase3_algorithm_alignment_review.md` says Phase 3 must distinguish the completed engineering integration from a full paper-style lifted EDMD controller claim.

Phase 3.5 closes that gap without undoing Phase 3.

## Algorithm Contract

### Direct-State Backend Already Used In Phase 3

The completed Phase 3 smoke used:

```text
x[k+1] = W * [phi(x[k], r[k]), u[k]]
```

where:

- `x[k]` is the 11D EasyUUV state.
- `r[k]` is the 5D attitude/depth reference.
- `u[k]` is 8D PWM.
- `phi(...)` is a direct prediction feature vector.

This is a valid engineering model for MPC integration, but it predicts the next raw state directly.

### Paper-Style Lifted EDMD Backend For Phase 3.5

Phase 3.5 focuses on:

```text
f[k]       = observable(x[k], r[k], u[k])
Theta      = argmin ||F_next - F * Theta||^2 + ridge * ||Theta||^2
f[k+1]     = f[k] * Theta
x_pred[k+1] = select_state(f[k+1])
```

In current code, `PaperObservableConfig` supports:

```text
linear:
  [state, state[:5] - reference, pwm]

selected_quadratic:
  [state, state[:5] - reference, pwm, state[5:11]^2, pwm^2]

optional:
  bias term
```

This is closer to the Koopman-Sim2Real lifted-space transition than `direct_state`, while still adapting to EasyUUV's 11D state and 8D PWM control interface.

## Paper Alignment Boundary

Phase 3.5 may claim:

```text
The project now includes a paper-style lifted EDMD Koopman backend
and evaluates it against the direct-state engineering backend.
```

Phase 3.5 may not claim:

```text
The project fully reproduces the original Koopman-Sim2Real controller.
```

Reasons:

- EasyUUV uses an 11D state and 8D PWM input, not the original paper's smaller 3-DOF system.
- Online Kalman/RLS adaptation is still deferred.
- The Phase 3 MPC solver is a pure NumPy first-pass receding-horizon optimizer, not a full CasADi/nonlinear MPC reproduction.
- Isaac smoke proves execution, not final performance superiority.

## Requirements

### PLED-01: Paper-Style Manifest

Create a manifest that selects the best passing `paper_lifted_edmd` candidate from the Phase 2.5 sweep or from a re-run sweep.

Acceptance:

- `model_class == "paper_lifted_edmd"`.
- `gate_status == "pass"` only if the candidate passes offline finite-value and divergence gates.
- Manifest records observable variant, ridge, normalization mode, metrics, logs and known limitations.
- Manifest does not overwrite the Phase 2.5 `direct_state` selected manifest.

### PLED-02: Paper-Aware Data Collection

Use Isaac to collect enough data to make the comparison meaningful.

Acceptance:

- At least step, sine and irregular logs exist for legacy controller data.
- Repeated runs are preferred over a single smoke, because one short trajectory cannot validate generalization.
- Data collection commands record trajectory type, controller mode and output path.
- Generated logs pass `workflows/validate_koopman_log.py`.

### PLED-03: Offline Prediction Gate

Evaluate `paper_lifted_edmd` on held-out logs before closed-loop smoke.

Acceptance:

- One-step and multi-step metrics are reported.
- `multi_step_rmse@5`, `multi_step_rmse@20` and `multi_step_rmse@60` are reported where enough samples exist.
- Nonfinite prediction count is zero for accepted candidates.
- Divergence status is explicit.
- Direct-state metrics are reported side by side, not replaced.

### PLED-04: Offline MPC Gate

Run the Phase 3 MPC offline replay with both `direct_state` and `paper_lifted_edmd`.

Acceptance:

- Both backends use the same MPC horizon, timeout, bounds and weights.
- PWM remains in `[-1, 1]`.
- Fallback count and fallback rate are reported.
- Mean horizon cost and latency are reported.
- The report states whether `paper_lifted_edmd` is safe enough for Isaac smoke.

### PLED-05: Repeated Isaac Smoke

Run multiple short Isaac smoke tests with `paper_lifted_edmd` before Phase 4.

Acceptance:

- At least one step smoke completes.
- If feasible, sine and irregular smoke also complete.
- Each smoke writes Koopman JSONL with solver diagnostics.
- Each log validates with `validate_koopman_log.py`.
- Summary reports backend, trajectory, sample count, PWM min/max, fallback rate, latency budget status and known limitations.

### PLED-06: Phase 4 Handoff

Produce a handoff document that tells Phase 4 which backends are eligible for full evaluation.

Acceptance:

- If paper-style smoke passes, Phase 4 evaluates legacy, direct-state MPC and paper-lifted MPC.
- If paper-style smoke fails, Phase 4 still records the failure and evaluates legacy vs direct-state MPC first.
- The handoff distinguishes engineering success from paper-aligned algorithmic success.

## Out Of Scope

- Replacing the Phase 3 controller adapter.
- Replacing the EasyUUV thruster or hydrodynamics pipeline.
- PPO training.
- Online Kalman/RLS adaptation.
- LLM tuning.
- Claiming final performance superiority.
- Claiming exact reproduction of the Koopman-Sim2Real system.

## Acceptance Criteria

- [ ] A `paper_lifted_edmd` manifest is produced without overwriting the direct-state selected manifest.
- [ ] The manifest records observable config, ridge, normalization, metrics and known limitations.
- [ ] Offline prediction comparison reports direct-state and paper-lifted metrics side by side.
- [ ] Offline MPC replay reports bounded PWM, fallback rate, latency and horizon cost for both backends.
- [ ] Isaac step smoke completes with `paper_lifted_edmd`.
- [ ] At least one additional Isaac smoke or data run is collected if server time permits.
- [ ] Phase 3.5 summary states whether paper-style lifted EDMD is eligible for Phase 4 three-way evaluation.
- [ ] Phase 4 roadmap is updated to compare legacy, direct-state MPC and paper-lifted MPC when eligible.
