# Phase 5.1 Context: Koopman-MPC PPO Stability Training

## User Decision

The selected next direction is:

```text
First prove stable training.
After stable training is proven, inspect each link and improve the links that can be improved.
```

This means Phase 5.1 must not chase a headline performance win first. It must build a clean evidence ladder for longer PPO training under the existing Koopman-MPC control chain.

## Gap Review Incorporation

The supplemental review in `docs/phase5_1_stability_plan_gap_review_for_agents.md` sets the current status to:

```text
PASS_WITH_MUST_FIXES_BEFORE_EXECUTION
```

The direction is correct, but current code still recognizes Phase 5 smoke evidence rather than Phase 5.1 stability evidence. Before any server run, Phase 5.1 must add first-class support for:

```text
stability_sentinel
stability_candidate
matched_stability_eval
phase5_1_stability_sentinel
phase5_1_stability_candidate
training health summary
stability validator
selected PPO checkpoint manifest
```

This preserves the terminology boundary: Phase 5.1 does not create a new PPO algorithm. It produces a Koopman-MPC-conditioned PPO policy checkpoint trained inside the PPO -> adapter -> Koopman+MPC closed loop.

## Current Evidence From Phase 5

Phase 5 proved smoke-level execution only:

```text
obs_9d
  -> RSL-RL PPO
  -> action_4d
  -> heuristic_reference_delta_v0
  -> koopman_reference_5d
  -> direct_state Koopman+MPC
  -> pwm_8d
  -> Isaac physics
```

Confirmed Phase 5 smoke facts:

- The adapter refresh ran on the RSL-RL `env.step(action_4d)` path.
- A checkpoint was generated under `retrained_ppo_koopman_mpc`.
- Checkpoint provenance validation passed.
- A two-sample evaluation loaded the checkpoint and produced bounded PWM.
- Smoke evaluation reported `fallback_rate=0.0`, `latency_ms_mean=11.496730614453554`, `latency_ms_max=11.539035476744175`.

Phase 5 did not prove:

- PPO convergence.
- Training stability over longer horizons.
- Reward quality.
- Superiority over `legacy/Ssurface`.
- Deployability.

## Phase 5.1 Framing

Phase 5.1 is a stability gate, not a performance phase.

The purpose is to answer:

```text
Can the PPO + heuristic reference adapter + direct_state Koopman-MPC loop train for a meaningful duration without numerical, control, or evidence failures?
```

Only after that answer is yes should we tune reward terms, fallback penalties, latency penalties, adapter scales, MPC parameters, or evaluation ranking.

## Stable Training Means

For Phase 5.1, stable training means all of the following are true for the selected run profile:

- Isaac training completes the requested iterations without crash or hang.
- RSL-RL produces periodic checkpoints.
- The selected checkpoint reloads through `play_ppo_koopman.py`.
- PPO observations and actions remain finite.
- PPO action clipping is recorded and does not dominate the rollout.
- Adapter refresh count is positive and occurs before environment stepping.
- PWM remains bounded.
- Koopman-MPC fallback rate and solver latency are recorded.
- Matched evaluation can replay the checkpoint on step, sine and irregular references.
- The result can be reproduced from a recorded command, config and artifact manifest.

## Design Boundary

Keep these fixed for the first stable-training proof:

- PPO implementation: RSL-RL PPO.
- PPO observation: current 9D EasyUUV observation.
- PPO action: current 4D policy output.
- Adapter: `heuristic_reference_delta_v0`.
- Low-level controller: `direct_state` Koopman+MPC.
- Evidence bucket: `retrained_ppo_koopman_mpc`.
- LLM: out of the real-time loop and out of Phase 5.1.

Allowed after the first stability gate passes:

- Add a versioned reward profile.
- Add fallback and latency penalties.
- Tune adapter scale bounds.
- Tune MPC horizon, regularization and fallback threshold.
- Add multi-env support if the wrapper is proven vector-safe.

Not allowed in the first stability gate:

- Hand-writing PPO.
- Letting PPO output 8D PWM.
- Switching the default low-level backend to `paper_lifted_edmd`.
- Claiming superiority over legacy based on training curves alone.

## Creative But Bounded Direction

The useful creative move is not to invent a new controller. It is to turn training into an instrumented experiment:

```text
train health gate
  -> checkpoint reload gate
  -> matched evaluation gate
  -> improvement queue
```

This lets us improve one link at a time:

- If fallback dominates, improve MPC fallback behavior or add fallback-aware reward.
- If latency dominates, optimize solver settings before touching PPO.
- If action clipping dominates, tune adapter scale/action regularization.
- If matched evaluation is unstable but training reward looks good, fix reward mismatch.
- If legacy remains much stronger, preserve it as the primary baseline and report Koopman-MPC PPO as research-stage.

## Immediate Planning Decision

Phase 5.1 should use a two-run ladder:

```text
sentinel run:
  short but longer than smoke, used to catch hangs and bad logging

stability run:
  longer single-env training, used as the first real stability evidence
```

Only after both pass should Phase 5.1 run matched evaluation and decide which improvement path comes next.
