# Phase 5.1: Koopman-MPC PPO Stability Training - Plan

**Spec:** `.planning/phases/05.1-koopman-mpc-ppo-stability-training/05.1-SPEC.md`
**Mode:** local instrumentation and runbook first, server Isaac training second
**Primary objective:** prove stable PPO training before reward/performance optimization
**Default reward profile:** `legacy_easyuuv_v0`
**Default backend:** `direct_state` Koopman+MPC
**Readiness status:** `PASS_WITH_MUST_FIXES_BEFORE_EXECUTION`

## Purpose

Phase 5 produced a tiny smoke checkpoint. Phase 5.1 turns that into stability evidence.

The order is:

```text
1. preserve Phase 5 contract
2. add Phase 5.1 evidence levels and provenance
3. add stability-oriented summary/validation
4. write selected checkpoint manifest
5. run a bounded sentinel training
6. run a longer single-env stability training
7. reload and evaluate checkpoints on matched references
8. classify the bottleneck
9. only then decide which link to improve
```

## Wave 4: Stability Validator

Likely files:

- Create: `workflows/validate_phase5_1_stability_summary.py`
- Test: `tests/test_phase5_1_stability_validator.py`

Validation rules:

Hard fail on:

```text
checkpoint_found = false
checkpoint reload failure
nonfinite_observation_count > 0
nonfinite_action_count > 0
nonfinite_reward_count > 0
PWM outside [-1, 1]
adapter_refresh_count <= 0
adapter_refresh_before_env_step != true
invalid checkpoint provenance
```

Warn on:

```text
policy_action_clip_rate > 0.5
training_loop_fallback_rate > 0.2
training_loop_latency_ms_mean > 20.0
training_loop_latency_ms_max > 50.0
latency_budget_violation_rate > 0.1
```

Acceptance:

- Validator exits non-zero for hard failures.
- Validator exits zero with warnings for warning-only cases.
- Validator prints a routing recommendation.
- Validator prints `selected_weight_status = candidate_only | rejected | promoted_for_phase5_2`.

## Wave 8: Matched Evaluation

Inputs:

- Legacy `Ssurface` Phase 4 matched logs or fresh matched logs.
- Controller-only direct_state Koopman+MPC matched logs or fresh matched logs.
- Phase 5.1 selected checkpoint.
- `source/results/koopman_phase5_1/selected_ppo_checkpoint_manifest.json`.

Command shape for PPO checkpoint:

```bash
cd /root/IsaacLab
SELECTED_CHECKPOINT=/root/IsaacLab/logs/rsl_rl/easyuuv_koopman_mpc/<run>/model_*.pt
SOURCE_SUMMARY=/root/EASYkoopman/source/results/koopman_phase5_1/stability_candidate_summary.json
for TRAJ in step sine irregular; do
  WANDB_MODE=disabled ./isaaclab.sh -p /root/EASYkoopman/workflows/play_ppo_koopman.py \
    --task EasyUUV-Direct-v1 \
    --num_envs 1 \
    --headless \
    --policy_mode checkpoint \
    --play_checkpoint "$SELECTED_CHECKPOINT" \
    --source_training_summary_path "$SOURCE_SUMMARY" \
    --controller_mode koopman_mpc \
    --koopman_manifest_path /root/EASYkoopman/source/results/koopman_phase2_5_verify_20260701_231802/selected_model_manifest.json \
    --trajectory_type "$TRAJ" \
    --trajectory_cycles 1 \
    --steps_per_action 50 \
    --result_bucket retrained_ppo_koopman_mpc \
    --ppo_evidence_level matched_stability_eval \
    --ppo_koopman_log_path /root/EASYkoopman/source/results/koopman_phase5_1/ppo_${TRAJ}.jsonl
done
```

Acceptance:

- Step evaluation must complete.
- Sine and irregular should complete, or failures must be classified.
- Logs validate with `workflows/validate_ppo_koopman_log.py`.
- `matched_stability_eval` requires valid Phase 5.1 checkpoint provenance.
- Matched report includes legacy, controller-only Koopman+MPC and PPO-Koopman-MPC.

## Wave 9: Bottleneck Classification

Likely files:

- Create: `workflows/analyze_phase5_1_stability.py`
- Test: `tests/test_phase5_1_stability_analysis.py`
- Create: `.planning/phases/05.1-koopman-mpc-ppo-stability-training/05.1-SUMMARY.md`

Classification rules:

```text
fallback-dominated:
  training_loop_fallback_rate or matched_eval_fallback_rate warning

latency-dominated:
  training_loop latency warning, matched_eval latency warning, or slow training throughput

clip-dominated:
  policy_action_clip_rate warning

tracking-dominated:
  stable run but worse matched error than controller-only Koopman+MPC

reward-dominated:
  stable run but reward curve gives no useful signal

clean-stable:
  no hard failure and no major warnings
```

Acceptance:

- The summary selects exactly one primary next bottleneck.
- Secondary bottlenecks are listed without triggering scope creep.
- Training-loop metrics and matched-evaluation metrics are interpreted separately.
- The final recommendation is one of:

```text
proceed_to_reward_v1
fix_mpc_latency
fix_mpc_fallback
tune_adapter_scales
add_vectorized_training_gate
collect_more_data_or_retrain_koopman
```
