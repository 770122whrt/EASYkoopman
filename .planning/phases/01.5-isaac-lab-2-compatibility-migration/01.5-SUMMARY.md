# Phase 1.5 Summary: Isaac Lab 2.x Compatibility Migration

**Date:** 2026-06-30
**Branch:** `isaaclab2-migration`
**Status:** Server smoke gate passed

## Result

Phase 1.5 made the Phase 1 direct-controller Koopman data path runnable on the confirmed server stack:

- Isaac Sim 5.0
- Isaac Lab 2.2.1
- Ubuntu 22.04
- Python 3.11 `isaaclab` environment

The server smoke rollout produced a valid Koopman JSONL file, and the offline validator accepted it:

```text
OK: 2 samples
state_dim=11 reference_dim=5 action_dim=4 pwm_dim=8
t_start=0.016666667 t_end=0.033333333
trajectory_types=step
controller_modes=legacy/Ssurface
```

This confirms that the core baseline chain is connected:

```text
Isaac Lab env -> legacy Ssurface controller -> 8D PWM -> physics step -> Koopman JSONL
```

## Asset Decision

The EasyUUV USD assets are allowed to be tracked in Git:

- `data/easyuuv/model.usd`
- `data/easyuuv/Props/instanceable_meshes.usd`

Reason: the files are below GitHub's 100 MB single-file limit, and keeping them in the repository prevents the server from reaching a valid code state without the matching model assets.

## Remaining Non-Blocking Warnings

These warnings did not block the smoke rollout:

- Isaac Lab seed was not set.
- render interval is smaller than decimation.
- DirectRLEnv legacy `num_actions`, `num_observations`, `num_states` warnings.
- Fabric point-instancer warnings from debug visuals.

They can be cleaned up in a later maintenance patch. They do not block Phase 2.
