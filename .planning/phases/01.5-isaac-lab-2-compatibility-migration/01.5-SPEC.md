# Phase 1.5 SPEC: Isaac Lab 2.x Compatibility Migration

**Date:** 2026-06-30  
**Branch:** `isaaclab2-migration`  
**Owner:** Codex + user server validation

## Problem

Phase 1 created the controller boundary and Koopman JSONL logging path, but the server environment is Isaac Sim 5.0 + Isaac Lab 2.2.1. The current EasyUUV code still imports the Isaac Lab 1.x namespace (`omni.isaac.lab.*`) and registers the task through the old `omni.isaac.lab_tasks.direct.EasyUUV-Isaac-Simulation` extension path.

That means the next real blocker is not Koopman or MPC logic. The blocker is making the baseline direct-controller rollout runnable on the confirmed server stack so it can generate the data required by Phase 2.

## Scope

In scope:

- Add a compatibility layer for Isaac Lab 2.x imports, with Isaac Lab 1.x fallback where practical.
- Change core EasyUUV environment, asset and dynamics imports to use the compatibility layer.
- Register `EasyUUV-Direct-v1` from a normal Git clone path rather than a legacy extension path with a hyphenated module name.
- Update `workflows/play_controller.py` so it can run as a direct controller without PPO/RSL-RL wrapping.
- Preserve Phase 1 Koopman JSONL logging from the legacy controller path.
- Add local source-contract tests because this workstation cannot import Isaac.
- Provide exact server commands for the Isaac Gate.

Out of scope:

- Koopman EDMD training.
- Koopman+MPC controller implementation.
- Full PPO training/evaluation migration.
- Isaac Lab extension packaging.
- Fixing non-blocking Warp CUDA warnings unless they stop rollout.

## Requirements

- **COMPAT-01:** Core code prefers Isaac Lab 2.x namespace: `isaaclab.*`, `isaaclab_tasks.*`, `isaaclab_rl.*`.
- **COMPAT-02:** Rollout workflows start `AppLauncher` before importing Kit-dependent environment/task code.
- **COMPAT-03:** `EasyUUV-Direct-v1` registration works from a normal clone directory.
- **COMPAT-04:** First server success criterion is direct controller rollout plus Koopman JSONL output, not PPO training.
- **BASE-04:** `play_controller.py` remains the non-PPO controller verification entrypoint.
- **DATA-01/DATA-02:** JSONL logs remain offline-readable and include state, reference, action, PWM and next state.

## Acceptance Criteria

Local:

- `pytest` passes for Phase 1 data helpers and Phase 1.5 source contracts.
- `compileall` passes for modified Python files.
- No direct-controller path imports `omni.isaac.lab.*` outside the compatibility layer.
- `play_controller.py` no longer imports `OnPolicyRunner`, checkpoint loading, policy export or `RslRlVecEnvWrapper`.

Server:

- From `/root/IsaacLab`, the branch runs with:

```bash
./isaaclab.sh -p /root/EASYkoopman/workflows/play_controller.py \
  --task EasyUUV-Direct-v1 \
  --num_envs 1 \
  --headless \
  --koopman_log_path /root/EASYkoopman/source/results/koopman_phase1/koopman_step.jsonl
```

- The command reaches environment creation and writes at least one JSONL record.

## Open Risks

- Isaac Lab 2.x may have minor API differences around `RigidObject`, marker configs or `parse_env_cfg`; local tests cannot execute these imports.
- `wandb` may not be configured on the server. The direct controller should not require online wandb success to generate JSONL.
- The raw Gym/DirectRLEnv step return shape may differ from the previous RSL-RL wrapper. The workflow should normalize observations defensively.
